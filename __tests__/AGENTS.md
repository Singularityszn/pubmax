# Unit fences and the test harness

Rules about the unit suite: the PostgreSQL harness, the jsdom runtime and the fences that own a launch contract. Browser rules are in [e2e/AGENTS.md](../e2e/AGENTS.md).

Repo-wide laws and the index of every other area file are in the root [AGENTS.md](../AGENTS.md).

## Harness and fences

- **ONE POSTGRES HARNESS, ONE HOST BUDGET, AND A SKIPPED PROOF IS A FAILURE.** Both 5 September 2026 reviews landed on the same gate: `npx vitest run` exited 1 on a cold run and 0 on a warm one on the same commit and the same machine, failing four migration proofs in `initdb` with `could not create shared memory segment: No space left on device`. macOS ships `kern.sysv.shmmni = 32`, every running cluster claims one SysV segment for the postmaster interlock whatever `shared_memory_type` says, and every suite booted its own. Behind that sat sixteen hand-copied `missingPostgresReason` definitions with sixteen binary searches and different `initdb` flags. THREE modules own it now and no suite may own any of it again. `scripts/rls/postgresHost.mjs` (plain ESM plus a `.d.mts` sidecar, the `lib/buildInfo.mjs` idiom, because the runner and the session harness are plain `node`) is the ONE binary search, the ONE skip predicate and the host CLUSTER BUDGET: a slot is a directory, `mkdir` being the atomic primitive every filesystem already has, it records the pid that owns it so a killed run frees its budget at once, and `PUBMAX_PG_MAX_CLUSTERS` caps live clusters at 6. `__tests__/helpers/postgres.ts` is the TypeScript door plus the ONE cluster every proof boots (`sql`, `sqlAsync`, `attempt`, `expectRefusal`, `concurrent`, `applyFile`, `applyFileTransactional`, and `psql` + `databaseArgs` for a probe only one proof needs). `scripts/rls/postgresSuites.mjs` is the CLOSED list of those suites, read three ways; it names the count so prose never has to. FOUR rules. (1) A SKIP IS NEVER A PASS: `postgresSkipReason()` is non-null ONLY for the deliberate `PUBMAX_RLS_NO_PG=1` opt-out, an absent PostgreSQL nobody opted out of makes `startPostgres` THROW, and `npm run test:rls` exits 1 on the skip banner unless `PUBMAX_RLS_ALLOW_SKIP=1` admits it. Before that the permission matrix - the one detector that has ever caught an RLS hole here - reported green on every host without a cluster. (2) THE LIST IS THE FENCE: `__tests__/postgresSuiteInventory.test.ts` holds the closed list to the suites that actually import the harness (it is what caught the two DM proofs #1567 landed with copies of their own), to the runner, and to the two `.github/workflows/ci.yml` jobs that install no PostgreSQL and must exclude exactly these, so a new proof cannot land in a clusterless job and report itself skipped. (3) `vitest.config.mts` bounds `maxWorkers` at 4, the `--maxWorkers=4` path `npm run coverage` already passed on, and `hookTimeout` is 180s because a cluster boot plus a migration chain is a hook. (4) A DATA DIRECTORY NAME IS A SOCKET PATH: PostgreSQL refuses one over 103 bytes, so the label is trimmed into `pubmax-pg-<12 chars>-` and names the slot and the error text instead.

- **A jsdom test needs `localStorage` back, because Node's own shadows it.** Node 22 and later define a global `localStorage` accessor answering undefined without `--localstorage-file`, and in vitest's jsdom environment `window` IS `globalThis`, so under Node 26 that accessor sits where jsdom's Storage should be: the window's `sessionStorage` is real and its `localStorage` is undefined. Sixteen browser suites failed on their first `localStorage.clear()`, green on the same commit under an older runtime, which the `engines` field admits (`>=22.0.0`). `vitest.setup.ts` restores an in-memory Storage ONCE, before any test, and only when jsdom is the environment and its Storage is missing; a suite that deliberately deletes or replaces `localStorage` still does so.

- **Launch hardening contracts have executable owners.** Form-zoom policy lives in `__tests__/iosFormZoomFloor.test.ts`, rendered phone-control geometry in `e2e/launch-phone-controls.spec.ts`, analytics consent foot clearance in `__tests__/analyticsConsentDesktopClearance.test.ts` with phone scroll-surface tap ownership in `e2e/ux-consent-chrome.spec.ts`. That spec also owns the FIRST-RUN surface, whose every block is sized to the viewport: `app/onboarding/onboarding.css` reserves the card's lane there, and because containment alone hid the ONE primary action below a fold no phone draws a bar for, the photograph is what yields while the card is up. Not-covered and on-screen are two assertions and the spec makes both, at 320, 360, 390 and 430. Evidence: `docs/proof/consent-onboarding/`. Public-asset cache classification in `__tests__/publicAssetCaching.test.ts`, and route ceilings in `perf/route-budgets.json`. Measurement evidence lives in `docs/proof/v01-launch-hardening/`.
