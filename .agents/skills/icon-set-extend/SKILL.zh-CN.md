# 扩展一套既有图标集

既有文件就是规范。先复原它们的决策，再让指定图标消失进集合里。一个新画或重绘的图标，只要陌生人能认出它是后加的，就算失败——哪怕它单独看很好看。

复制定义这套集合的怪癖。修正破坏渲染的缺陷。一个偏重的描边或古怪的箭头头部可能是怪癖；一条被裁剪的描边、一个合并的形状、或破坏主题化的固定颜色则是缺陷。当单个图标无法裁决这层区分时，向集合看齐并报告该问题。

## 工作流程

### 第 1 步：复原规范

```bash
python3 scripts/infer_spec.py path/to/icons/ --write
```

该命令写出 `style-spec.json` 和 `elements.md`。两个文件都要读。检查网格、绘制模式、描边设置、圆角半径、视觉包络、间隙与共享部件。

动手之前先解决集合内部的分歧。强多数派可以定案。对于接近五五开的分裂，检查哪些图标最新。仅当仓库留下的方向仍含糊时才询问用户。

输出的 `minGap` 来自网格。`observedSmallestGap` 报告的是现存最小间隙——那可能是缺陷而非规则。

此步骤完成于：目标规范已记录、`elements.md` 已存在、且每个接近分裂的分歧都有书面裁决。

### 第 2 步：研究最近的邻居

为每个被点名的形态，打开三到五个最接近的既有图标。阅读它们的 SVG 标记，比较细节预算、透视、端点、闭合与命名。当集合看起来正在转向时，检查 git 历史。

若是已知的图标库，阅读 `references/matching.md`。把它当作向导，然后把每一条惯例都对照项目里的实际文件验证一遍。本地文件优先于已发表的惯例——因为项目会锁定版本，而且经常改动内嵌（vendored）的 SVG。

此步骤完成于：每个被点名的图标都有指定的邻居，以及一张待复制的惯例短清单。

### 第 3 步：一次画一个（或重设计一个）

从 `elements.md` 出发。逐字粘贴既有的共享部件。平移只用整数单位，旋转只用四分之一圈（直角）。任何缺失的部件从最近的既有形态推导。

每画完一个图标，就在目标渲染尺寸下与它指定的邻居比较。除了几何，还要匹配集合的细节层次与格式。当第三方库（vendored）的工具链依赖注释、属性排列和文件格式时，原样保留它们。

此步骤完成于：每个被点名的图标都存在，且每个复用的部件与其登记表条目逐项一致。

### 第 4 步：对合并后的集合校验

把旧图标与指定图标放在一起跑校验。用 `--focus` 限定报告的发现范围：

```bash
python3 scripts/validate_icons.py path/to/icons/ \
  --spec path/to/icons/style-spec.json --focus batch-run,data-lineage,rollback-snapshot
```

完整目录提供规范与视觉中位数。`--focus` 把与本任务无关的遗留发现挡在门外。一次聚焦运行的完成标准是：指定图标零错误。逐条检查警告——要么修掉，要么记录保留的具体理由。

只有当用户问的是更大的集合时，才去掉 `--focus` 完整跑一次。除非用户把旧文件划入范围，否则不要动它们。

### 第 5 步：跑陌生人测试

制作（或复用）一张新旧混合的对照表。先去掉标签，以最小公共渲染尺寸展示。比较光学尺寸、视觉重量、细节层次、共享部件与端点处理。

修改任何一个显眼的指定图标。为每个指定图标记录邻居比较，让视觉检查无法退化成一瞥而过。

此步骤完成于：每个指定图标都有记录在案的比较，且每个离群项都被解决或解释。

### 第 6 步：报告决策

说明复制了哪些惯例、修正了哪些缺陷、裁决了哪些含糊之处。列出每条保留的校验器警告及其理由。对于重设计的图标，把被点名的重绘与旧集合的无关问题分开陈述。

任务完成于：所有被点名的文件都存在、聚焦校验零错误、每条警告都有处置结论、陌生人测试覆盖每个指定图标、且总结记录了每一次判断调用。

## 参考文件

- 第 2 步中，对任何第三方图标集阅读 `references/matching.md`。覆盖 Lucide、Heroicons、Feather、Phosphor、Tabler、Radix、Bootstrap Icons 与 Material Symbols。
- 当 `icon-set-generator` 可用且本地集合没有可用的先例时，阅读它的 `references/construction.md`。`references/svg-patterns.md` 只在绘制具体形态时按需阅读。
