# The browser suite

Rules about Playwright: the server it drives, the state it must clear and the idioms that stop a spec lying.

Repo-wide laws and the index of every other area file are in the root [AGENTS.md](../AGENTS.md).

## Driving the browser suite

- **`npm run test:e2e`** (Playwright) needs browsers installed first: `npx playwright install --with-deps chromium`. The e2e config builds and starts the app itself.

- **A hand-started server on the e2e port makes Playwright lie.** `playwright.config.ts` owns the env that lets keyless API routes run (`webServer.env`); without it a production build refuses the routes that write. Playwright reuses an existing listener on its port rather than starting its own, so a stray `npm run start` silently becomes the server under test and every later run inherits that gap. Free the port before a real run; to reuse a build deliberately, start it with the config's env and pass `PW_SKIP_WEBSERVER=1`. `PW_NEXT_DIST_DIR` moves the build directory, and the screenshot commands inherit the isolated wrapper's `NEXT_DIST_DIR` unless an explicit `PW_NEXT_DIST_DIR` wins. A local run also trips `scripts/run-with-restored-next-env.mjs` on a CLEAN tree, because `webServer.env` pins `NEXT_PUBLIC_SW_VERSION=local` on purpose and the pack build then stamps every `public/data` venue pack `"revision":"local"` where the committed copies carry a deploy SHA: own that output for the run with `PUBMAX_TRACKED_OUTPUTS=public/data`, and restore it before committing, because a stamp is not a data change.

- **Manual planner testing is stateful and constraint-sensitive.** `/api/plans/generate` returns `422` when the intake carries must-have needs the area's data cannot satisfy: honest scarcity, not a broken environment. The intake and a route draft also persist across sessions in `localStorage`, so a prior run's constraints silently leak into the next. Run manual UI planner tests in a fresh or incognito profile; a low-constraint free-text request through "Describe instead" reliably yields a priced three-stop plan keyless. The e2e specs clear this state with `addInitScript`.

- **A browser test never guesses where a pin is.** The pins paint through the MapLibre canvas, so a spec cannot find one in the DOM, and a grid of taps hunting for one is a race the test loses under parallel workers. `components/map/canvas/paintedPinProbe.ts` publishes `paintedMapTapPoints` on `window`: the viewport point of every pin and cluster the map is drawing right now, each checked to have survived symbol collision, to re-query to the same mark, and to carry no app chrome on top of it. It is unconditional, like the `pubmax:pin-reveal` event beside it, because the browser suite runs a production build. The map opens with the pubs gathered, so a spec that wants a pin opens a cluster first. Pins: `__tests__/paintedPinProbe.test.ts`, `e2e/mobile-map-chrome-fit.spec.ts`.

- **A LONE CLICK IS NOT A WAIT FOR HYDRATION, and the dropped tap looks exactly like missing markup.** A control painted on the SERVER is tappable in the document before React attaches, so Playwright's own actionability check passes and the tap is dropped with nothing on screen saying so; the spec then waits out its whole budget and reports the surface the tap would have opened as ABSENT. That is how `/pal`'s `Meet your Pub Pal` was read as a heading main had deleted when the heading was there all along (#1464), and how `/plan`'s stop-count answered `aria-pressed=false` for a full assertion budget before. The idiom is to retry the TAP rather than assert harder on what follows it: `await expect(async () => { await control.click(); await expect(result).toBeVisible({ timeout: 1_000 }); }).toPass({ timeout: 20_000 })`, as in `e2e/plan-invite.spec.ts` and `e2e/mobile-button-system.spec.ts`. Before changing an assertion that a server-painted surface never appeared, open the page in a browser and click it: a page that answers there is right, and the spec's tap is the defect.
