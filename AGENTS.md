# AGENTS.md

## Cursor Cloud specific instructions

PubMaxing is a single Next.js 16 (App Router, React 19, TypeScript) web app — a price-aware London pub-crawl planner with a MapLibre 3-D map. There is one service.

- **Dedicated `/login` (alias `/signin`) owns the email-link flow as a first-class page.** Phone nav Sign in navigates there; desktop may keep the header popover. The browser session lives in evictable localStorage, so a durable HttpOnly resume cookie (`lib/authSessionResume.ts`, route `/api/auth/session`, client seam `lib/authSessionResumeClient.ts`) mirrors the refresh token: AuthProvider persists it on every auth event, redeems it when the browser boots with no local session, and a dead token surfaces the welcome-back one-tap path on `/login` instead of a cold form. Sign-out is the only place that deletes the cookie. Under `next dev` only, a non-supabase.co `NEXT_PUBLIC_SUPABASE_URL` origin is admitted into CSP `connect-src` (proxy.ts) so a local GoTrue (`supabase start`, or a stub) can drive real browser sign-in; production never widens. `__tests__/authSessionRoute.test.ts` pins the restart-restore regression. The claim surface (`components/identity/AccountOnboarding.tsx`) must await the server onboarding answer before offering a claim: an existing handle shows the owned identity state and syncs `pubmax_handle` from the server, and a failed status load never falls through to the claim form. Do not touch `AuthProvider.tsx` token-fragment paths without coordinating the auth-hardening lane.
- **Clerk is optional and two-key gated.** `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` + `CLERK_SECRET_KEY` (documented empty in `.env.example`). `isClerkMiddlewareConfigured` in `lib/clerkIdentity.ts` requires BOTH before `proxy.ts` runs `clerkMiddleware` - a missing secret must leave the plain security proxy so the site never 500s. The publishable key is decoded with Buffer on the server and `atob` in the browser (client controls used to hide when Buffer was missing). Clerk sits beside Supabase in `SignInButton` / `ClerkAccountControls`; a Clerk session is not a PUBMAXX User ID. Firefox proof shots live in `docs/proof/clerk-auth/`.
- **Runs keyless.** `npm run dev` (Next dev on webpack, http://localhost:3000) works with no secrets: Pint Drops use an in-memory store and `/api/heritage` (The Landlord) returns grounded structured-only answers. Supabase / `OPENROUTER_API_KEY` in `.env.local` are only needed to exercise durable persistence, browser auth, admin moderation, and narrated heritage replies — not required to run or demo the app. See `.env.example`.
- **Standard commands** live in `package.json` scripts and `README.md`: `npm run dev`, `npm run lint`, `npm run typecheck`, `npm test` (Vitest), `npm run verify` (validate-data · lint · typecheck · coverage — the pre-push gate), `npm run ci` (verify + build).
- **`npm run test:e2e`** (Playwright) needs browsers installed first: `npx playwright install --with-deps chromium`. The e2e config builds and starts the app itself.
- **Pre-push hook** (`.githooks/pre-push`) runs `npm run verify` but is only active after `npm run setup` (sets `core.hooksPath=.githooks`); it is not enabled by default in a fresh clone.
- **RLS is a second line of defence; the service role is still the write path.** App stores use `requireSupabaseAdmin` and bypass RLS. Migrations `0065`-`0069` (`supabase/migrations/2026080320*_rls_wave2_*.sql`) add JWT policies derived from API ownership, plus explicit client-deny on capability/secret tables. Helpers live as `public.rls_*`. Hard rules the policies must keep: `visit_reports` SELECT matches `canViewOnPublicSurface` via `rls_can_read_visit_report` (status=visible; friends = author + author's followers; hidden/pending never PostgREST-readable); `community_prices` SELECT is `hidden_at is null` only (no actor exception, no `hidden_at` column grant); `private_account_identities` is owner SELECT only (writes service-role). Do not re-open `using (true)` on private tables; do not grant `plan_crew_members.token_hash` or `community_prices.actor` to browser roles. Rollback: `supabase/migrations/rollback/20260803200000_rls_wave2_rollback.sql`. Captain applies migrations - agents ship SQL only. Effective proof: `npm run test:rls` needs local PostgreSQL 16 and PostgREST, applies every pre-wave migration plus exact `0065`-`0069`, exercises JWT sessions through SQL and PostgREST, then requires rollback to reproduce the pre-wave policy and privilege catalog byte for byte. SQL shape pins: `__tests__/rlsWave2Policies.test.ts`.
- **Map density is a contract, not a styling choice.** The pin/cluster zoom boundaries, supercluster radius, and the symbol-collision policy that stops labels and pins overlapping, including its narrow overlap exemptions, are the constants at the top of `components/map/canvas/buildScene.ts` (and the layers below them), asserted in `__tests__/mapSymbolCollision.test.ts`. Change them there, and keep every app symbol layer inside MapLibre's collision index.
- **What a community price is allowed to move is a policy, not an implementation detail.** A current submission is signed-in, handle-attributed, and bound to the account's stable profile actor; only legacy rows without a handle remain anonymous. Every submission shows on the pub's own sheet, dated, but only reaches pins/list rows/cheapest buckets once it is corroborated by a second independent submitter and is inside the max-age window. The constants and predicates are in `lib/communityPrice.ts`, the count is derived (never stored, never client-supplied) on the store's read path, and the price gate is `mergeCommunityPriceSignals` in `components/map/communityPriceSignals.ts`. VISIBILITY is a separate, ungated question from AUTHORITY: a first in-window pint report immediately marks its pin with a provisional badge via `provisionalCommunityPriceVenueIds` (same file, second seam - a set of ids, never a `VenueSignal`), while pin colour, list rows and cheapest buckets still wait for corroboration. A UK base pin wears the SAME mark through its own seam - a settled viewport asks `/api/price-submit?scope=provisional-base` for the marked ids among the base pins on screen, in bounded chunks against a per-actor budget, and `ukBasePubsToGeoJSON` flags them in memory (`public/data/uk_base/README.md`) - and that mark is the only thing a base pin ever earns: no band, no cheapest price, no pin label, no Pint Index, whatever it is corroborated by. So a surface's promise is `CommunityPriceMapReach` (`paint` | `mark` | `page`), not a boolean: the copy may claim the mark and never the colour. Keep the two seams apart: nothing about a pending report may travel through the price merge. Taking a price DOWN is the mirror policy: readers flag (`POST /api/price-submit { action: "report" }`), only a moderator hides (`app/api/admin/community-prices`), reporting never auto-hides (unlike pint drops - an anonymous threshold here would be a one-tap eraser), and hiding never deletes. The one filter lives in `freshestPerCategory`, so a hidden row leaves the sheet, the corroboration count and the map candidate together; `__tests__/communityPriceModeration.test.ts` pins it.
- **A Visit Report is an account of one visit, never a venue rating.** `lib/visitReports.ts` owns its dated 140-character account and closed crowd, noise, seating, and bar-wait observations; `components/visits/VisitReportPanel.tsx` is the shared newest-first reader and composer. Public reads carry `ready` or `degraded`, because a failed lookup may never read as no visits. `/api/visit-reports?contributor=<handle>` is the leaderboard count seam. A row prints the VISIT date and nothing else, so the lane sorts on `visitedAt` with `createdAt` only as the tie-break, and that makes the date authority-bearing: `MAX_VISIT_AGE_DAYS` (90 calendar days, both ends inclusive) and the no-future rule are enforced in `resolveVisitedAt`, with the composer's `min`/`max` mirroring rather than owning them. Reader flags only queue a row; only a moderator hides it, hiding never deletes its provenance, and a hidden row keeps its own moderator lane (`GET ?status=hidden`) so the hide stays reversible from the surface that made it. `__tests__/visitReportsRoute.test.ts`, `__tests__/visitReportsStore.test.ts`, and `e2e/visit-reports.spec.ts` pin the contract.
- **Community venue signals are observations, never venue facts.** `lib/communityVenueSignals.ts` owns the closed vocabulary, trust states and copy for character, access, door policy and whether people are eating. They travel through the existing `/api/price-submit` and `lib/communityPriceStore.ts` actor, attribution, rate-limit and corroboration seams. Character copy must name drinkers' judgement. Step-free entrance and step-free toilets are separate signals; each stays visibly unknown until corroborated, and a single report may add detail but never turn unknown into confirmed access - at ANY age, because ageing weakens a report and may only ever move it to the supporting line (an expired lone report reading as a confirmed step-free entrance was the original defect). What a reading surface may branch on is `CommunityVenueSignalTrust` (`unknown` | `reported` | `established`), never the sentence: the collapsed access summary in `VenueCommunitySignals.tsx` used to compare copy, so a wording change would have silently promoted a pub nobody had checked. Signals share the price table, so the price scans narrow to `drink_category is not null` (a row cap is a window, not a filter, and unbounded signal rows would push a pub's prices out of it), and they share the price MODERATION path too: ids ride on the read, `POST /api/price-submit { action: "report" }` flags either shape, `/api/admin/community-prices` lists both (`kind`) and hide/restore is the removal means, with `freshestVenueSignals` as the single filter so a hidden signal leaves the sheet, the corroboration count and the established answer together. Contributor totals are derived on the server from the same observation rows for future leaderboard reads. `__tests__/communityVenueSignals.test.ts`, `__tests__/venueCommunitySignals.test.ts` and `__tests__/communityPriceModeration.test.ts` pin those apart.
- **A Round records spend, never debt.** `lib/rounds.ts` owns immutable buying turns and derives rotation from their payer order. A plain total stays inside the Round diary. Itemised drink lines reach the community-price store only for a signed-in account with a claimed public handle; anonymous lines stay private in the diary. Membership resolves through stable profile ownership, so a handle rename cannot strand a member or retry. Each line persists its promotion state, so dependency failures retry idempotently and only `promoted` lines claim community-price status in the UI. The latest line from one account for each venue and drink category owns that community-price key; earlier same-key lines become `superseded`, stay in the diary, and stop claiming live status. Older rows without durable outcome evidence stay neutral as `legacy_unknown`, never relabelled as promoted or diary-only. Promoted lines can affect map price surfaces only through `mergeCommunityPriceSignals`. Never add balances, shares, IOUs, settlement, or debt totals to this model. A drink line is a first-party observation, so a known price may only PRE-FILL the composer's drink row for the drinker to confirm, and the remaining gate on what reaches `submitCommunityPrice` is PROVENANCE, never the figure: `RoundSpendItemSource` (`lib/rounds.ts`) records whether a line is the drinker's own claim ("round") or a figure lifted off the seeded demo menu ("demo"), and a demo line stays in the diary labelled rather than being dropped. Value equality is the wrong fence: a drinker who really paid what a demo menu quotes is still observing it, and a refusal nobody is told about reads as a price they logged. `__tests__/roundsRoute.test.ts` pins identity, promotion retry, corroboration, demo refusal, and coincidence.
- **No-alcohol prices share trust policy, never pint authority.** `lib/drinks.ts` owns the closed drink taxonomy mirrored by database CHECK constraints, so every category addition needs a migration. Soft-drink and alcohol-free reports earn map visibility through the same corroboration and age gates as beer, but `lib/mapExperienceLens.ts` keeps every category `MapLensPrice` outside `VenueSignal`, cheapest-pint buckets and the Pint Index. An explicit selected-drink lens may use that trusted category price for pin colour, its category-labelled pin figure and cheapest-drink views; a missing category price stays unknown. Food anchors may join experience views only with their real source metadata and never print on pins. Which categories a viewer may put the MAP under is a narrower question than which they may log: `MAP_LENS_DRINK_CATEGORIES` (in `lib/drinks.ts` beside the taxonomy it narrows, so `parseDrinkCategoryParam` can share it without importing the map) drops `other` because a pin reading "£6 Other" labels a figure with a name identifying no drink, while `SUBMITTABLE_DRINK_CATEGORIES` keeps it so nothing is unloggable. De-lensing a category also has to de-FILTER it AND de-LINK it: the URL, the restored session, `filterVenues`, the persona lens and the Discover explore grid all read that one guard, because a category the picker cannot show or clear would otherwise narrow the map in silence (worse than a wrong figure - the reader cannot tell there is anything to disbelieve), and a card promising a filtered view the map will not honour reads as a broken destination rather than one never offered. `__tests__/categoryShowcaseLens.test.ts` pins the grid. Empty views stay explicit; never seed prices to populate them. The UK base layer is suspended while any price lens owns the map (`suspended` in `useUkBaseStreaming`) because 38k unpriced pubs answer neither question. The cross-venue category index is the one read that is neither per-venue nor per-actor, so `readCommunityPriceCategoryIndex` holds its promise briefly and any write drops it; and a TRUNCATED index is `partial`, never `degraded`, because it answered. Every such index reports on one three-way scale (`CategoryPriceIndexStatus`), a single pub's own read reports on the same scale minus `partial` (`VenuePriceReadStatus`, set by `loadVenue`), and every surface either feeds has to say which it got - a sheet may call a pub empty only once ITS read answered: an all-unknown map under a read that FAILED may never be worded as a city with no prices in it, and a partial read keeps its "trusted prices" sentence because its figures are real. `drinkLensCoverageNote`, `drinkLensUnknownRowLabel`, `mapPriceLegend`'s hint and `experienceLensSummary` are the sentences, and the row label exists because a row is read on its own - the list row, the area row, the mobile peek and the desktop hover card are all that single read, so all four take the helper rather than a bespoke line, and the ACCESSIBLE list is the DOM parallel to the pins. A lens whose display name is already a negative gets a separate sentence noun (`NO_ALCOHOL_LENS_PRICE_NOUN`), because "no no-alcohol price logged" hides the one fact that is about the pub. `__tests__/mapExperienceLens.test.ts`, `__tests__/mapPriceLegend.test.ts`, `__tests__/mapVenueList.test.ts`, `__tests__/canvas-hoverCard.test.ts` and `__tests__/areaSheetDrinkLens.test.ts` pin them apart.
- **A pin's COLOUR may be a hint; a pin's FIGURE may not.** Pins print the price itself from `PIN_PRICE_LABEL_MIN_ZOOM` (`components/map/canvas/filters.ts`, which owns the gate and the `text-field` expressions; the tag's size/offset/padding are at the top of `buildScene.ts`). The default pint band (`priceBucket`) may be fed by a demo seed so an unpriced city pack still reads as a map; its label is a claim, so `formatPinPriceLabel` in `geojson.ts` reads a strictly narrower stack - contributor price, curated `cheapestPrice`, favourite-pint price, never `latestDemoPrice` and never a `priceBand` without a price - and only for pub kinds (`isPubVenueKind`). A selected non-pint lens replaces both band and label from its corroborated category price, names the drink in the label, and makes missing prices neutral. A famous bar, late-food, or restaurant venue's default `cheapestPrice` is its anchor price (a cocktail, a doner, a signature dish), which printed bare would masquerade as a pint. An uncorroborated report cannot reach either lane (see the community-price bullet). The tag rides `pubs-point` itself (not a second layer) and takes the ordinary collision deal - `text-optional`, no `*-allow-overlap`, so where it will not fit the LABEL goes and the pin stays. `__tests__/mapSymbolCollision.test.ts` and `__tests__/canvas-geojson.test.ts` pin both halves.
- **A pin's fill says the price; its EDGE is what makes it findable, and dark mode needs two tones for that.** Dark roads are subordinate warm context in `lib/mapBasemapTaste.ts`, but night ground, water, buildings, and road tiers still span distinct tones, so no single rim edges every price band everywhere. `venuePinEdgeTokens` (`components/map/canvas/tokens.ts`) therefore publishes a rim plus an opposite-luminance casing in dark and nothing in light, and `makeVenuePinDraw` in `lib/mapIcons.ts` draws the casing pass first at `GLASS_CASING_STROKE` so the rim can drop to a hairline and the band keeps its area. Do not reach for a brighter band instead: `--brick` is a muted rose because dark `--brass` is a coral, and this map's rings are already spoken for. `__tests__/mapPinBandContrast.test.ts` reads the shipped dark tokens rather than a restated copy - the original defect was `--paper` resolving to a near-black, which turned a documented "light rim" into a black one - and holds every band to an edge over every dark basemap tone.
- **An audit waiver is a documented exception, not a mute button.** `npm run verify` ends in `scripts/resilient-audit.mjs`, which fails on high/critical findings, tolerates primary registry outages, and waives only advisories named in its `WAIVED_ADVISORIES` set - each with an inline rationale and a removal condition, and only while a second production-only audit proves the chain is dev-only. Add an entry there only after upgrades and `overrides` are genuinely exhausted; never hide an advisory by raising `--audit-level`, omitting dev dependencies from the primary audit, or skipping the step. `__tests__/resilientAuditWaivers.test.ts` pins the blast radius.
- **Two pub layers, and only one of them is the product.** `venues_slim*.json` is the CURATED index - priced pins, search, filters, crawl routing - and its payload budgets are enforced in `scripts/build_slim_index.mjs`. The UK-wide unpriced OSM pubs are a separate BASE layer streamed per viewport past a zoom gate. Never merge base pubs into the venue index: doing so would impose the country-wide payload on every phone and put unpriced pubs into product systems that require curated venues. `public/data/uk_base/README.md` owns delivery, dedupe, and identity details. Both layers carry OSM-derived venues, so the ODbL credit is attached to the MAP (`OSM_ATTRIBUTION` in `components/map/canvas/tokens.ts`, passed as MapLibre's `customAttribution`) rather than to one optional source - a source-only credit disappears in every city that does not load that source. The **third map** is national browse of that base layer (`/map?uk=1`, place search, locate-to-town) on the same canvas - ADR `docs/adr/0013-uk-national-base-map.md` - never a Google Maps clone and never a multi-city priced splash. `__tests__/mapOsmAttribution.test.ts` pins it.
- **No surface is a dead end, and the way out is one pattern.** `lib/surfaceStack.ts` holds the presentation-free trail. On the Map, `components/map/pubmap/useMapSurfaceNavigation.ts` is the only browser-history owner: every entry carries the complete trail plus venue selection state, direct opens synchronously publish their decision before React changes drawers, and its one `popstate` listener restores the landed snapshot. An internal open may only `pushState` or `replaceState`; reopening a surface already lower in the trail writes a fresh entry with the current surface as its parent and never calls `history.go()` to negotiate with a browser Back already in flight. `components/ui/surface-nav.tsx` is the only affordance: leading Back, trailing Home, the same 44px box in the same two cells of a `44px 1fr 44px` head on the phone sheet, desktop drawers and List view panel. Back renders only when there is a parent. Escape is keyboard Back and fling-dismiss is gesture Back. Back must restore exact held state, never reload a default. Never push history from inside a setState updater. A panel anchored to a visible trigger (map key, layers, persona, Ask, site More menu) is not in the trail and owes only `lib/useDismissOnEscape.ts` plus outside dismiss. Ambient banners and chips owe neither. `__tests__/mapSurfaceHistory.test.ts`, `__tests__/surfaceStack.test.ts`, `e2e/map-surface-history.spec.ts` and `e2e/surface-back-and-home.spec.ts` pin the rules.
- **Phone chrome is measured, not eyeballed, and a trust caption never ellipses.** Phone rows share the balanced `--mobile-map-stack-left` / `--mobile-map-stack-right` outer boundary published in `components/mobile/mobileMapShell.css`; the Tonight Arc reserves the `--mobile-map-corner-lane` inside that boundary so the fixed TfL control and a right safe-area inset cannot steal its taps. `e2e/mobile-map-chrome-fit.spec.ts` owns the rendered 320px, 390px and 430px geometry, horizontal scrolling, centre-point hit ownership and 164px budget guarantees. `__tests__/mobileChromeFit.test.ts` owns the shipped-CSS contract, 44px tap-target floors, and the rule that the venue price caption wraps rather than truncating. Do the measuring in a real device viewport: `chrome-devtools-axi open` drops the CDP device override, so `open`, then `emulate --viewport "390x844x3,mobile,touch"`, then reload in place (`eval '()=>location.reload()'`) - a second `open` resets it again, and the mobile shell only mounts if the page booted at phone width. A truncated `£5.50 / current recorded pri…` is a price whose meaning was cut, which the whole trust argument rests on; widen the cell or wrap the line, never ellipsis it.
- **How copy reads is governed, and the governor is `docs/VOICE.md`.** It owns the banned-word list, the no-em-dash law (`__tests__/emDashLaw.test.ts`), British spelling, the no-exclamation rule, and the named-publisher versus publisher-not-recorded price disclosure. Two tree-wide fences sit beside it: `__tests__/frictionVoice.test.ts` (empty/denied/error surfaces may never leak plumbing or slam the door) and `__tests__/landingPriceHonesty.test.ts` (only the people-logged price lanes may be described as dated per row), and single surfaces carry their own voice fences next to them. Jokes belong in empty states, loading lines, the 404 and a couple of dev-tools easter eggs; never beside a figure, a date, a source, an attribution, a legal term, or an accessible name. The bar a line must clear, and the visible-copy vs accessible-name split, are `docs/VOICE.md` "Where the jokes live".
- **The privacy notice is part of the data path, not marketing copy.** `/privacy` and `/terms` (`app/privacy`, `app/terms`, shared `app/legal.css`) describe exactly what the code does: consent-gated analytics, hashed-never-stored IPs, the named processors. Viewer points cross the one browser-and-server egress seam in `lib/geo.ts`; do not add caller-owned rounding, and keep public venue coordinates distinct from viewer coordinates. Durable `rate_limits` rows expire with their useful window and both database writers prune expired keys rather than leaving an activity archive. Change a data practice and change those pages in the same commit; `__tests__/legalPages.test.ts`, `__tests__/viewerCoordinateEgress.test.ts`, and `__tests__/rateLimitExpiryMigration.test.ts` pin these contracts. The one public contact address lives in `lib/siteContact.ts` - never hardcode it into a page.
- **A published Pint Index month is written once.** `/pint-index` stays live; every CLOSED month is frozen to `public/data/pint_index/<YYYY-MM>.json` by `npm run publish:pint-index-month -- --month YYYY-MM` and served at `/pint-index/<YYYY-MM>` with its own CSV, OG card and `Dataset` JSON-LD. Every figure-bearing block on that dated route must read only the frozen edition: live map prices, the live `PintIndexArrival`, and national benchmarks belong only on `/pint-index`. `__tests__/pintIndexEditionPage.test.ts` pins that page boundary. The rules are `lib/pintIndexArchive.ts` (a FIRST publication needs a closed month at or after `PINT_INDEX_PUBLIC_START_MONTH` that the live snapshot assessed; a correction is checked against `monthPublishFloorBlocker` alone, because the live window moves on and a published figure nobody can fix is worse than a visible correction; a correction is amended out of the PUBLISHED edition by `amendArchivedMonth` and never re-derived from the live snapshot, whose silence about an old month is absence rather than evidence; a republish needs `--correction "<note>"` naming what changed, with `--withdraw <observation>` for a price that should never have been in the Index or `--restate <observation> <pricePence>` for one that belongs but was written down wrong, where `<observation>` is `<venueId>[@<observedAt>][#<sourceId>][^<ordinal>]` and names exactly ONE published price because a month may hold several for a pub, an ambiguous reference being refused rather than guessed, and appends a dated correction carrying the replaced revision's observations hash, never a quiet edit; the canonical form the integrity hash covers is `lib/pintIndexCanonical.mjs`, imported by both the app and `validate-data` so the gate cannot accuse a correctly published edition of having been rewritten) and they are re-checked on every build by `validate-data` and `__tests__/pintIndexArchive.test.ts`. A month whose observations stop matching its stored hash is served as unpublished rather than answering a citation. The SCHEMA of an edition is written once too: the live export's columns and the frozen editions' come from one column table in `lib/pintIndex.ts` (`LEAGUE_CSV_HEADER` vs `PUBLISHED_EDITION_CSV_HEADER`, split by `LIVE_ONLY_CSV_COLUMNS`), so a new column joins the live CSV alone and reaches a dated month only through a correction - widening it silently shifts every later column for anyone parsing by position with no figure moved. `__tests__/pintIndexEditionCsvRoute.test.ts` pins the published header as literal bytes.
- **The live Pint Index arrival must full-load the map.** The area chips in `components/pintindex/PintIndexArrival.tsx` are plain anchors on purpose: the map freezes at mount whether an arrival is intentional (`lib/explicitMapIntent.ts`) and what the camera owes it, so a soft navigation from another page hands it an empty query, opens all of London and stacks the first-run welcome on top. They deep-link `?sel=<venue>`, not `?q=<area>`, because a phone arriving at `/map?q=Camden` today is still looking at the whole city. The arrival funnel's events are in `lib/analyticsEvents.ts` and `docs/METRICS_FUNNEL.md` §6.
- **Only two CURRENT price lanes are dated per row.** (The historical lane below carries a per-row day too, but it is never a current price.) Community submissions and `public/data/drink_price_updates/*` carry a real per-observation timestamp; the curated venue index's priced rows share one hand-maintained stamp in `data/freshness_registry.json`. A named publisher may appear only when that price row carries one; otherwise the surface says no publisher is recorded and never borrows venue notes or image credits. Marketing copy follows the disclosure contract in `docs/VOICE.md` and may date only the people-logged lane.
- **A historical price is history, and history answers nothing about tonight.** `public/data/price_history/london.json` holds dated, sourced prices from years gone by (wave one: archived pub reviews, hand-read before shipping). It is a THIRD price lane, second class by design: it may never enter price bands, pin colour, the pin price label, cheapest-pint buckets, the Pint Index, the freshness registry, or any current-price merge. The rule and the row guards are `lib/priceHistory.ts`, the only consumer is `components/map/VenuePriceThen.tsx` via `lib/priceHistoryLoader.ts`, and `__tests__/priceHistory.test.ts` pins the import fence, the data fence and the row schema. `public/data/price_history/README.md` owns what earns a row; curate it, do not generate it.
- **A national average is somebody else's measurement, and it may never pass as one of ours.** `lib/nationalPintBenchmarks.ts` carries the small hand-curated set of cited UK figures shown on `/pint-index`; a two-figure row is a then-and-now line and reuses the venue sheet's idiom. It is a FOURTH price lane and the most quotable one, so the fence is the same shape as price history's: nothing shaped like an observation is exported, the module is reached by `components/pintindex/NationalPintBenchmarks.tsx` and the live page alone, and it never appears on a dated edition, whose figures are promised not to move. Cite the body that counted the figure, not the paper that repeated it, and drop any claim without a named publisher, a public link and a day. `__tests__/nationalPintBenchmarks.test.ts` pins the import, shape and presentation fences. The dearest-end view beside it is presentation only (`dearestFirst` in `lib/pintIndex.ts`): cheapest-first stays the default, and `PintIndexLeagueTable` moves the ranked column ahead of the others because that table scrolls at 390px and a rank counted on an off-screen figure is unreadable.
- **A file a route opens at runtime is not in the deployed function unless you say so.** Next traces only paths it can see statically, so any route that builds a path at request time (`join(process.cwd(), somethingFromJson)`) ships without its data, and whether the file is there anyway is an accident of which routes Vercel grouped into that lambda - a distinct `maxDuration` isolates a route and takes the accident away. That is what made the freshness-audit cron report every field-stamped feed as `unknown` daily while `/api/freshness`, same code and same deployment, resolved them fine. Declare such files in `next.config.mjs` `outputFileTracingIncludes`, derived from their registry rather than hand-copied; `__tests__/freshnessTracing.test.ts` pins the freshness pair and `__tests__/feedTracing.test.ts` the dynamic `/feed`, which opens the drink-price overlay plus every enabled city's slim venue pack per request. The ROUTE list is derived as well: `RUNTIME_DATA_PACKS` in `lib/venueIndexTracing.mjs` names each module that assembles a data path at request time (the city packs, the detail manifest and rows, the id alias map, the menu overlay, the UK place index) with the files it can open, the reader routes come from the source import graph, and a hand-written key for such a route merges with the derived one instead of replacing it. Declare a new pack there rather than naming a route. Then mark the declared dynamic path operation with Next's `turbopackIgnore` comment so automatic tracing does not widen the route to the whole repository; the comment never replaces the explicit include. `__tests__/venueIndexTracing.test.ts` fails when a reader is undeclared, and it also fails when ANY route-reachable module hands `fs` a path it assembled unless that module is a declared pack, is named in `RUNTIME_PATH_MODULES_TRACED_ELSEWHERE` (its files arrive through another key), or is carried in `RUNTIME_PATH_MODULES_PENDING_DECLARATION` saying what it opens - a documented exception whose list may only shrink, never a mute button. That is why the pack table lives in `lib/cityVenuePacks.mjs`: the config cannot import TypeScript, so a city added to `lib/cities.ts` alone would browse in the app and be missing from the deployed function. Venue-detail lookup must preserve `unavailable` through `/api/venue/[id]` as a 503 so the map says it could not check; it must never collapse missing runtime data into an unknown pub. `__tests__/venueRoute.test.ts` and `e2e/map-unknown-selection.spec.ts` pin the distinction. To check a real build rather than guess, read `.next-prod/server/<route>/route.js.nft.json` - it is the exact file set that function ships with.
- **"Stale" and "cannot tell" are two findings, and an alert may never merge them.** The freshness spine (`lib/freshness.ts`) reports a feed whose DATA is over budget separately from one whose age it could not measure, and `resolveStamp` gives every failure mode its own sentence naming the artifact, so an alert is actionable. `lib/freshnessNotify.ts` logs them as two groups and the cron answers `stale` and `unresolved` separately. Never let an unmeasurable feed read as fresh, and never let it count as stale either: merging them is how eleven blind spots hid two real breaches for weeks. `scripts/check_freshness.mjs` mirrors the same rules dependency-free.
- **An API error is one envelope, and every mutating route is rate limited.** Every 4xx/5xx JSON body from `app/api` goes through `publicApiError` (`lib/apiError.ts`; `publicApiErrorFromStatus` when a shared gate decided the status) - extra reader-visible fields ride `compatibilityFields`, never a bespoke shape. A 2xx fail-soft payload may carry an `error` field beside real data; that is not an error response. Cron routes authenticate with `assertCronRequest` (`lib/cronAuth.ts`) instead of a limiter; every other mutating route consults `isLimited` (`lib/pintDrops.ts`, per-IP keys, neighbours' budgets) or a named delegation such as `socialCrewActor`. `__tests__/theLocalErrorContract.test.ts` sweeps every route plus one level of local helper imports and fails on a rogue emitter or an unlimited mutating route.
- **Do not commit tooling churn.** `next dev` rewrites `next-env.d.ts`'s route-types import to the dev path (`./.next/dev/types/routes.d.ts`) and `npm install-scripts approve` adds an `allowScripts` block to `package.json`. Both are local artifacts of running the app, not changes: `git checkout --` them before committing.
- **Shared-worktree build gotcha:** a concurrent `next dev` and `next build` can clobber `.next` mid-build and leave `BUILD_ID` missing (the `prestart` guard will refuse to `next start`). For isolated production QA, build/serve with `NEXT_DIST_DIR=.next-prod` so it doesn't collide with a running dev server.
- **A hand-started server on the e2e port makes Playwright lie.** `playwright.config.ts` owns the env that lets keyless API routes run (`webServer.env`); without it a production build refuses the routes that write, so `/api/plans/generate` answers 500 and the spec reads as a broken planner. Playwright reuses an existing listener on its port rather than starting its own, so a `npm run start` left on 3100 silently becomes the server under test, and every later run inherits that gap. Free the port before a real run; to reuse a build deliberately, start it with the config's env and pass `PW_SKIP_WEBSERVER=1`. For normal E2E, `PW_NEXT_DIST_DIR` moves the build directory. The screenshot commands inherit the isolated wrapper's `NEXT_DIST_DIR`; an explicit `PW_NEXT_DIST_DIR` still wins.
- **`/plan` opens on one describe-first question, not the wizard.** `components/plan/PlanDescribeFirst.tsx` is the default entry surface at every width: one heading, a free-text field, and a few chips that generate a real route keyless. The five-step wizard (`components/plan/PlanIntake.tsx`) sits behind its own "Guide me instead" link and is otherwise unchanged, including its own internal "Describe instead" skip straight to the full composer's concierge field. A returning visitor with a saved, incomplete wizard draft (`pubmax:plan-intake:v1`) lands back on the wizard instead of describe-first. `/plan` renders `PlanComposer` alone - `MobilePlanActivation` is the map sheet's phone planner (`components/PubMap.tsx`) and never mounts on that route, so the two surfaces need separate specs.
- **Manual planner testing is stateful and constraint-sensitive.** `/api/plans/generate` returns `422` with "No three-stop route ... meets every must-have need with the information available" (not a crash) when the intake carries must-have needs (e.g. access or a hard budget ceiling) that the area's data can't satisfy - it is honest scarcity, not a broken environment. The intake also persists across sessions in `localStorage` (`pubmax:plan-intake:v1`) and a route draft in `pubmaxx:plan-route-draft:v1`, so a prior run's constraints silently leak into the next and make repeat generations flaky. Manual UI planner tests should run in a fresh/incognito profile; a low-constraint free-text request via "Describe instead" (e.g. `Quiet in Clapham for 4, not pricey`) reliably yields a priced three-stop plan keyless. The e2e specs clear this state with `addInitScript` instead.
- **A browser test never guesses where a pin is.** The pins paint through the MapLibre canvas, so a spec cannot find one in the DOM, and a grid of taps hunting for one is a race the test loses under parallel workers. `components/map/canvas/paintedPinProbe.ts` publishes `paintedMapTapPoints` on `window`: the viewport point of every pin and cluster the map is drawing right now, each checked to have survived symbol collision, to re-query to the same mark, and to carry no app chrome on top of it. It is unconditional, like the `pubmax:pin-reveal` event beside it, because the browser suite runs a production build. The map opens with the pubs gathered, so a spec that wants a pin opens a cluster first. `__tests__/paintedPinProbe.test.ts` pins the gates and `e2e/mobile-map-chrome-fit.spec.ts` walks them.
- **Honest path anti-goals (London night OS first).** Do not ship a Twitter-for-pubs growth engine; do not enable Social invite beta or referral grants in this wave; do not market multi-city splash without London density; do not add Stripe Checkout / payments theatre before venue trust density; do not build AI that fabricates prices, hours, or pub lore (heritage and plan generate fail closed to grounded / scarcity answers); do not claim “we beat Stripe” in marketing or investor copy.
