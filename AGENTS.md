### Running the app, CI and the database

- **Runs keyless.** `npm run dev` works with no secrets: Pint Drops use an in-memory store and `/api/heritage` returns grounded structured-only answers. Supabase and `OPENROUTER_API_KEY` are needed only to exercise durable persistence, browser auth, admin moderation and narrated heritage. See `.env.example`.
- **Standard commands** live in `package.json` and `README.md`: `npm run dev`, `lint`, `typecheck`, `test`, `verify` (the pre-push gate), `ci`. `npm run test:e2e` needs `npx playwright install --with-deps chromium` first; its config builds and starts the app itself. The pre-push hook (`.githooks/pre-push`) is only active after `npm run setup`, which sets `core.hooksPath=.githooks`; a fresh clone does not have it enabled.
- **PR CI runs on stock `ubuntu-latest`.** So a test may not depend on a binary that image does not ship. `.github/workflows/ci.yml` triggers on pull_request and push to `main`; effective RLS stays in `.github/workflows/rls-session.yml`. Do not repoint `runs-on` to Blacksmith (#747 rejected). Branch protection is captain-side.
- **Do not commit tooling churn.** `next dev` rewrites `next-env.d.ts`'s route-types import and `npm install-scripts approve` adds `allowScripts` to `package.json` (`./.next/dev/types/routes.d.ts`). Both are local artifacts of running the app, not changes: revert them before committing. Also: a concurrent `next dev` and `next build` can clobber `.next` and leave `BUILD_ID` missing, so use `NEXT_DIST_DIR=.next-prod` for isolated production QA.
- **RLS is a second line of defence; the service role is still the write path.** App stores use `requireSupabaseAdmin` and bypass RLS. Migrations `0065`-`0069` add JWT policies derived from API ownership (`supabase/migrations/2026080320*_rls_wave2_*.sql`) (`supabase/migrations/rollback/20260803200000_rls_wave2_rollback.sql`). Hard rules the policies must keep: `visit_reports` SELECT matches `canViewOnPublicSurface`; `community_prices` SELECT is `hidden_at is null` only, with no actor exception; `private_account_identities` is owner SELECT only. Never re-open `using (true)` on a private table, and never grant `plan_crew_members.token_hash` or `community_prices.actor` to browser roles. Captain applies migrations; agents ship SQL only. Pins: `npm run test:rls` (needs local PostgreSQL 16 and PostgREST), `__tests__/rlsWave2Policies.test.ts`.
