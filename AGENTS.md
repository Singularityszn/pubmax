### Identity, accounts and auth

- **A moderator door refuses the DOCUMENT.** `app/admin/page.tsx` gates before the console mounts via `canOpenAdminDocument` (`lib/adminAuth.ts`) and `unauthorized()`; client-side gating around a 200 shell was the defect. Both doors spend one session module (`lib/adminSessionClient.ts`) whose read is TRI-STATE: `anonymous` after a POST means the browser refused the cookie, which is not `unknown`. The cookie is `SameSite=Lax` because the gate is on a top-level navigation. Pins: `__tests__/adminDocumentGuard.test.ts`, `e2e/admin-document-guard.spec.ts`.
- **`/login` names nobody until the session answers.** Head copy is `lib/loginPageFraming.ts`; while it resolves, `aria-busy` sits on the SHAPE and the screen-reader line OUTSIDE it. `/sign-in` is a 308 in `proxy.ts`. Pins: `__tests__/loginPageFraming.test.ts`, `__tests__/loginSkeletonAnnouncement.test.ts`.
- **A durable resume cookie mirrors the evictable browser session.** `lib/authSessionResume.ts`, route `/api/auth/session`, client seam `lib/authSessionResumeClient.ts`. Sign-out is the only deleter; malformed data reads as absent at every decode boundary. Do not touch `AuthProvider.tsx` token-fragment paths outside the auth lane. Pins: `__tests__/authSessionRoute.test.ts`, `__tests__/authSessionResume.test.ts`.
- **A password is CREATED behind a session and only ever SPENT without one.** Creation is `updateUser` from a signed-in browser (`components/auth/SetAccountPassword.tsx`); no route of ours is in that path. `lib/passwordPolicy.ts` is the ONE owner of the rules and their words. Sign-in applies the length floor alone and answers ONE 401 shape for unknown handle, wrong password and too-short alike, with the way out under EVERY failure. `account_has_password` is tri-state (migration `0099`, service-role only). Pins: `__tests__/passwordPolicy.test.ts`, `__tests__/handlePasswordRoute.test.ts`, `e2e/account-password.spec.ts`.
- **The signed-in account is the only identity authority on a device.** `lib/deviceAccountIdentity.ts` owns the artifact set and the owner stamp; `AuthProvider.updateSession` rebinds it on every auth event before children re-render, and a different or unstamped account loses the whole set atomically. Sign-out drops set and stamp together. Identity is TRI-STATE: a surface that NAMES or ROUTES the viewer stays neutral until the live session answers, never a cache, never a confident "nobody" from a failed read (`components/auth/useViewerHandle.ts`, `useViewerSession.ts`). Writes announce themselves, because a same-tab write raises no `storage` event. Pins: `__tests__/deviceAccountIdentity.test.ts`, `__tests__/gatedActorAuth.test.ts` (tree-wide), `e2e/account-switch-identity.spec.ts`.
- **A device may hold several accounts, and exactly one owns it.** `lib/deviceAccountSessions.ts` keeps one refresh token per account, deliberately OUTSIDE the identity key set that every account change drops. The swap (`lib/deviceAccountSwitch.ts`) exchanges the token at GoTrue directly then `setSession`, so the ordinary auth event runs the atomic pass; never refresh through the live client, which would sign you out of the account you are leaving. Outcomes are three-way: a REFUSED token is deleted, a read that could not run keeps it. Sign-out is scoped, and `clearPersistedSession` is awaited. One control: `components/auth/AccountDeviceControls.tsx`. Pins: `__tests__/deviceAccountSwitch.test.ts`, `__tests__/accountSwitcherRender.test.ts`.
- **Arrival is the moment of togetherness, never an admin form.** An account holding a handle is owed nothing: `components/identity/AccountOnboarding.tsx` awaits the server answer and resolves to nothing, because handle-claim stores no date of birth so onboarding reports incomplete forever. Renaming lives in profile editing alone; a failed status read never falls through to the claim form. Returning accounts get one line (`lib/arrivalWelcome.ts`), a live region and never a dialog. `/login` is two doors sharing one link machinery. Pins: `__tests__/arrivalWelcome.test.ts`, `__tests__/accountOnboarding.test.ts`, `e2e/arrival-journey.spec.ts`.
- **Everybody who joins is taken to be an adult, on ONE recorded tap.** `accountIsAdult` (`lib/socialLaunch.ts`) is THE gate and reads two things: stored date of birth, which still decides in both directions, and the recorded assertion (`adult_self_assertions`, migration `0103`, written only from the caller's own bearer). The tap is offered only when it is the actual blocker, as one line and one button, never a dialog. Photo walls ask the same question through the same function. NOTHING else may branch on an assertion: it is not a capability. Pins: `__tests__/socialFriendsLaunch.test.ts`, `__tests__/adultSelfAssertionRoute.test.ts`, `e2e/social-open.spec.ts`.

### Running the app, CI and the database

- **Runs keyless.** `npm run dev` works with no secrets: Pint Drops use an in-memory store and `/api/heritage` returns grounded structured-only answers. Supabase and `OPENROUTER_API_KEY` are needed only to exercise durable persistence, browser auth, admin moderation and narrated heritage. See `.env.example`.
- **Standard commands** live in `package.json` and `README.md`: `npm run dev`, `lint`, `typecheck`, `test`, `verify` (the pre-push gate), `ci`. `npm run test:e2e` needs `npx playwright install --with-deps chromium` first; its config builds and starts the app itself. The pre-push hook is only active after `npm run setup`.
- **PR CI runs on stock `ubuntu-latest`.** So a test may not depend on a binary that image does not ship. `.github/workflows/ci.yml` triggers on pull_request and push to `main`; effective RLS stays in `rls-session.yml`. Do not repoint `runs-on` to Blacksmith (#747 rejected). Branch protection is captain-side.
- **Do not commit tooling churn.** `next dev` rewrites `next-env.d.ts`'s route-types import and `npm install-scripts approve` adds `allowScripts` to `package.json`. Both are local artifacts of running the app, not changes: revert them before committing. Also: a concurrent `next dev` and `next build` can clobber `.next` and leave `BUILD_ID` missing, so use `NEXT_DIST_DIR=.next-prod` for isolated production QA.
- **RLS is a second line of defence; the service role is still the write path.** App stores use `requireSupabaseAdmin` and bypass RLS. Migrations `0065`-`0069` add JWT policies derived from API ownership. Hard rules the policies must keep: `visit_reports` SELECT matches `canViewOnPublicSurface`; `community_prices` SELECT is `hidden_at is null` only, with no actor exception; `private_account_identities` is owner SELECT only. Never re-open `using (true)` on a private table, and never grant `plan_crew_members.token_hash` or `community_prices.actor` to browser roles. Captain applies migrations; agents ship SQL only. Pins: `npm run test:rls` (needs local PostgreSQL 16 and PostgREST), `__tests__/rlsWave2Policies.test.ts`.
