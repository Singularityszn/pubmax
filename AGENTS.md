# AGENTS.md

## Cursor Cloud specific instructions

PubMaxing is a single Next.js 16 (App Router, React 19, TypeScript) web app — a price-aware London pub-crawl planner with a MapLibre 3-D map. There is one service.

- **Runs keyless.** `npm run dev` (Next dev on webpack, http://localhost:3000) works with no secrets: Pint Drops use an in-memory store and `/api/heritage` (The Landlord) returns grounded structured-only answers. Supabase / `OPENROUTER_API_KEY` in `.env.local` are only needed to exercise durable persistence, browser auth, admin moderation, and narrated heritage replies — not required to run or demo the app. See `.env.example`.
- **Standard commands** live in `package.json` scripts and `README.md`: `npm run dev`, `npm run lint`, `npm run typecheck`, `npm test` (Vitest), `npm run verify` (validate-data · lint · typecheck · coverage — the pre-push gate), `npm run ci` (verify + build).
- **`npm run test:e2e`** (Playwright) needs browsers installed first: `npx playwright install --with-deps chromium`. The e2e config builds and starts the app itself.
- **Pre-push hook** (`.githooks/pre-push`) runs `npm run verify` but is only active after `npm run setup` (sets `core.hooksPath=.githooks`); it is not enabled by default in a fresh clone.
- **Map density is a contract, not a styling choice.** The pin/cluster zoom boundaries, supercluster radius, and the symbol-collision policy that stops labels and pins overlapping (sole exemption: the selected pin's dedicated layer) are the constants at the top of `components/map/canvas/buildScene.ts` (and the layers below them), asserted in `__tests__/mapSymbolCollision.test.ts`. Change them there, and keep every app symbol layer inside MapLibre's collision index.
- **What a community price is allowed to move is a policy, not an implementation detail.** An anonymous submission always shows on the pub's own sheet, dated, but only reaches pins/list rows/cheapest buckets once it is corroborated by a second independent submitter and is inside the max-age window. The constants and predicates are in `lib/communityPrice.ts`, the count is derived (never stored, never client-supplied) on the store's read path, and the price gate is `mergeCommunityPriceSignals` in `components/map/communityPriceSignals.ts`. VISIBILITY is a separate, ungated question from AUTHORITY: a first in-window pint report immediately marks its pin with a provisional badge via `provisionalCommunityPriceVenueIds` (same file, second seam - a set of ids, never a `VenueSignal`), while pin colour, list rows and cheapest buckets still wait for corroboration. Keep the two seams apart: nothing about a pending report may travel through the price merge. Taking a price DOWN is the mirror policy: readers flag (`POST /api/price-submit { action: "report" }`), only a moderator hides (`app/api/admin/community-prices`), reporting never auto-hides (unlike pint drops - an anonymous threshold here would be a one-tap eraser), and hiding never deletes. The one filter lives in `freshestPerCategory`, so a hidden row leaves the sheet, the corroboration count and the map candidate together; `__tests__/communityPriceModeration.test.ts` pins it.
- **A pin's COLOUR may be a hint; a pin's FIGURE may not.** Pins print the price itself from `PIN_PRICE_LABEL_MIN_ZOOM` (`components/map/canvas/filters.ts`, which owns the gate and the `text-field` expressions; the tag's size/offset/padding are at the top of `buildScene.ts`). The band (`priceBucket`) may be fed by a demo seed so an unpriced city pack still reads as a map; the label is a claim, so `formatPinPriceLabel` in `geojson.ts` reads a strictly narrower stack - contributor price, curated `cheapestPrice`, favourite-pint price, never `latestDemoPrice` and never a `priceBand` without a price - and only for pub kinds (`isPubVenueKind`): a famous bar, late-food, or restaurant venue's `cheapestPrice` is its anchor price (a cocktail, a doner, a signature dish), which printed bare would masquerade as a pint. An uncorroborated report cannot reach it at all (see the community-price bullet), which is what keeps "a mark, never a figure" true with only one gate. The tag rides `pubs-point` itself (not a second layer) and takes the ordinary collision deal - `text-optional`, no `*-allow-overlap`, so where it will not fit the LABEL goes and the pin stays. `__tests__/mapSymbolCollision.test.ts` and `__tests__/canvas-geojson.test.ts` pin both halves.
- **A pin's fill says the price; its EDGE is what makes it findable, and dark mode needs two tones for that.** The dark basemap is deliberately bimodal (Wave A in `lib/mapBasemapTaste.ts` made roads the lightest strokes on a near-black canvas), so a pin's background spans about 20:1 and no single rim tone edges it everywhere. `venuePinEdgeTokens` (`components/map/canvas/tokens.ts`) therefore publishes a rim plus an opposite-luminance casing in dark and nothing in light, and `makeVenuePinDraw` in `lib/mapIcons.ts` draws the casing pass first at `GLASS_CASING_STROKE` so the rim can drop to a hairline and the band keeps its area. Do not reach for a brighter band instead: `--brick` is a muted rose because dark `--brass` is a coral, and this map's rings are already spoken for. `__tests__/mapPinBandContrast.test.ts` reads the shipped dark tokens rather than a restated copy - the original defect was `--paper` resolving to a near-black, which turned a documented "light rim" into a black one - and holds every band to an edge over every dark basemap tone.
- **An audit waiver is a documented exception, not a mute button.** `npm run verify` ends in `scripts/resilient-audit.mjs`, which fails on high/critical findings, tolerates primary registry outages, and waives only advisories named in its `WAIVED_ADVISORIES` set - each with an inline rationale and a removal condition, and only while a second production-only audit proves the chain is dev-only. Add an entry there only after upgrades and `overrides` are genuinely exhausted; never hide an advisory by raising `--audit-level`, omitting dev dependencies from the primary audit, or skipping the step. `__tests__/resilientAuditWaivers.test.ts` pins the blast radius.
- **Two pub layers, and only one of them is the product.** `venues_slim*.json` is the CURATED index - priced pins, search, filters, crawl routing - and its payload budgets are enforced in `scripts/build_slim_index.mjs`. The UK-wide unpriced OSM pubs are a separate BASE layer streamed per viewport past a zoom gate. Never merge base pubs into the venue index: doing so would impose the country-wide payload on every phone and put unpriced pubs into product systems that require curated venues. `public/data/uk_base/README.md` owns delivery, dedupe, and identity details. Both layers carry OSM-derived venues, so the ODbL credit is attached to the MAP (`OSM_ATTRIBUTION` in `components/map/canvas/tokens.ts`, passed as MapLibre's `customAttribution`) rather than to one optional source - a source-only credit disappears in every city that does not load that source. `__tests__/mapOsmAttribution.test.ts` pins it.
- **Phone chrome is measured, not eyeballed, and a trust caption never ellipses.** The 390px chrome budget (the Tonight Arc rail fits all five of its chips clear of the fixed TfL utility control, which is the binding constraint - fitting inside the viewport is not enough, so both sides measure the same `--mobile-map-corner-lane` published in `components/mobile/mobileMapShell.css`), the 44px tap-target floors, and the rule that the venue price caption wraps rather than truncating are asserted in `__tests__/mobileChromeFit.test.ts` against the shipped CSS. Do the measuring in a real device viewport: `chrome-devtools-axi open` drops the CDP device override, so `open`, then `emulate --viewport "390x844x3,mobile,touch"`, then reload in place (`eval '()=>location.reload()'`) - a second `open` resets it again, and the mobile shell only mounts if the page booted at phone width. A truncated `£5.50 / current recorded pri…` is a price whose meaning was cut, which the whole trust argument rests on; widen the cell or wrap the line, never ellipsis it.
- **How copy reads is governed, and the governor is `docs/VOICE.md`.** It owns the banned-word list, the no-em-dash law (`__tests__/emDashLaw.test.ts`), British spelling and the no-exclamation rule. Two live fences sit beside it: `__tests__/frictionVoice.test.ts` (empty/denied/error surfaces may never leak plumbing or slam the door) and `__tests__/landingPriceHonesty.test.ts` (the landing may claim a SOURCE for every price and a DATE only for the people-logged lanes). Jokes belong in empty states, loading lines and the 404; never beside a figure, a date, a source, an attribution, a legal term, or an accessible name.
- **The privacy notice is part of the data path, not marketing copy.** `/privacy` and `/terms` (`app/privacy`, `app/terms`, shared `app/legal.css`) describe exactly what the code does: consent-gated analytics, hashed-never-stored IPs, the named processors. Change a data practice and change those pages in the same commit; `__tests__/legalPages.test.ts` pins the honesty claims, the footer links and the sitemap entries. The one public contact address lives in `lib/siteContact.ts` - never hardcode it into a page.
- **A published Pint Index month is written once.** `/pint-index` stays live; every CLOSED month is frozen to `public/data/pint_index/<YYYY-MM>.json` by `npm run publish:pint-index-month -- --month YYYY-MM` and served at `/pint-index/<YYYY-MM>` with its own CSV, OG card and `Dataset` JSON-LD. The rules are `lib/pintIndexArchive.ts` (a FIRST publication needs a closed month at or after `PINT_INDEX_PUBLIC_START_MONTH` that the live snapshot assessed; a correction is checked against `monthPublishFloorBlocker` alone, because the live window moves on and a published figure nobody can fix is worse than a visible correction; a correction is amended out of the PUBLISHED edition by `amendArchivedMonth` and never re-derived from the live snapshot, whose silence about an old month is absence rather than evidence; a republish needs `--correction "<note>"` naming what changed, with `--withdraw <observation>` for a price that should never have been in the Index or `--restate <observation> <pricePence>` for one that belongs but was written down wrong, where `<observation>` is `<venueId>[@<observedAt>][#<sourceId>][^<ordinal>]` and names exactly ONE published price because a month may hold several for a pub, an ambiguous reference being refused rather than guessed, and appends a dated correction carrying the replaced revision's observations hash, never a quiet edit; the canonical form the integrity hash covers is `lib/pintIndexCanonical.mjs`, imported by both the app and `validate-data` so the gate cannot accuse a correctly published edition of having been rewritten) and they are re-checked on every build by `validate-data` and `__tests__/pintIndexArchive.test.ts`. A month whose observations stop matching its stored hash is served as unpublished rather than answering a citation. The SCHEMA of an edition is written once too: the live export's columns and the frozen editions' come from one column table in `lib/pintIndex.ts` (`LEAGUE_CSV_HEADER` vs `PUBLISHED_EDITION_CSV_HEADER`, split by `LIVE_ONLY_CSV_COLUMNS`), so a new column joins the live CSV alone and reaches a dated month only through a correction - widening it silently shifts every later column for anyone parsing by position with no figure moved. `__tests__/pintIndexEditionCsvRoute.test.ts` pins the published header as literal bytes.
- **The Pint Index arrival must full-load the map.** The area chips in `components/pintindex/PintIndexArrival.tsx` are plain anchors on purpose: the map freezes at mount whether an arrival is intentional (`lib/explicitMapIntent.ts`) and what the camera owes it, so a soft navigation from another page hands it an empty query, opens all of London and stacks the first-run welcome on top. They deep-link `?sel=<venue>`, not `?q=<area>`, because a phone arriving at `/map?q=Camden` today is still looking at the whole city. The arrival funnel's events are in `lib/analyticsEvents.ts` and `docs/METRICS_FUNNEL.md` §6.
- **Only two CURRENT price lanes are dated per row.** (The historical lane below carries a per-row day too, but it is never a current price.) Community submissions and `public/data/drink_price_updates/*` carry a real per-observation timestamp; the curated venue index's priced rows carry a SOURCE and share one hand-maintained stamp in `data/freshness_registry.json`. Marketing copy may claim provenance for every price and dating only for the people-logged lane - `__tests__/landingPriceHonesty.test.ts` pins the landing page's half of that.
- **A historical price is history, and history answers nothing about tonight.** `public/data/price_history/london.json` holds dated, sourced prices from years gone by (wave one: archived pub reviews, hand-read before shipping). It is a THIRD price lane, second class by design: it may never enter price bands, pin colour, the pin price label, cheapest-pint buckets, the Pint Index, the freshness registry, or any current-price merge. The rule and the row guards are `lib/priceHistory.ts`, the only consumer is `components/map/VenuePriceThen.tsx` via `lib/priceHistoryLoader.ts`, and `__tests__/priceHistory.test.ts` pins the import fence, the data fence and the row schema. `public/data/price_history/README.md` owns what earns a row; curate it, do not generate it.
- **A national average is somebody else's measurement, and it may never pass as one of ours.** `lib/nationalPintBenchmarks.ts` carries the small hand-curated set of cited UK figures shown on `/pint-index`; a two-figure row is a then-and-now line and reuses the venue sheet's idiom. It is a FOURTH price lane and the most quotable one, so the fence is the same shape as price history's: nothing shaped like an observation is exported, the module is reached by `components/pintindex/NationalPintBenchmarks.tsx` and the live page alone, and it never appears on a dated edition, whose figures are promised not to move. Cite the body that counted the figure, not the paper that repeated it, and drop any claim without a named publisher, a public link and a day. `__tests__/nationalPintBenchmarks.test.ts` pins the import, shape and presentation fences. The dearest-end view beside it is presentation only (`dearestFirst` in `lib/pintIndex.ts`): cheapest-first stays the default, and `PintIndexLeagueTable` moves the ranked column ahead of the others because that table scrolls at 390px and a rank counted on an off-screen figure is unreadable.
- **A file a route opens at runtime is not in the deployed function unless you say so.** Next traces only paths it can see statically, so any route that builds a path at request time (`join(process.cwd(), somethingFromJson)`) ships without its data, and whether the file is there anyway is an accident of which routes Vercel grouped into that lambda - a distinct `maxDuration` isolates a route and takes the accident away. That is what made the freshness-audit cron report every field-stamped feed as `unknown` daily while `/api/freshness`, same code and same deployment, resolved them fine. Declare such files in `next.config.mjs` `outputFileTracingIncludes`, derived from their registry rather than hand-copied; `__tests__/freshnessTracing.test.ts` pins the freshness pair and `__tests__/feedTracing.test.ts` the dynamic `/feed`, which opens the drink-price overlay plus every enabled city's slim venue pack per request. That is why the pack table lives in `lib/cityVenuePacks.mjs`: the config cannot import TypeScript, so a city added to `lib/cities.ts` alone would browse in the app and be missing from the deployed function, and the venue lookup fails soft, so the loss reads as an empty surface rather than an error. To check a real build rather than guess, read `.next-prod/server/<route>/route.js.nft.json` - it is the exact file set that function ships with.
- **"Stale" and "cannot tell" are two findings, and an alert may never merge them.** The freshness spine (`lib/freshness.ts`) reports a feed whose DATA is over budget separately from one whose age it could not measure, and `resolveStamp` gives every failure mode its own sentence naming the artifact, so an alert is actionable. `lib/freshnessNotify.ts` logs them as two groups and the cron answers `stale` and `unresolved` separately. Never let an unmeasurable feed read as fresh, and never let it count as stale either: merging them is how eleven blind spots hid two real breaches for weeks. `scripts/check_freshness.mjs` mirrors the same rules dependency-free.
- **Do not commit tooling churn.** `next dev` rewrites `next-env.d.ts`'s route-types import to the dev path (`./.next/dev/types/routes.d.ts`) and `npm install-scripts approve` adds an `allowScripts` block to `package.json`. Both are local artifacts of running the app, not changes: `git checkout --` them before committing.
- **Shared-worktree build gotcha:** a concurrent `next dev` and `next build` can clobber `.next` mid-build and leave `BUILD_ID` missing (the `prestart` guard will refuse to `next start`). For isolated production QA, build/serve with `NEXT_DIST_DIR=.next-prod` so it doesn't collide with a running dev server.
