# AGENTS.md

## Cursor Cloud specific instructions

PubMaxing is a single Next.js 16 (App Router, React 19, TypeScript) web app — a price-aware London pub-crawl planner with a MapLibre 3-D map. There is one service.

- **Runs keyless.** `npm run dev` (Next dev on webpack, http://localhost:3000) works with no secrets: Pint Drops use an in-memory store and `/api/heritage` (The Landlord) returns grounded structured-only answers. Supabase / `OPENROUTER_API_KEY` in `.env.local` are only needed to exercise durable persistence, browser auth, admin moderation, and narrated heritage replies — not required to run or demo the app. See `.env.example`.
- **Standard commands** live in `package.json` scripts and `README.md`: `npm run dev`, `npm run lint`, `npm run typecheck`, `npm test` (Vitest), `npm run verify` (validate-data · lint · typecheck · coverage — the pre-push gate), `npm run ci` (verify + build).
- **`npm run test:e2e`** (Playwright) needs browsers installed first: `npx playwright install --with-deps chromium`. The e2e config builds and starts the app itself.
- **Pre-push hook** (`.githooks/pre-push`) runs `npm run verify` but is only active after `npm run setup` (sets `core.hooksPath=.githooks`); it is not enabled by default in a fresh clone.
- **Map density is a contract, not a styling choice.** The pin/cluster zoom boundaries, supercluster radius, and the symbol-collision policy that stops labels and pins overlapping (sole exemption: the selected pin's dedicated layer) are the constants at the top of `components/map/canvas/buildScene.ts` (and the layers below them), asserted in `__tests__/mapSymbolCollision.test.ts`. Change them there, and keep every app symbol layer inside MapLibre's collision index.
- **What a community price is allowed to move is a policy, not an implementation detail.** An anonymous submission always shows on the pub's own sheet, dated, but only reaches pins/list rows/cheapest buckets once it is corroborated by a second independent submitter and is inside the max-age window. The constants and predicates are in `lib/communityPrice.ts`, the count is derived (never stored, never client-supplied) on the store's read path, and the price gate is `mergeCommunityPriceSignals` in `components/map/communityPriceSignals.ts`. VISIBILITY is a separate, ungated question from AUTHORITY: a first in-window pint report immediately marks its pin with a provisional badge via `provisionalCommunityPriceVenueIds` (same file, second seam - a set of ids, never a `VenueSignal`), while pin colour, list rows and cheapest buckets still wait for corroboration. Keep the two seams apart: nothing about a pending report may travel through the price merge. Taking a price DOWN is the mirror policy: readers flag (`POST /api/price-submit { action: "report" }`), only a moderator hides (`app/api/admin/community-prices`), reporting never auto-hides (unlike pint drops - an anonymous threshold here would be a one-tap eraser), and hiding never deletes. The one filter lives in `freshestPerCategory`, so a hidden row leaves the sheet, the corroboration count and the map candidate together; `__tests__/communityPriceModeration.test.ts` pins it.
- **An audit waiver is a documented exception, not a mute button.** `npm run verify` ends in `scripts/resilient-audit.mjs`, which fails on high/critical findings, tolerates primary registry outages, and waives only advisories named in its `WAIVED_ADVISORIES` set - each with an inline rationale and a removal condition, and only while a second production-only audit proves the chain is dev-only. Add an entry there only after upgrades and `overrides` are genuinely exhausted; never hide an advisory by raising `--audit-level`, omitting dev dependencies from the primary audit, or skipping the step. `__tests__/resilientAuditWaivers.test.ts` pins the blast radius.
- **Two pub layers, and only one of them is the product.** `venues_slim*.json` is the CURATED index - priced pins, search, filters, crawl routing - and its payload budgets are enforced in `scripts/build_slim_index.mjs`. The UK-wide unpriced OSM pubs are a separate BASE layer streamed per viewport past a zoom gate. Never merge base pubs into the venue index: doing so would impose the country-wide payload on every phone and put unpriced pubs into product systems that require curated venues. `public/data/uk_base/README.md` owns delivery, dedupe, and identity details. Both layers carry OSM-derived venues, so the ODbL credit is attached to the MAP (`OSM_ATTRIBUTION` in `components/map/canvas/tokens.ts`, passed as MapLibre's `customAttribution`) rather than to one optional source - a source-only credit disappears in every city that does not load that source. `__tests__/mapOsmAttribution.test.ts` pins it.
- **The privacy notice is part of the data path, not marketing copy.** `/privacy` and `/terms` (`app/privacy`, `app/terms`, shared `app/legal.css`) describe exactly what the code does: consent-gated analytics, hashed-never-stored IPs, the named processors. Change a data practice and change those pages in the same commit; `__tests__/legalPages.test.ts` pins the honesty claims, the footer links and the sitemap entries. The one public contact address lives in `lib/siteContact.ts` - never hardcode it into a page.
- **Only two price lanes are dated per row.** Community submissions and `public/data/drink_price_updates/*` carry a real per-observation timestamp; the curated venue index's priced rows carry a SOURCE and share one hand-maintained stamp in `data/freshness_registry.json`. Marketing copy may claim provenance for every price and dating only for the people-logged lane - `__tests__/landingPriceHonesty.test.ts` pins the landing page's half of that.
- **Do not commit tooling churn.** `next dev` rewrites `next-env.d.ts`'s route-types import to the dev path (`./.next/dev/types/routes.d.ts`) and `npm install-scripts approve` adds an `allowScripts` block to `package.json`. Both are local artifacts of running the app, not changes: `git checkout --` them before committing.
- **Shared-worktree build gotcha:** a concurrent `next dev` and `next build` can clobber `.next` mid-build and leave `BUILD_ID` missing (the `prestart` guard will refuse to `next start`). For isolated production QA, build/serve with `NEXT_DIST_DIR=.next-prod` so it doesn't collide with a running dev server.
