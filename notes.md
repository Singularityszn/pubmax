## Root cause (confirmed with evidence)

- `readPriceTrustImpact` (lib/priceTrustImpact.server.ts) is the ONLY exported function in the module without a `now` param; it calls `categoryIsTrusted(observations)` with the default `now = Date.now()`.
- `categoryIsTrusted` -> `firstQualifyingCluster` -> `isWithinMaxAge` uses `PRICE_AUTHORITY_MAX_AGE_MS = 30 days` (lib/priceAuthorityWindow.ts, deliberate product behavior: a price stops speaking for tonight past 30 days).
- The test's fixed anchor `NOW = Date.parse("2026-08-16T18:00:00.000Z")`; observations stamped `NOW - 3_000` etc. Every sync call in the test passes this synthetic clock; the read cannot.
- Wall-clock crossed the anchor + 30 days at 2026-09-15T18:00:00Z. CI on main head 47996de ran the unit suite at 2026-09-15T16:00:01Z -> still inside the window -> green. Local runs on 2026-09-16 are past it -> `pricesTrustedNow: 0` -> the four failures. The "Weather cache refresh" failure at 18:11Z on 15 Sep is an unrelated workflow.
- Ruled out:
  - env/Supabase: test mocks `@/lib/supabase` wholly; durable fields (`lifetimeTrustUnlocks`, `observationsLogged`) read fine in the same failing objects; only the wall-clock-dependent field differs. Same failure on two unrelated branches.
  - test ordering/shared state: reproduced single-file in isolation.
  - product regression CI hasn't seen: identical HEAD 47996de green in CI and red locally; only delta is the clock. 30-day decay is intended product behavior.

## Fix plan

Follow the module's own convention (every sibling takes `now: number = Date.now()`):
1. `lib/priceTrustImpact.server.ts`: add `now: number = Date.now()` to `readPriceTrustImpact`, pass it to `categoryIsTrusted`. Production behavior unchanged (default stays wall clock).
2. `__tests__/priceTrustImpact.test.ts`: inject the scenario clock at every `readPriceTrustImpact` call so the file is deterministic. No assertion is changed, deleted, skipped, or loosened.
