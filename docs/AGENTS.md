# Voice, copy and the analytics plan

Rules about what the documentation itself governs: how copy reads, and what a number means.

Repo-wide laws and the index of every other area file are in the root [AGENTS.md](../AGENTS.md).

## Governed documents

- **How copy reads is governed, and the governor is `docs/VOICE.md`.** It owns the banned-word list, the no-em-dash law (`__tests__/emDashLaw.test.ts`), British spelling, the no-exclamation rule, and the named-publisher versus publisher-not-recorded price disclosure. A COPY CLASS is held by a fence, never by a file list, because an inventory of inspected files is a snapshot every new surface lands outside of. So the em-dash law scans `components/**/*.ts` as well as its .tsx files, and the rendered friction fence in `__tests__/frictionVoice.test.ts` checks visible text in five rendered cases: `TonightListingsNotice` error, partial-read and empty states, plus `SocialAccessBoundary` sign-in and unavailable states. `please try again`, `check back later`, `try again later` and `don't miss out` are refused, while the bare imperative `Try again.` stays, because it hands the reader an action rather than a closed door. The em-dash fence reads the AST, so a comment about a banned phrase and a regex that BLOCKS one (`lib/stepOutNudge.ts`, `lib/cheapPintPing.ts`) are not offences. A spaced hyphen holding two CLAUSES apart gets the sentence rewritten; a spaced hyphen in a LABEL is a name plus a qualifier and stays. The sweep and its findings, including the one deferred behavioural finding, are `docs/voice-audit-evidence.md`. Jokes belong in empty states, loading lines, the 404 and a couple of dev-tools easter eggs; never beside a figure, a date, a source, an attribution, a legal term or an accessible name. The bar and the visible-copy versus accessible-name split are `docs/VOICE.md` "Where the jokes live".

- **What a number MEANS is written down once, and the registry is not that place.** `lib/analyticsEvents.ts` owns the closed event names, their props and the sanitiser; `docs/analytics/TRACKING_PLAN.md` owns what each one ANSWERS, the release metric and who acts on which figure, and `docs/analytics/weekly-dashboard.json` is the PostHog dashboard the captain creates once (the Vercel project holds only the write-only ingest token, which cannot create one). THREE facts a query has to start from. (1) TWO TRANSPORTS, ONE CONSENT GATE: named product events go `trackEvent` to `POST /api/events` to `lib/posthogServer.ts`, while `$pageview`, `$web_vitals` and redacted `$exception` go from `posthog-js` through the first-party `/ingest` proxy, so every rate is a rate over CONSENTED visitors and a funnel mixing the two reads `path` on one side and `$pathname` on the other. (2) A NAMED EVENT CARRIES NO `$session_id`, so a session-scoped funnel over product events answers nothing and the window has to be a time window over `distinct_id`; the release metric's HogQL is written that way. (3) EVERY REGISTERED NAME HAS AN EMITTER, AND `__tests__/analyticsEmitterFence.test.ts` IS WHAT SAYS SO. Eighteen did not, listed in the plan's own section 6 as a standing finding, and a tile on any of them read zero for ever while being indistinguishable from a real zero. All eighteen are DELETED (`cmdk_open`, `drop_logged`, `planned_night_status_changed`, `pub_pal_adopted`, `pub_pal_memory_changed`, `planning_handoff_preserved`, `map_search_ran`, `guest_plan_participated`, the five London Capture district names, both `claim_*` steps, and the three open-plan names), and the fence sweeps every name in the registry for a file that also reaches an emitter seam, so a name and its emitter land in the SAME commit. That was already the loop moments' rule; it is now everyone's. The old defence, that the sanitiser must know a shape before the first event arrives, is a promise about a surface that is COMING and is still the right answer for one: register the name in the commit that builds it. It was never the right answer for a surface that was cancelled, never built, or lost its emitter. The fence proves the cheap half, that a name is referenced from a file that can emit; whether a call site fires, and fires once, stays each event's own test's job, and the cheap half is the one that was missing. (4) EVERY EVENT NAMES ITS LANE AND ITS BUILD, and `lib/analyticsAttribution.mjs` is the ONE rule both transports read: `environment` (the closed set `production`, `preview`, `development`, `internal-test`), `release` (the short commit, from `lib/buildInfo.mjs`, so a release can never name a commit `/api/version` would not) and `schema_version`. The browser SDK stamps `$host`, but a named product event is sent from the SERVER and carries none, so every one of them landed in the missing-$host bucket and a preview, a laptop and our own browser suite were indistinguishable from a drinker's night. A product query filters `properties.environment = 'production'`, NEVER `$host`, because a preview host is generated per deployment and names a machine rather than a lane. The lane is decided at BUILD time in `next.config.mjs` (plain ESM with a `.d.mts` sidecar, the `lib/buildInfo.mjs` idiom) because `VERCEL_ENV` reaches no browser bundle, our own suite's `NEXT_PUBLIC_POSTHOG_E2E_ALLOW_BOT` is asked FIRST so a test run can never claim production, and a build nobody named is `development` rather than a guess. `schema_version` is 2 and version 1 is every row written before it: an unattributed row states nothing about where it came from and may not be read as production. WHAT EACH NUMBER MEANS is `docs/analytics/METRICS.md`, which owns the north star (weekly repeating crew nights: an accepted plan, a server-minted `crew_committed` proving a second person, and an explicit `plan_completed`) and every supporting measure with its own denominator; it also owned the ONE gap, that `plan_completed` did not say whether the night had a crew, and that gap is CLOSED by the smallest honest change it named: `crewNight`, one boolean, minted SERVER-side on the completion receipt (`completionLoopEventTokens`) from the roster the store already answered with, signed into the delivery token so a browser that flips it gets an event the ingest route discards, and read off the same `CREW_NIGHT_MIN_PARTICIPANTS` threshold `crew_committed` is minted on, so the two halves of one ratio cannot come to mean different sizes of night. A plan id or any per-plan key was refused for the reason it always is: it would link two devices to one night. It is OPTIONAL in the registry, because a receipt minted before it shipped carries the ending alone and is still a countable completion, so the share is read against the rows that carry the property rather than against every completion ever recorded. A KEPT ACTION is only what the verified delivery lane already wrote down. `venue_sheet_opened` is the ONE sheet-open signal and `components/map/useVenueSheetOpened.ts` is its ONE emitter, shared by `VenueInspector` and `UnverifiedPubSheet`, because `price_submit_viewed` is scoped to pubs on the Overview tab and is a price denominator rather than a sheet-open one. A server-minted `PintDropConfirmation` may never become an event: nobody consenting is behind it. THE FOUR LOOP MOMENTS #252 NAMED NOW EMIT, as six names (`late_food_viewed`, `late_food_added`, `briefing_viewed`, `briefing_opened`, `voice_started`, `recap_viewed`), and they came from `docs/API_CONTRACTS_THE_LOCAL.md` section 8 rather than being invented: section 12.3 resolved that the SHIPPED vocabulary wins where an event already emits, so a #252 name for a moment that never emitted has nothing to be renamed to and stands as written. FIVE rules ride with them. Each is one half of a RATIO and is never read alone, which is why `late_food_viewed` reports an EMPTY shortlist too. Each rides the thing really happening: `late_food_added` off the SAVED ending rather than the tap, `voice_started` off `onConnect` rather than the Start button. `recap_viewed` is the PUBLISHED recap alone, because `/plan/[id]/recap` already reports `memory_reviewed` and two names for one read would double every recap figure. And `lib/briefingArrival.ts` is the ONE place the daily brief's landing marker lives, written by `broadcastDailyBrief` and read by `/today`, because a sender that drifted from the reader would answer zero opens for ever with nothing saying so. All six are browser IMPRESSIONS with no server half, so `components/loop/useLoopMoment.ts` is the one latch and `__tests__/loopMomentEvents.test.ts` sweeps the tree for a second emitter, a server emitter, or a slip onto the plan's no-emitter list. And NONE of the six is a Weekly Meaningful core action: five are impressions, while `late_food_added` rides the ending save that ALSO mints `plan_completed`, so a fold would count one night twice in the roll-up denominator; `WEEKLY_MEANINGFUL_CORE_ACTIONS` is typed `Exclude<AnalyticsEventName, LoopMomentEvent>` so the fold is a compile error, and `LOOP_MOMENT_EVENTS` is where the six are written down once. Pins: `__tests__/analyticsTrackingPlan.test.ts` (which fails the build when the registry grows an event the plan does not name), `__tests__/analyticsEvents.test.ts`, `__tests__/loopMomentEvents.test.ts`, `__tests__/loopMomentHook.test.tsx`.
