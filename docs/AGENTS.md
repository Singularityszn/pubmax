# Voice, copy and the analytics plan

Rules about what the documentation itself governs: how copy reads, and what a number means.

Repo-wide laws and the index of every other area file are in the root [AGENTS.md](../AGENTS.md).

## Governed documents

- **How copy reads is governed, and the governor is `docs/VOICE.md`.** It owns the banned-word list, the no-em-dash law (`__tests__/emDashLaw.test.ts`), British spelling, the no-exclamation rule, and the named-publisher versus publisher-not-recorded price disclosure. A COPY CLASS is held by a fence, never by a file list, because an inventory of inspected files is a snapshot every new surface lands outside of. So the em-dash law scans `components/**/*.ts` as well as its .tsx files, and the rendered friction fence in `__tests__/frictionVoice.test.ts` checks visible text in five rendered cases: `TonightListingsNotice` error, partial-read and empty states, plus `SocialAccessBoundary` sign-in and unavailable states. `please try again`, `check back later`, `try again later` and `don't miss out` are refused, while the bare imperative `Try again.` stays, because it hands the reader an action rather than a closed door. The em-dash fence reads the AST, so a comment about a banned phrase and a regex that BLOCKS one (`lib/stepOutNudge.ts`, `lib/cheapPintPing.ts`) are not offences. A spaced hyphen holding two CLAUSES apart gets the sentence rewritten; a spaced hyphen in a LABEL is a name plus a qualifier and stays. The sweep and its findings, including the one deferred behavioural finding, are `docs/voice-audit-evidence.md`. Jokes belong in empty states, loading lines, the 404 and a couple of dev-tools easter eggs; never beside a figure, a date, a source, an attribution, a legal term or an accessible name. The bar and the visible-copy versus accessible-name split are `docs/VOICE.md` "Where the jokes live".

- **What a number MEANS is written down once, and the registry is not that place.** `lib/analyticsEvents.ts` owns the closed event names, their props and the sanitiser; `docs/analytics/TRACKING_PLAN.md` owns what each one ANSWERS, the release metric and who acts on which figure, and `docs/analytics/weekly-dashboard.json` is the PostHog dashboard the captain creates once (the Vercel project holds only the write-only ingest token, which cannot create one). THREE facts a query has to start from. (1) TWO TRANSPORTS, ONE CONSENT GATE: named product events go `trackEvent` to `POST /api/events` to `lib/posthogServer.ts`, while `$pageview`, `$web_vitals` and redacted `$exception` go from `posthog-js` through the first-party `/ingest` proxy, so every rate is a rate over CONSENTED visitors and a funnel mixing the two reads `path` on one side and `$pathname` on the other. (2) A NAMED EVENT CARRIES NO `$session_id`, so a session-scoped funnel over product events answers nothing and the window has to be a time window over `distinct_id`; the release metric's HogQL is written that way. (3) 18 REGISTERED NAMES HAVE NO EMITTER, listed in the plan's own section 6, and a tile built on one reads zero for ever. (4) EVERY EVENT NAMES ITS LANE AND ITS BUILD, and `lib/analyticsAttribution.mjs` is the ONE rule both transports read: `environment` (the closed set `production`, `preview`, `development`, `internal-test`), `release` (the short commit, from `lib/buildInfo.mjs`, so a release can never name a commit `/api/version` would not) and `schema_version`. The browser SDK stamps `$host`, but a named product event is sent from the SERVER and carries none, so every one of them landed in the missing-$host bucket and a preview, a laptop and our own browser suite were indistinguishable from a drinker's night. A product query filters `properties.environment = 'production'`, NEVER `$host`, because a preview host is generated per deployment and names a machine rather than a lane. The lane is decided at BUILD time in `next.config.mjs` (plain ESM with a `.d.mts` sidecar, the `lib/buildInfo.mjs` idiom) because `VERCEL_ENV` reaches no browser bundle, our own suite's `NEXT_PUBLIC_POSTHOG_E2E_ALLOW_BOT` is asked FIRST so a test run can never claim production, and a build nobody named is `development` rather than a guess. `schema_version` is 2 and version 1 is every row written before it: an unattributed row states nothing about where it came from and may not be read as production. WHAT EACH NUMBER MEANS is `docs/analytics/METRICS.md`. It separates the accepted 28-day group outcome from the next-week device proxy. Migration 0158 snapshots completion-time accounts for a private store aggregate; no Plan or account identity enters analytics. Production test-account exclusions require an explicit reviewed specification. Missing classification, snapshot history, or deleted account identity cannot become a confident zero or rate. A KEPT ACTION is only what the verified delivery lane already wrote down. `venue_sheet_opened` is the ONE sheet-open signal and `components/map/useVenueSheetOpened.ts` is its ONE emitter, shared by `VenueInspector` and `UnverifiedPubSheet`, because `price_submit_viewed` is scoped to pubs on the Overview tab and is a price denominator rather than a sheet-open one. A server-minted `PintDropConfirmation` may never become an event: nobody consenting is behind it. THE FOUR LOOP MOMENTS #252 NAMED NOW EMIT, as six names (`late_food_viewed`, `late_food_added`, `briefing_viewed`, `briefing_opened`, `voice_started`, `recap_viewed`), and they came from `docs/API_CONTRACTS_THE_LOCAL.md` section 8 rather than being invented: section 12.3 resolved that the SHIPPED vocabulary wins where an event already emits, so a #252 name for a moment that never emitted has nothing to be renamed to and stands as written. FIVE rules ride with them. Each is one half of a RATIO and is never read alone, which is why `late_food_viewed` reports an EMPTY shortlist too. Each rides the thing really happening: `late_food_added` off the SAVED ending rather than the tap, `voice_started` off `onConnect` rather than the Start button. `recap_viewed` is the PUBLISHED recap alone, because `/plan/[id]/recap` already reports `memory_reviewed` and two names for one read would double every recap figure. And `lib/briefingArrival.ts` is the ONE place the daily brief's landing marker lives, written by `broadcastDailyBrief` and read by `/today`, because a sender that drifted from the reader would answer zero opens for ever with nothing saying so. All six are browser IMPRESSIONS with no server half, so `components/loop/useLoopMoment.ts` is the one latch and `__tests__/loopMomentEvents.test.ts` sweeps the tree for a second emitter, a server emitter, or a slip onto the plan's no-emitter list. And NONE of the six is a Weekly Meaningful core action: five are impressions, while `late_food_added` rides the ending save that ALSO mints `plan_completed`, so a fold would count one night twice in the roll-up denominator; `WEEKLY_MEANINGFUL_CORE_ACTIONS` is typed `Exclude<AnalyticsEventName, LoopMomentEvent>` so the fold is a compile error, and `LOOP_MOMENT_EVENTS` is where the six are written down once. Pins: `__tests__/analyticsTrackingPlan.test.ts` (which fails the build when the registry grows an event the plan does not name), `__tests__/analyticsEvents.test.ts`, `__tests__/loopMomentEvents.test.ts`, `__tests__/loopMomentHook.test.tsx`.
