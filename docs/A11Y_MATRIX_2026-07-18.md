# Accessibility matrix — Wave-1 mobile shell (#283)

**Date:** 2026-07-18
**Issue:** #283 (Wave 1 — Mobile UI, map, and performance foundation)
**Spec-axis gap closed:** #338 flagged the #283 acceptance line
_"390×844 and 430×932 light/dark/reduced-accessibility matrix"_ as unproven.
This document is the proof, computed and grepped against the actual source, with
small failures fixed in-lane and larger ones filed as findings.

**Acceptance box → tick with this file.** The runtime side of the acceptance
(no flicker / clipping / overlap / overflow across 320/375/390/430 × light/dark,
reduced-motion forced) is exercised by `e2e/mobile-map-shell-matrix.spec.ts`;
this document adds the token-, aria-, and motion-level proof behind it.

## Method

- **Reduced motion:** grepped every `animation:` / `transition:` / `@keyframes`
  in `app` + `components` (55 files) and cross-checked motion neutralisation.
- **Contrast:** computed WCAG 2.x relative-luminance ratios for the #328-era
  token pairs in both themes (script: `scratchpad/contrast.py`). AA = 4.5:1
  body / 3:1 large & UI.
- **Focus / aria / touch:** read the sheet + dialog + tab-bar + map source
  directly (file:line cited under Findings).
- **Toolchain:** `tsc --noEmit` (clean), `eslint` (0 errors), `vitest`
  `venueAccessibility.test.ts` (18/18 green).

### Why each column passes

**Reduced motion — ✅ (verified, not assumed).** A universal catch-all neutralises
all CSS motion: `app/globals.css:4132` →
`@media (prefers-reduced-motion: reduce) { * { animation-duration:.01ms!important; transition-duration:.01ms!important } }`,
mirrored for Legacy Mode (`html[data-legacy="1"] *`, ~`app/globals.css:4671`).
So the 8 animated files with **no** local reduced-motion block
(`barTab.css`, `crawls.css`, `PubMap.tsx`, `logIntentFallback.css`,
`routePanel.css`, `citySwitcher.css`, `MobileSharedSheet.tsx`, `FeedCard.tsx`)
are still covered. No JS animation library exists (no framer-motion / react-spring
in `package.json`); the two JS entrance effects toggle CSS classes
(`FeedCard.tsx:176`, `MobileSharedSheet.tsx:28`) so the reset still applies; and
the WebGL map reads the media query directly in JS to shorten explicit camera
moves and pin entrances (`PubMapCanvas.tsx`, `reducedRef` + `change` listener).
40+ surfaces also
carry their own per-component `prefers-reduced-motion` blocks for state holds.

**Focus management — ✅.** `MobileSharedSheet.tsx`: captures opener
(`:25`), focuses close button on open (`:28`), Esc closes (`:29-32`), restores
focus on close (`:36`), and at the `full` detent traps Tab + sets background
`inert` + `role="dialog"`/`aria-modal` (`:47-76`, `:87-88`). `CommandPalette.tsx`
and `FirstRunTour.tsx` are full modals with trap + Esc + restore
(`CommandPalette.tsx:82-140,159-162`; `FirstRunTour.tsx:152-195,228-238`).

**Touch ≥44px — ✅.** Tab bar holds `min-height:44px` down to the smallest
phone (`components/nav/mobileNav.css:128,303`); venue-sheet tabs / actions /
citation chips all `44px` (`components/map/venueSheet.css:425,814,832,847,
935-936,1175,1194,1201`). Enforced live by `expectTouchTargets()` in
`e2e/mobile-map-shell-matrix.spec.ts` across 4 viewports × 2 themes.

**aria / landmark — ✅ / 🔧.** Tab bar = `<nav aria-label="Primary">` with
`aria-current="page"` on the active link and `aria-hidden` icons
(`MobileTabBar.tsx:98,127,134`). Map region now carries an accessible name
(fix below). Skeletons use `role="status" aria-live` (`VenueSheetSkeleton.tsx:7`,
`PubMap.tsx:1447-1450`).

**Keyboard — ✅ except raw canvas pins.** Map discovery is keyboard-operable via
the tonight lane (real `<button>`/`<Link>` cards — `TonightLane.tsx:105,164,235`)
and the search input (`/` focuses `#mapSearchInput`, labelled
`MapToolbar.tsx:94-99`; Esc clears — `useMapKeyboardShortcuts.ts`). Only
selecting an arbitrary pin is pointer-only (finding).

## Fix applied in this lane

- **Map region now a named landmark.** `components/PubMap.tsx:1439` — the
  full-bleed `<section className="mapStage">` was unnamed, so it was not exposed
  as a region in the a11y tree. Added
  `aria-label={`Interactive pub map of ${city.displayName}`}`. One line, no
  redesign; `tsc` clean, `eslint` 0 new problems.

## Findings (larger — not fixed here)

1. **No keyboard-operable DOM list of venues (map).** Pins are WebGL/canvas only
   (`components/map/canvas/geojson.ts:32`); the only element named "fallback" is
   the WebGL-error retry card (`PubMapCanvas.tsx:1675`, `role="alert"`). A
   keyboard/AT user can reach discovery (tonight lane + search + `/tonight` +
   `/feed`) but cannot enumerate/open an individual pin. WCAG 2.1.1. _Fix:_ a
   visually-hidden or on-screen DOM list of in-viewport venues wired to the same
   select handler. Sizable — own issue.
2. **Desktop venue drawer has no focus trap.** The mobile sheet traps focus; the
   desktop drawer in `PubMap.tsx` (~`:1808-1843`) sets `role="dialog"`/
   `aria-modal` at `full` but never traps Tab or `inert`s the background.
   Desktop-only, so out of the mobile-shell acceptance, but worth a follow-up.
3. **Accent-token contrast as text/CTA.** Cream-on-coral Plan CTA = 2.93:1;
   amber/pint/brick as text on paper = 1.9–2.9:1 (mitigated in practice by
   tinted chip backgrounds and decorative-pin usage). Sub-AA. Token/brand change
   = redesign, out of this lane.
