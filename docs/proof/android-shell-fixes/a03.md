# A03: Profile account menu

Tested on 7 October 2026 with the API 36 Pixel 7 emulator, WebView 133,
and the production web build on localhost:3911. A private local account signed in
through the app's email-link flow. The before build was origin/main `3bc62e232be88dcbfa564ecb01970aba68afa9de`.

| Menu control | Before centre hit | After centre hit |
| --- | --- | --- |
| Your profile | Profile header | Menu link |
| Your Wanteds | Profile identity | Menu link |
| Edit profile | Profile identity | Menu link |
| Switch account | Profile identity | Menu button |
| Sign out | Profile actions | Menu button |

All five controls passed `element.contains(document.elementFromPoint(centre))` after the fix.
A native tap on Sign out removed the account trigger and menu, cleared the session,
and displayed Sign in while staying on the profile route.

The profile's header now owns the shared navigation layer, `--z-nav`.
Its existing account menu paints above the profile content.
The scoped rule preserves the shared modal layer and the existing menu geometry.
Mobile-native, emil-design-eng and apple-design guided the review of layers and touch behaviour.

The browser regression test failed on the centre hit check at 390px and 1440px before the fix.
Both widths passed after the fix, including Sign out.
The test used a production build and the installed Chrome browser because Playwright's bundled Chromium was absent.
The isolated browser configuration remained in ignored validation artifacts.
