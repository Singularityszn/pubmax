# A02: Consume the cold launch once

Tested on 7 October 2026 with the API 36 Pixel 7 emulator, WebView 133,
and a production Next.js build on localhost:3911 through `adb reverse`.
The before build was origin/main `3bc62e232be88dcbfa564ecb01970aba68afa9de`.

| Action | Before URL | After URL |
| --- | --- | --- |
| Force-stop, then VIEW `pubmaxx://map?sel=venue-ca6by4` | `/map?sel=venue-ca6by4` | `/map?sel=venue-ca6by4` |
| DevTools full-document navigation to `/places` | `/map?sel=venue-ca6by4` | `/places` |
| Second warm VIEW `pubmaxx://tonight` | Warm routing already worked | `/tonight` |

The native listener stays active after launch consumption. A sessionStorage marker
survives document reloads within the WebView. It stores only `1`, never the launch URL
or callback credentials. A document guard also handles unavailable storage and
concurrent activation replies.

The unit test reproduced the replay by reloading the module with the same sessionStorage.
It failed before the fix. All 36 native-deep-link tests passed after the fix.
Additional cases cover repeated warm links, new warm links and concurrent activations.
The shared TypeScript fix also applies to the iOS shell. iOS runtime validation is outside this lane.
