# A01: Android document errors

Tested on 7 October 2026 with the API 36 Pixel 7 emulator, WebView 133,
and a production Next.js build served through `adb reverse` on localhost:3911.
The before build was origin/main `3bc62e232be88dcbfa564ecb01970aba68afa9de`.
The private local Supabase and authentication rig followed section 7 of the QA report.
The rig patches were restored after building. The public production site was not contacted.

| Check | Before | After |
| --- | --- | --- |
| GET `/no-such-page`, HTTP 404 | Bundled "No connection" page | Site's "Called for last orders here" 404 |
| First document with the server stopped and no service worker | Bundled offline page | Bundled offline page |
| HTTP 503 at `/places?qa503=1`, then server restored and native tap on Try again | Retryable failure | Opens exactly `/places?qa503=1` |

The 503 came from a temporary localhost HTTP server. It logged the requested URL.
The retry used the restored production server. A native screen tap activated Try again.
The stopped-server check used a fresh WebView after removing its service worker.
An already controlled document's service-worker error path is the separate A07 finding.

The Java regression test rejects 400, 401, 403, 404, 410 and 422 as offline-page triggers.
It accepts main-frame 408, 429 and 5xx responses and rejects subresource triggers.
Existing retry tests continue to protect callback credentials and destination matching.
`npm run android:build` passed, including `testDebugUnitTest`, with JDK 21.
