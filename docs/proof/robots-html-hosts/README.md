# An ordinary HTML page at /robots.txt is an absent rules file

Captain's ruling, 5 September 2026: "Crawl them." 254 UK pub hosts answered
`/robots.txt` on the 4 September crawl with an ordinary HTML page, and the
reader refused every one as `robots-unreadable` because it could not tell a
site page from a challenge page. This change tells them apart.

## The rule

`lib/harvest/robots.ts` classifies what a host SERVED at `/robots.txt`
(`RobotsFileClass`) apart from what it decided:

| Class | Status | Body | Decision |
| --- | --- | --- | --- |
| `rules-file` | 2xx | parses as robots.txt | rules honoured |
| `absent` | 404, 410 | any | no rules published, admitted |
| `html-page` | 2xx | an HTML document root, no challenge signature | no rules published, admitted (RFC 9309 section 2.3.1.3) |
| `challenge-page` | any | carries a `CHALLENGE_PAGE_SIGNATURES` mark or a meta refresh into a challenge | refused |
| `http-refused` | 401, 403, 429, 5xx, other non-2xx | any | refused |
| `not-a-rules-file` | 2xx | neither rules, HTML nor a challenge | refused |
| `unreachable` | no answer, twice | | refused |

Nothing else moved. A 401, 403, 429 or 5xx is refused whatever its body says.
A Disallow rule in a real rules file is honoured as before. The UK price ledger
(`data-harvest/uk_prices/hosts.json`) now carries `robots` on every host row and
`harvest_report.json` counts the classes as `robotsFiles`, so each admission is
auditable per host.

## The measurement

The 4 September ledger kept each host's evidence sentence and not its body, so
the 266 hosts it recorded as `robots-unreadable` on a 200 body ("returned
something that is not a rules file") were asked again, live, on 5 September
2026 through the new reader (`createRobotsChecker()`, one fetch per host).
`remeasure-2026-09-05.csv` is the per-host answer.

| New class | Hosts | Pubs behind them | Decision |
| --- | --- | --- | --- |
| `html-page` | 247 | 527 | admitted |
| `challenge-page` | 11 | 11 | refused |
| `not-a-rules-file` | 7 | 8 | refused |
| `unreachable` | 1 | 1 | refused |

So of the 266 hosts the ledger holds under that sentence (254 of them were
HTML bodies when they were counted on 4 September; sites move between days),
the fixture logic admits 247. Of the 11 refused as a challenge,
8 answered 429 with a Cloudflare "Just a moment" interstitial on the day of the
re-measurement (refused on status alone as well), one is a hijacked domain
serving an hCaptcha, and two carry an hCaptcha widget on an otherwise ordinary
page (`northernmonkbrewco.com`, `thecockinnhanbury.com`); the brief names
hCaptcha as a signature and the refusal side is the safe side, so they stay out.
The 7 `not-a-rules-file` bodies are text that is neither rules nor HTML (a bare
sitemap URL, a "robots.txt generated by" preamble with no colon, an HTML
fragment with no document root) and were refused before this change too.

The largest admitted host is `greatukpubs.co.uk` (240 pubs), an estate site
whose per-pub pages the crawl still holds to the estate rule: a page may only
price a pub it NAMES.

## A signature the measurement corrected

The first cut of `CHALLENGE_PAGE_SIGNATURES` matched the bare prefix
`/cdn-cgi/challenge-platform/`. Cloudflare puts its detection beacon
(`/cdn-cgi/challenge-platform/scripts/jsd/main.js`) on EVERY ordinary page
served behind Bot Fight Mode, so that mark refused 14 pub home pages that had
let us in (`crownciren.com`, `therisleypark.co.uk`, `frontierpubs.co.uk` among
them). The mark is now the interstitial's own orchestrator path,
`/cdn-cgi/challenge-platform/h/`, and `__tests__/harvestRobots.test.ts` pins the
beacon as not a challenge.

## What to run

```
npm run harvest:uk-prices -- --recheck robots-unreadable
```

re-asks the 711 hosts under that finding (the 266 above plus the 403s, 401s
and 5xx, which stay refused) and writes the new `robots` class onto each row.
