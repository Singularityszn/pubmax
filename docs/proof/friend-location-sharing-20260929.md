## Browser plan and proof limits

`node docs/proof/friend-location-local-backend.mjs` starts a disposable PostgreSQL cluster and PostgREST with the full migration chain. Three separate current adult identities are seeded: Alice is mutual with Bob and Carol; only Bob is selected when Alice shares. The loopback GoTrue fixture validates signed tokens. Authentication is a controlled fixture seam; this does not prove OAuth or production authentication.

The production build will use an exact synthetic `*.supabase.co` public origin permitted by the existing CSP. Browser setup will proxy only that synthetic authentication/REST origin to the loopback fixture. The app's friend-location routes and database operations remain real. The ignored fixture manifest and browser auth states must retain mode 0600; tokens must not enter published logs or screenshots.

Required walkthrough: explicit share with actual controlled browser geolocation grant; independent Bob point and marker; independent Carol denial; browser permission denial without coordinate POST; confirmed revoke; hidden/sign-out clearing; stalled-read expiry; 390, 768 and 1440 layouts; and a stable camera while friend markers arrive. Final screenshots and observations will be added only after that walkthrough runs.

Synthetic analytics preparation uses a fake PostHog token and intercepts first-party `/ingest` plus the configured EU collection/assets hosts. Recorder assets come from this lane's installed SDK. The fixture observes rrweb output after its ordinary DOM blocking, observes `$snapshot` attempts before the application's existing sanitizer, and delegates both unchanged. A fixture-only public sampling override selects the consented test session without changing the production 10% setting. Raw captures stay ignored with mode 0600; a local receipt reuses the repository's existing wire decoder and publishes counts only.

The recorder factory hook observes the actual instance passed by the application's consent-lazy `posthog-js` singleton. It never imports or initializes a second PostHog client. Its sanitized probe requires the fake token, first-party `/ingest` host, original 0.1 sample rate, disabled body/header recording and an unchanged before-send callback. Actual collected pageviews must carry that same fake token. The installed recorder's snapshot attempt still calls the original application capture method and sanitizer. Factory observation alone does not prove consent or transport; actual native Allow, started status and intercepted allowed telemetry are required.

Build/start preparation reads the existing E2E environment through `scripts/print-e2e-server-env.ts` into memory without printing values. The overlay pins `NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN=phc_pubmaxx_e2e_public_test` and `NEXT_PUBLIC_POSTHOG_E2E_ALLOW_BOT=1` at build time, overrides ambient public Supabase values with the exact synthetic origin and disposable anonymous key, and uses only the local fixture URL/service key server-side. It retains `DEPLOYMENT_VERSION=local`, `PUBMAX_TRACKED_OUTPUTS=public/data` and `NEXT_DIST_DIR=.next-prod` with the restoration-aware build wrapper. Real-auth E2E mode stays off. Server-only PostHog credentials are blanked; because the server sender also falls back to the public token, an ignored Node fetch preload intercepts its hard-coded EU capture host too. The ordinary browser host interceptor cannot observe server-originated requests. No `.env.local` values or real project tokens are needed or read for this setup. The same captured environment must serve the resulting build.

Required affirmative checks are a started recorder, a real full snapshot containing a public probe while private friend DOM is present, blocked map/control placeholders without descendants, no synthetic private handles or coordinate bodies in producer events, attempted snapshots reaching the sanitizer, and actual allowed pageview collection. The existing sanitizer rejects `$snapshot`, so the expected collection count for snapshots is zero. That zero alone is insufficient evidence. Localhost also suppresses the SDK network recorder by default; the installed SDK options regression proves body/header policy independently. Neither fixture preparation nor a future intercepted run proves production replay or a real PostHog project. This preparation has not run.
