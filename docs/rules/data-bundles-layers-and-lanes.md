## Bundles, layers and lanes

- **Every UK price we hold lives in ONE bundle, and each row says what it is worth.** `public/data/uk_prices/` is built by `npm run build:uk-price-bundle`. Its [README](../../public/data/uk_prices/README.md#the-four-lanes) owns the lane producers and row reference. `lib/ukPriceBundle.ts` is the shape, the parser and the ONE rule that keeps it honest: an estimate is IN the file, because a coverage answer that omits the modelled figures is not a coverage answer, and `authoritativeBundleRows` is what an authority lane reads so pin colour, the cheapest-pint buckets and the Pint Index still cannot take one. The narrower governance table binds at build time too, which is what keeps the 1,914 Nicholson's rows out. FEEDING it are three lanes sharing ONE set of rules (`lib/harvest/ukPriceCrawl.ts`): `npm run harvest:uk-prices` reads what a page SERVES, `npm run harvest:uk-prices-rendered` reads what a page SHOWS through wigolo, `npm run harvest:uk-prices-ocr` reads what a pub PHOTOGRAPHED, and all three follow the price-reading rules in [the harvest guide](../UK_PRICE_HARVEST.md#what-counts-as-a-price). The offer and pub-attribution guards are not theory: the first run wrote a Brewers Fayre "2 for £9" happy hour onto 27 pubs as the price of a pint. `publishes-no-web-price` is a verdict about a DOCUMENT and not about a site, which is why Greene King flipped to allowed on 2026-09-04 when the same permitted URL stated 102 prices to a browser, and why `RENDER_CHECKED_ON` sits apart from `PRICE_CHECKED_ON`. The [source permission rule](scripts-harvest-and-source-permission.md) owns estate refusals across harvest lanes. The venue sheet reads it: `/api/venue/[id]` carries `bundlePrices` on the venue it already fetches (declared in `RUNTIME_DATA_PACKS`), `venueBundlePrices` is the accessor every caller shares, and `venuePriceLane` gained two lanes in ONE order, `listed` above the baseline because it carries its page and its day, and `estimate` below every price anybody observed. The first-drop gate reads the same call, so a lane added there cannot leave the nudge behind. The [base-pub price-read contract](lib-prices-trust-and-drinks.md#base-pub-price-reads) owns listed-pint delivery and read states for a base pin's sheet. A PDF MENU IS A MENU: `lib/harvest/pdfText.ts` reads the text layer through pinned harvest-only `pdfjs-dist` and hands the words to those same rules, a leaf module because `scripts/harvest/uk-prices/run.mjs` ends in `main()`; it never renders, so a scan with no text layer is counted `unreadable` rather than guessed at, and the report tallies PDFs seen, read and unreadable. THOSE SCANS ARE THE OCR LANE'S, AND IT IS A READER RATHER THAN AN AUTHOR: `scripts/harvest/uk-prices/ocr.mjs` visits only the hosts that ledger recorded an unreadable PDF for, asks the text layer FIRST and skips any document that has one, and puts the transcription through the same three calls, which is what stops a figure a model invented becoming a price. Its byte ceiling is deliberately NOT the text reader's 12 MB, because a scan is large for the ordinary reason and every menu it was built for sits above it. The model is olmOCR, a PINNED PYTHON TOOL UNDER `uv` AND NEVER A REPO DEPENDENCY, served locally over any OpenAI-compatible endpoint so no document leaves the machine; the script header owns the install and the reason for each choice. Runbook `docs/UK_PRICE_HARVEST.md`. Pins: `__tests__/ukPriceCrawl.test.ts`, `__tests__/harvestPdfText.test.ts`, `__tests__/ukPriceOcrLane.test.ts`, `__tests__/ukPriceBundle.test.ts`, `__tests__/refusedEstateHosts.test.ts`, `__tests__/priceSourceGovernance.test.ts`, `__tests__/venuePriceLane.test.ts`, `__tests__/venueRoute.test.ts`.

- **Two pub layers, and only one of them is the product.** `venues_slim*.json` is the CURATED index (priced pins, search, filters, crawl routing) with payload budgets enforced in `scripts/build_slim_index.mjs`. The UK-wide unpriced OSM pubs are a separate BASE layer streamed per viewport past a zoom gate. Never merge base pubs into the venue index: that imposes the country-wide payload on every phone and puts unpriced pubs into product systems that require curated venues. `public/data/uk_base/README.md` owns delivery, dedupe and identity. An AREA joins the curated layer by PROMOTION out of that base snapshot rather than a second Overpass observation (`promoteFromUkBase` in `scripts/fetch_city_osm_pubs.mjs`): the curated pack takes the SAME rows, keeps the snapshot's own `fetchedAt`, and `scripts/build_uk_base_shards.mjs` hands each base row to its curated pin by EXACT OSM id, so a new area stops double-pinning without refetching the country and a `venue-uk-*` id keeps its community prices. A promoted pin may SAY name, position and address; its area label is the locality OSM states for that pub, and the pack's name only where OSM states none. [The city-pack contract](../../data/cities/README.md#what-a-pin-says-it-knows) owns permitted fields and unpriced pins, enforced by `validate-data`'s `city_venue_packs` checks. Both layers carry OSM-derived venues, so the ODbL credit is attached to the MAP (`OSM_ATTRIBUTION` in `components/map/canvas/tokens.ts`, passed as MapLibre's `customAttribution`), never to one optional source. The third map is national browse of that base layer (`/map?uk=1`), ADR `docs/adr/0013-uk-national-base-map.md`, never a Google Maps clone and never a multi-city priced splash. ONE NAMED EXCEPTION, the captain's call on 2026-10-17: a subtype view may LIST a London base pub that its own menu prices, read from a bundle row that carries `lat`, `lng` and `londonBorough` (`public/data/uk_prices/README.md`), never an unpriced base pub and never by adding it to the venue index; the Lucia 🐐 lens is the one reader (`lib/drinkSubtypeObservedPrice.ts`). Pins: `__tests__/llandudnoPack.test.ts`, `__tests__/mapOsmAttribution.test.ts`.

- **THE PUBS PEOPLE ARE TALKING ABOUT ARE CURATED, DATED AND CITED.** `public/data/hyped/london.json` is the lane `/tonight` leads with, published by `npm run ingest:hyped-pubs` from the hand-written research file that command's `--in` flag names. `public/data/hyped/README.md` owns what earns a row and what the ingest refuses; `lib/hypedPubs.ts` is the shape and the runtime guards. THREE rules. A row with no dated http source is not a row. `score` and `mentions` order the list and are never printed, because a number on a screen reads as a measurement. And an ambiguous pub name is left UNMATCHED rather than pinned to a guess: the row stays in the pack and says it is not on our map yet, and the page gives it a place only when the pinned rows leave one empty. Pins: `__tests__/hypedPubs.test.ts`, `__tests__/hypedPubsIngest.test.ts`.

- **Editorial overlay freshness has one owner.** Read `public/data/editorial/README.md` for snapshot freshness and stale-versus-degraded contracts; `docs/notes/voice-audit-editorial-stale-line.md` records the composed stale-line ruling. Pins: `__tests__/editorial.test.ts`, `__tests__/editorialPoll.test.ts`, `__tests__/editorialRail.test.ts`.

A refreshed episodic feed reads `fresh` until its age exceeds `SNAPSHOT_AFTER_DAYS`, when it reads `snapshot`. Pins: `__tests__/dataFreshness.test.ts`, `__tests__/freshnessRoute.test.ts`, `__tests__/buildAppDatasetQuarantine.test.ts`, `__tests__/onePriceClock.test.ts`, `__tests__/pintPricesListingIdentity.test.ts`.

- **A LANE NOBODY WRITES IS RETIRED, AND SAYING SO IS THE WHOLE FIX.** Two packs sat in the freshness audit reading `untracked`, which is a sentence about a lane somebody might still refresh, while neither had a producer at all. `public/data/price_updates/` had a hand-run publish whose only parser (`fetchFromSource`) returned `[]` by construction, so every run wrote nothing and the registry still named the command as the lane's refresh workflow; `public/data/food_price_updates/` is a 3 MB served pack no script in this tree has ever written. Both rows now declare `retired: true` and both readers report them `retired`, the fourth freshness finding. THREE rules. (1) SUPPLY IS THE REASON HERE, NOT PERMISSION, and it is measured rather than assumed: the chains that PERMIT automated reading publish no web pint price, and the one that publishes one is refused on permission, so a real parser has nothing permissible to parse and `data/price_sources.json` `sources` is empty rather than holding two `example-*` placeholders a reader could mistake for supply. (2) DELETED RATHER THAN SWITCHED OFF: the hand-run publish, the parser module behind it, the `refresh:prices` package script and the nightly scheduler slot are all gone, because a stub parser is a promise of a parser. (3) THE PACK KEEPS SERVING AND THE FILE KEEPS ITS GUARD: the empty envelope is still read by the Map and the food pack is still read by the venue Menu tab, every row carrying its own `observedAt`, and because retiring a lane retires its refresh and not its artifact, a declared stamp that stops resolving is still an `unknown` breach. Reviving either is a captain SOURCE decision with a producer beside it, never a budget or a cadence change. Pins: `__tests__/freshnessPriceUpdatesProse.test.ts`, `__tests__/priceFreshnessHonesty.test.ts`, `__tests__/freshnessRoute.test.ts`.

- **Price observation dates and the dataset collection stamp are separate.** [The dataset date contract](../../data/README.md) owns their interpretation. [The publisher disclosure contract](../VOICE.md#the-mission-said-plainly) owns attribution and marketing copy.

- **A historical price is history, and history answers nothing about tonight.** `public/data/price_history/london.json` holds dated, sourced prices from years gone by. It is a THIRD price lane, second class by design: it may never enter price bands, pin colour, the pin price label, cheapest-pint buckets, the Pint Index, the freshness registry or any current-price merge. The rule and the row guards are `lib/priceHistory.ts`, and `__tests__/priceHistory.test.ts` checks row identity, current-price isolation and the committed data boundary. `public/data/price_history/README.md` owns what earns a row and identifies the display consumers; curate it, do not generate it.
