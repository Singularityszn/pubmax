<a id="a-menu-url-the-fold-recorded-is-a-crawl-input-and-the-table-is-empty"></a>

- **A MENU URL THE FOLD RECORDED IS A CRAWL INPUT, AND THE TABLE IS EMPTY.** `harvest_venue_overlays.menu_url` was the last source named in the price brief that nothing read. `npm run harvest:uk-menu-urls` (`scripts/harvest/uk-prices/menu-urls.mjs`) is the reader: it ONLY ever reads, it takes its credential from the environment, and both crawl lanes then take its committed answer at `data/uk_prices/overlay_menu_urls.json` through `--menu-urls`. MEASURED 2026-09-04 against production, read only: the table holds 0 rows, because `npm run harvest:fold` has never run against it, so the coverage delta from this source is 0 rows and 0 pubs and the bundle is unmoved at 3,966 rows over 3,163 venues. FOUR rules. (1) PERMISSION IS ASKED TWICE AND NEITHER ASK SUBSTITUTES FOR THE OTHER: `isHarvestableOperatorUrl` drops a refused host before a URL is written down AND again in `crawlableOverlayMenuUrls` on the way out, because the file is committed and can be older than the source policy, and each lane still asks the host's own robots.txt live. (2) A READ WE COULD NOT RUN WRITES NOTHING, on the freshness law's own reasoning: an empty input file meaning "unmeasured" would be read for ever after as a measured empty answer, so no credential and a failed read both refuse and exit non-zero. (3) THE DOCUMENT LANE SEEDS, IT DOES NOT ADD A HOST: a menu URL joins its own host's entry as `seedPages`, read FIRST, so one host still answers once under one ledger row; a URL whose host the snapshot states no pub for is counted, never crawled under an invented host. That reordering is why `crawlHost` now drops the home page from the queue BY VALUE rather than by slicing index 0, which would have discarded the seed. (4) The file names the door it was read through (`readVia`), because a service-role read and a session read are two different claims about who took the answer. THE ALARM is `__tests__/overlayMenuUrlSupply.test.ts`, which fails the day the fold fills the table so the coverage claim is remeasured in the same commit.

<a id="a-url-we-decide-to-fetch-is-somebody-else-s-string-and-the-allow-list-is-asked-a"></a>

- **A URL WE DECIDE TO FETCH IS SOMEBODY ELSE'S STRING, AND THE ALLOW-LIST IS ASKED ABOUT WHERE WE LANDED.** `isHarvestableOperatorUrl` (`lib/harvest/sourcePolicy.ts`) is the predicate in front of every harvested URL, and nobody types those: a menu URL comes from `harvest_venue_overlays.menu_url`, a pub's OSM `website` tag or a link on a page a crawl already read, and the same predicate gates every URL-taking Context.dev call, where a passing URL also spends credit. FOUR CLASSES, and the last is the one a single-URL check cannot see. A REFUSAL IS ABOUT AN OPERATOR, so it matches on a LABEL BOUNDARY: a refused estate host was refused while its own menu SUBDOMAIN was not, which gave every refused estate a way back in that the table still claimed to hold shut; a look-alike domain that merely CONTAINS a refused name is a different operator and is judged on its own permission. A HOST THAT NAMES OUR OWN NETWORK is refused (localhost, loopback, the private ranges, CGNAT 100.64.0.0/10, the benchmarking range 198.18.0.0/15, the reserved range 240.0.0.0/4, the mDNS and internal suffixes and the cloud metadata address), because a harvested string reaching a server-side fetch is otherwise a question asked of our own infrastructure in a pub's name. A HOST IS READ IN ONE SPELLING: lowercase, with a single trailing DNS-root dot stripped, so a refused estate or a loopback written with that dot is the same name; a second trailing dot is refused. The Outer London price lane asks this predicate and a live robots answer before it fetches a page, and it only follows a link whose host is the pub's own. THE FAMILY IS DECIDED FIRST AND AN ADDRESS IS READ AS AN ADDRESS: the first cut tested the hostname as a string, so `[::ffff:169.254.169.254]` (which the WHATWG parser normalises to `[::ffff:a9fe:a9fe]`) was ADMITTED while its v4 spelling was refused, and every pub whose name began `fc` or `fd` was refused as though it were a unique-local address. An IPv6 literal is parsed into its eight hextets, judged by first-hextet RANGE (`fc00::/7`, `fe80::/10`, `fec0::/10`, `::1`, `::`), unwrapped where it EMBEDS a v4 address (mapped, compatible, NAT64 `64:ff9b::/96`, 6to4 `2002::/16`) and refused outright when it cannot be parsed. Neither the URL predicate nor the landing check verifies DNS resolution to a private address. CREDENTIALS in a URL are refused, since they are sent to whatever the URL names. A redirect target must pass permission checks before its request. `fetchFollowingPermittedRedirects` (`lib/harvest/redirectChain.ts`) follows redirects manually, bounded by `HARVEST_REDIRECT_HOP_LIMIT`. Both UK price lanes, `scripts/harvest_chain_menu_prices.mjs` and `scripts/lib/permittedHarvestFetch.mjs` check each resolved `Location` against source policy and robots before requesting it. The chain lane also requires each target to remain within its source row. Its report distinguishes `redirect-left-source`, `redirect-robots-refused`, `redirect-hop-limit` and `redirect-unreadable` drops. The UK price fetch results retain the refusal reason. The shared robots transport uses the same bounded helper, checking `isHarvestableOperatorUrl` before each redirect request. A refused robots redirect, an unreadable `Location` or an exhausted hop limit returns `robots-unreadable` with classification `http-refused`. The checker caches the rules or decision per origin for the run, including refusals. `harvestRedirectLanding` is the ONE owner of the landing rule and still reads the final response as a second fence: both `scripts/harvest/uk-prices/run.mjs` and `scripts/harvest/uk-prices/ocr.mjs` read it, as do `scripts/harvest_chain_menu_prices.mjs`, `scripts/backfill_site_harvest_drink_labels.mjs`, `scripts/refresh_pint_price_observations.mjs` (on the fetch's landed URL) and every Firecrawl scrape in `scripts/harvest/run.mjs` (on the landed URL Firecrawl reports). A SITEMAP IS THE HOST'S STRING TOO: the chain lane puts every `<loc>` back through `isHarvestableChainMenuUrl` and asks robots before it reads the sitemap itself. Pins: `__tests__/harvestUrlAllowList.test.ts`, `__tests__/harvestScriptPermission.test.ts`, `__tests__/harvestRobots.test.ts`.

<a id="a-price-source-is-fenced-like-every-other-source-and-the-narrower-table-binds"></a>

- **A PRICE source is fenced like every other source, and the NARROWER table binds.** Two governance tables answer whether a price page may be read: `data/price_sources.json` (the refresh allowlist) and `lib/harvest/sourceRegistry.ts` (recorded permission). They disagreed in production, the allowlist marking Nicholson's permissible while sourcePolicy refused the Mitchells & Butlers estate on `robots-unreadable`, and 1,914 Nicholson's rows shipped on the refused side. Price sources now live in the source table (`lib/harvest/sourceRegistry.ts`) under a `chain-menu-prices` kind, a source is usable only when it is permissible in the allowlist AND not refused on permission, and `__tests__/priceSourceGovernance.test.ts` fails the build if they drift apart again. PERMISSION AND SUPPLY ARE TWO QUESTIONS: `publishes-no-web-price` is its own skip reason, because a chain that admits us and keeps its prices in an app said YES, and `REFUSED_HOSTS` is therefore derived from `isRefusedOnPermission` rather than from every refusal, or recording a permitted chain as empty would bar its own pub pages from every other lane. Live re-read 2026-09-03: Greene King and Wetherspoon both PERMIT and publish no price in the document, Nicholson's still answers robots with a Cloudflare 403 and stays refused, so the one chain publishing web prices is the one we may not read. `npm run harvest:chain-prices` takes its pages from the table alone (no URL flag), re-asks robots live every run, honours each source's crawl delay under a page budget, keeps a figure only when the shared reader (`lib/harvest/ukPriceCrawl.ts`, mapped through `lib/harvest/chainMenuPrices.ts`) finds it verbatim on the page with a drink word beside it, and writes NOTHING through to the price store. The Tavily enrichment path (`scripts/lib/tavilyPubEnrichment.mjs`) uses the same reader. Both call the judged batch path when `TYPESAFE_API_KEY` is set; the model call stays in `scripts/harvest/uk-prices/readPrices.mjs`. Pins: `__tests__/priceSourceGovernance.test.ts`, `__tests__/chainMenuPrices.test.ts`; findings in `docs/plans/CHAIN_PRICE_HARVEST.md`.

<a id="the-london-harvest-reads-first-party-pages-and-a-skip-is-a-finding"></a>

- **The London harvest reads first-party pages, and a skip is a finding.** [London harvest](../LONDON_HARVEST.md) owns lane coverage and commands. `lib/harvest/sourcePolicy.ts` is the permission fence. The [source ledger](../data/SOURCE_LEDGER.md) owns the input and publication contracts for each lane. PERMISSION, not reachability, is the bar: an unreadable `robots.txt` is a REFUSAL, and a site may admit ordinary crawlers while naming `CloudflareBrowserRenderingCrawler`, the class this harvest belongs to, in a Disallow; the venue lanes follow the curated dataset's own `website`, so `lib/harvest/robots.ts` asks each host live, once per run. THREE FINDINGS hide under that one word and only two are about permission: a body that PARSES as a rules file publishes no restriction however few rules it holds (`looksLikeRulesFile`, so an empty file, a Sitemap-only file and a comments-only file are permission, the same permission a 404 gives), an ORDINARY HTML PAGE served on a 200 where a rules file should be is an ABSENT rules file (captain 2026-09-05, "Crawl them": 254 UK pub hosts route `/robots.txt` to their own site, and RFC 9309 section 2.3.1.3 reads no rules as no restriction), recorded on the host row as `robots: "html-page"` so each admission is auditable, while a CHALLENGE page stays refused at every status, a 200 included, through the closed `CHALLENGE_PAGE_SIGNATURES` table, and a 401, 403, 429 or 5xx is refused whatever its body says; and a host nobody was home at is `robots-unreachable`, asked once more first, because reporting it as a refusal says a pub turned us away when it has no site left. `--recheck <outcome>` re-asks one finding without discarding the ledger. A page that does not STATE a thing yields no row, and the drop is counted; `empty`, `skipped` and `failed` are three outcomes with three names in `lib/harvest/runReport.ts`. `lib/harvest/firecrawl.ts` fails closed without `FIRECRAWL_API_KEY` and caps a run at its own request budget counting RETRIES. `npm run harvest:run` owns the durable output because a Vercel function's file system is read-only. Pub facts ACCUMULATE (merge on `venueId`, freshest wins). The deal file is re-derived whole. The events refresh may also read REGISTERED venue-events pages through Context.dev when `CONTEXT_DEV_API_KEY` is set server-side only: ONE wrapper `lib/contextDev.ts`, lane `lib/events/contextDevProvider.ts` gated on FIRST PARTY rather than a URL suffix, spending ONE `createContextDevBudget()` per run. BOTH are imported by a plain-`node` CLI, so the wrapper carries NO `server-only` marker, nothing in `app/` imports it, and every specifier inside the lane is RELATIVE with its extension. Pins: `__tests__/harvest*.test.ts`, `__tests__/contextDev*.test.ts`, `__tests__/cronHarvestRefreshRoute.test.ts`.

<a id="an-open-data-api-is-a-source-too-and-its-builder-asks-the-table-for-its-url"></a>

- **AN OPEN-DATA API IS A SOURCE TOO, AND ITS BUILDER ASKS THE TABLE FOR ITS URL.** An `open-data` row in `lib/harvest/sourceRegistry.ts` is a public body's or a commons' API that a builder reads into its own committed pack: today `fsa-fhrs-api` (FSA FHRS, Open Government Licence v3.0, `npm run build:fsa-hygiene`), `wikidata-query-service` (CC0 1.0, `npm run build:wikidata-history`) and `historic-england-nhle` (Historic England NHLE, Open Government Licence v3.0, `node scripts/build_heritage_listings.mjs`). Its permission is the publisher's licence and API terms, not robots.txt. It states facts about businesses it does not own, so it is never first party, and its `nonFirstPartyException` says what may be taken. THE TABLE OWNS THE HOST: a builder never types an origin. It calls `openDataSourceUrl(id, path)`, which refuses an unregistered or refused row and any path that resolves to another host or scheme, and it fetches with `redirect: "error"`, so the host it lands on is the host the table named. The FSA and Wikidata rows were registered on the owner's decision of 16 Oct 2026 from an environment whose network refused both hosts; their terms were read live on 17 Oct 2026, on each builder's first networked run. The NHLE row was registered on 17 Oct 2026, when that builder's own hard-coded FeatureServer URL moved into the table; Historic England's own terms page answers automated reads with a Cloudflare challenge, so that row says it was NOT read live and leans on the layer's "Released under OGL" metadata. A row says in its evidence what was read and the day, or what was NOT read live, until a run can read it. Pin: `__tests__/harvestSourcePolicy.test.ts`.

<a id="the-uk-venue-extraction-is-osm-stated-or-it-does-not-exist-save-one-london-resta"></a>

- **The UK venue extraction is OSM-stated or it does not exist, save one London restaurant lane.** `scripts/lib/ukOsmVenueSeed.mjs` is the taxonomy and the only place it is written down; `data/osm/uk/VENUES.md` is the map. THE RULE: a restaurant is not a drinking venue and a fast-food counter is not a night venue, so both are taken only where a tag says otherwise, and nothing is inferred from a name, a chain or a postcode. ONE EXCEPTION, London only: a restaurant OSM names (`amenity=restaurant`, alcohol not stated either way) may join `public/data/london_venues/` as a `restaurant` row when its OWN website states alcohol. The evidence lives in `data/london_restaurant_drinks/evidence.json` (`npm run harvest:london-restaurant-drinks`): a verbatim own-site quote, the URL that stated it, the read time and the robots answer that permitted the read. `npm run build:london-venues` checks every row again with `validateRestaurantDrinksPack` (`scripts/lib/londonRestaurantDrinks.mjs`) and fails rather than ship one that lost any of them. The identity stays OSM's, the row carries no price, band or opening claim, and the exception reaches no other kind and no other place. `amenity=nightclub` and `amenity=music_venue` are a `club`. A restaurant, a `club=*` and a casino are taken when OSM states a bar, a microbrewery, real ale, `alcohol=yes|served`, or an alcoholic `drink:*` key from the OSM wiki list, including when `yes`, `served`, `draught` or `bottled` is one token in a semicolon-separated value. An element the table does not claim is DROPPED AND COUNTED, because a silent drop is how a selector change stops covering a lane with nothing saying so. `npm run fetch:uk-venues` keeps the pub fetcher's contract and asks for the WHOLE taxonomy in ONE request per chunk, because three lanes tripled the requests against public mirrors already answering 504. The shared client is `scripts/lib/overpassClient.mjs`, and its endpoint order is MEASURED, not preferred: primaries take the first four attempts and the degraded pair only sees the tail. The normalized per-group packs are what a reader consumes. `public/data/london_venues/` is the kind-tagged London publish and is deliberately NOT `uk_base`, because that layer's every reader draws a pub, so ids are salted apart (`venue-osm-…`) and the decoder is its own module (`lib/londonVenueShards.ts`). Nothing here is a price source.

<a id="the-nightly-tavily-pass-spends-the-plan-and-writes-listed-evidence-only"></a>

- **The nightly Tavily pass spends the plan and writes Listed evidence only.** `npm run tavily:nightly` (`scripts/tavily-nightly-pass.mjs`, `lib/harvest/tavilyNightlyPass.ts`) reads the account usage and spends tonight's allowance. The figure is stated in `docs/TAVILY_NIGHTLY_PASS.md`. Pay as you go headroom is ignored. `--max-credits` can only lower that allowance. The cursor and the curation queue stay in the gitignored nightly directory beside the other Tavily checkpoints. Every drink line is standing listed. The queue refuses a confirmed standing and refuses `cheapestPrice`. The pass does not write community prices, `public/data/drink_price_updates`, or `public/data/uk_prices`. The shared reader in `lib/harvest/ukPriceCrawl.ts` is asked first. A half or a bottle it refuses as not a pint stays eligible, and so does a stated serving it drops for want of a category word. A pint, a keg and a bottle stay different sizes, a 125ml, 175ml or 250ml glass stays unstated, and a vague line is not a price. A drink line is kept only when the same line states a pound price and a serving size, and only on a drinks menu page, a drinks title, a drinks heading, or the page that bound the site. A food menu page or section, a served flag, a closure, hours, an amenity, a phone number and a dish are the source URL and a short verbatim excerpt, and a later read keeps an earlier excerpt it does not restate. The page that bound the site is read with the menu pages. A site is bound only when a result states this venue's postcode or its exact street address; otherwise the venue stays unbound, the candidate URLs are kept for a curator, and no extract credit is spent. Two pubs with one name stay apart by postcode. An extract URL still has to pass `isHarvestableOperatorUrl`. The run command and both schedule options are in `docs/TAVILY_NIGHTLY_PASS.md`. This tree does not add the workflow. Pin: `__tests__/tavilyNightlyPass.test.ts`.

<a id="a-pub-s-own-food-menu-is-read-like-its-drinks-list-and-only-its-price-fact-ships"></a>

- **A PUB'S OWN FOOD MENU IS READ LIKE ITS DRINKS LIST, AND ONLY ITS PRICE FACT SHIPS.** `npm run harvest:uk-food` (`scripts/harvest/uk-food/run.mjs`, crawl in `scripts/harvest/uk-food/lane.mjs`, reader `lib/harvest/ukFoodCrawl.ts`) is the producer that revives `public/data/food_price_updates/`, on the owner's decision of 17 Oct 2026 (London pubs first, dishes and prices only). It reads curated London venues' own menu URLs (`public/data/venue_menu_enrichment.json`, keyed by the curated venue id) and London OSM pubs that state their own website (`venue-uk-*`), and a host a curated venue owns is left to the curated lane. PERMISSION IS ASKED THREE TIMES, exactly as the price lanes ask it: `isHarvestableOperatorUrl` before a request, the host's robots.txt live about every PATH, and `harvestRedirectLanding` about the page we landed on, served or rendered. A PAGE IS READ SERVED FIRST and rendered through Browserbase (`BROWSERBASE_API_KEY`, `scripts/lib/localRefreshProviders.mjs`) only when the served document answered and states no menu, under its own `--renders` cap beside the `--pages` budget; without the key the run says rendering was not configured. A BROWSER IS NOT A WAY PAST A SHUT DOOR: a page the site refused (401, 403, 407, 429, 451) or answered with a bot challenge (`looksLikeChallengePage`) is recorded `refused-by-site` or `blocked-by-challenge` and is never rendered, in any `--render` mode. THE READER KEEPS A DISH ONLY WHEN THE PAGE STATES ITS NAME AND ONE £ FIGURE TOGETHER, under a food heading or beside a plate word: offers, add-ons, set and per-head figures, two-figure lines, drinks headings and drink-named lines are each a named drop; a dish with no heading is `other`, never guessed into `mains`; and a page stating fewer than `MIN_DISHES_FOR_MENU` (4) dishes yields nothing. On an estate host a page speaks only for the pub its path names (`pageMayPriceThisPub`). THE HARVEST ROW KEEPS THE MENU'S OWN WORDS AS EVIDENCE AND THE PACK DOES NOT: `npm run build:food-price-updates` publishes the price fact, its page, its observedAt and the first-party licence, replaces every older row of a pub it re-read, derives `generatedAt` from the newest row, and refuses to write when nothing harvested passes `lib/foodPriceUpdates.ts`. The registry keeps the lane `retired` until the first reviewed publish lands, because a producer that has not yet run has refreshed nothing. Runbook `docs/UK_FOOD_HARVEST.md`. Pins: `__tests__/ukFoodCrawl.test.ts`, `__tests__/ukFoodHarvestLane.test.ts`, `__tests__/foodPriceUpdatesBuild.test.ts`.

<a id="an-exa-website-is-read-for-a-price-only-when-its-own-page-states-the-pub-s-address"></a>

- **AN EXA WEBSITE IS READ FOR A PRICE ONLY WHEN ITS OWN PAGE STATES THE PUB'S ADDRESS.** `npm run harvest:uk-pubs -- --london --enrich` runs the Exa lane on the Greater London subset of the pub seed, into its own london-enriched folder under the gitignored `data-harvest/`, with its own progress, so the all-UK resume offset never moves. `npm run harvest:uk-exa-sites` (`scripts/harvest/uk-prices/exa-sites.mjs`, rules in `scripts/harvest/uk-prices/exaSites.mjs`) cuts the committed input exa_site_candidates.json under `data/uk_prices/` from those local shards through `overlayRowsFromHarvestRecords`, the same derivation `npm run harvest:fold` writes, so the input and the overlay table can never name different websites. It reads and writes no production data. An observation the fold refuses (an http page, a social host) is dropped and counted under `observationsRefusedByFold`, because the fold fails a whole run on one, which is right for a production write and wrong for a crawl input. FOUR RULES. (1) A NAMESAKE IS NOT THE PUB: in the first pilot Exa answered the Joiners Arms in Morpeth for a Joiners Arms in Oxfordshire, so a candidate needs OSM tags that state a full postcode or a house number with its street (a street alone is refused, half the country has a High Street pub), and the crawl keeps a price from a host only Exa named only when a page of that host states the same postcode or street address. The home page is asked first, then up to two same-origin contact pages behind the live robots ask, then every page the crawl reads. A full postcode may be read inside page data or an attribute; a street address only in the page's words. A host that never binds is `exa-site-unbound` and writes nothing. (2) ONE NEW HOST, ONE PUB: a new host two pubs' searches landed on is counted as `sharedHost` and never crawled from this input, and a source-table estate host is counted as `estateHost`. (3) An aggregator, directory or social host (`NOT_A_PUBS_OWN_SITE`) is never a pub's own site, and `isHarvestableOperatorUrl` is asked when the input is cut AND again when the crawl reads it. (4) The input is OFF unless named: `npm run harvest:uk-prices -- --london --exa-sites <that file> --exa-sites-only` crawls only the new hosts it adds, and a host already in `data/uk_prices/site_harvest.jsonl` is never added again. Such a run writes `data/uk_prices/exa_sites_report.json` and never replaces the national `data/uk_prices/harvest_report.json`. A fresh checkout's crawl ledger starts from the published rows, because the bundle rewrites `data/uk_prices/site_harvest.jsonl` from the ledger and an empty ledger would publish one run alone. A candidate on a host the snapshot already states seeds that host's menu page on a full run. Pin: `__tests__/exaSiteBinding.test.ts`.

<a id="a-menu-is-the-pub-s-whose-website-it-is-and-a-shared-name-is-not-a-match"></a>

- **A MENU IS THE PUB'S WHOSE WEBSITE IT IS, AND A SHARED NAME IS NOT A MATCH.** A chain menu page belongs to the pub that states it as its own website, in the OSM `website` tag or the Google Places `websiteUri`, placed by that pub's OSM point (`scripts/lib/menuPageOwners.mjs`). When that owner stands more than `MENU_OWNER_MAX_METRES` (150 m) from the pub a harvester matched, the row is another pub's menu and is refused, however well the names agree. The Greene King harvester (`scripts/firecrawl_greene_king_prices.mjs`) asks before it fetches and again of the page a live or cached fetch landed on, because a redirect can carry the request to another pub's menu on the same host, drops a published row that fails on `--merge`, and resolves a shared name only to the one pub the owner stands beside, never to the first. This is not theory: the first harvest put 415 rows on 9 wrong pubs, among them the St James's Golden Lion's menu on the Dean Street Golden Lion and a Westminster menu on a Bexleyheath pub 20 km away. `npm run prices:drop-wrong-pub` removes such rows from `public/data/drink_price_updates/latest.json` and fetches nothing; a page no pub states is `owner-unknown` and is left to the name rules. Pins: `__tests__/menuPageOwners.test.ts`, `__tests__/greeneKingResolvedMenuUrl.test.ts`, `__tests__/reviewedDrinkSourceImport.test.ts`.

<a id="a-page-that-names-another-branch-is-not-this-pub-s-price-even-on-a-one-pub-host"></a>

- **A PAGE THAT NAMES ANOTHER BRANCH IS NOT THIS PUB'S PRICE, EVEN ON A ONE-PUB HOST.** The snapshot states a website only for the pubs OSM tagged with one, so a chain whose other branches carry no tag looks like one pub's own site, and the crawl gave that pub every page on the host (`pubsOnHost: 1`). Found on 1 Nov 2026 while building the cheapest pint hunt: The Botanist Gas Street Basin (Birmingham) carried £4.95 read off the chain's Barnsley page (`https://thebotanist.uk.com/locations/barnsley/whats-on`), and Simmons in Camden carried three prices read off the Shoreditch page (`https://www.simmonsbar.co.uk/venues/shoreditch-cocktail-bar/`). `pageNamesAnotherBranch` in `lib/harvest/ukPriceCrawl.ts` owns the rule. A path segment after a branch word (`locations`, `venues`, `pubs` and kin) names a branch; a singular `bar` or `restaurant` is a pub site's own section, not a branch. The page is this pub's only when one of those segments shares a word with the pub's name, locality, address or own stated website path, or spells its whole name ("court-house" is The Courthouse). Menu, page, pub and street words name no branch, so a path the rule cannot read keeps today's answer. `pageMayPriceThisPub` asks it before the pub count, so the document, OCR and food lanes refuse such a page, and the rendered lane does not open such a link. `npm run build:uk-price-bundle` asks it of every site-harvest ledger row, with the row's own pub name, the snapshot's current name and the snapshot's locality, address and website, drops the row only when the page names none of them and counts it in the manifest notes. The ledger keeps the row as the crawl wrote it, because the reconciliation fingerprints cover it. LIMIT: a page that names the pub's own city beside another branch's name (a path such as /venues/london-shoreditch/ for a London pub) still passes. Pins: `__tests__/ukPriceBundleBranchAttribution.test.ts`, `__tests__/ukPriceCrawl.test.ts`.
