# Harvest and source permission

Moved from [`scripts/AGENTS.md`](../../scripts/AGENTS.md). Authoritative policy detail lives here; the area index stays short.

<a id="the-all-uk-pub-harvest-enumerates-osm-then-enriches-via-exa"></a>

- **The all-UK pub harvest enumerates OSM then enriches via Exa.** `docs/UK_PUB_HARVEST.md` is the map: `npm run harvest:uk-pubs` (`scripts/harvest/uk-pubs/run.mjs`) enumerates, `npm run harvest:fold` (`scripts/harvest/uk-pubs/fold.mjs`) upserts into `harvest_venue_overlays` (migration `0123`). Identity is OSM id, never the pub name. Lore is HeritageFact source `web`, name and town gated, citations required, lazy sheet only (`/api/harvest-overlay`, `/api/heritage`), never pin or slim; socials are refused; fold-stats mismatches fail loud. London first-party harvest stays at `npm run harvest:run`. Observations only: every stored fact carries `sourceUrl` and `fetchedAt`. Shards live under gitignored `data-harvest/`; the committed sample is `data-harvest/uk_pubs_seed.sample.jsonl`. Pins: `__tests__/ukPubHarvest.test.ts`, `__tests__/harvestFold.test.ts`, `__tests__/harvestOverlay*.test.ts`.

<a id="a-menu-url-the-fold-recorded-is-a-crawl-input-and-the-table-is-empty"></a>

- **A MENU URL THE FOLD RECORDED IS A CRAWL INPUT, AND THE TABLE IS EMPTY.** `harvest_venue_overlays.menu_url` was the last source named in the price brief that nothing read. `npm run harvest:uk-menu-urls` (`scripts/harvest/uk-prices/menu-urls.mjs`) is the reader: it ONLY ever reads, it takes its credential from the environment, and both crawl lanes then take its committed answer at `data/uk_prices/overlay_menu_urls.json` through `--menu-urls`. MEASURED 2026-09-04 against production, read only: the table holds 0 rows, because `npm run harvest:fold` has never run against it, so the coverage delta from this source is 0 rows and 0 pubs and the bundle is unmoved at 3,966 rows over 3,163 venues. FOUR rules. (1) PERMISSION IS ASKED TWICE AND NEITHER ASK SUBSTITUTES FOR THE OTHER: `isHarvestableOperatorUrl` drops a refused host before a URL is written down AND again in `crawlableOverlayMenuUrls` on the way out, because the file is committed and can be older than the source policy, and each lane still asks the host's own robots.txt live. (2) A READ WE COULD NOT RUN WRITES NOTHING, on the freshness law's own reasoning: an empty input file meaning "unmeasured" would be read for ever after as a measured empty answer, so no credential and a failed read both refuse and exit non-zero. (3) THE DOCUMENT LANE SEEDS, IT DOES NOT ADD A HOST: a menu URL joins its own host's entry as `seedPages`, read FIRST, so one host still answers once under one ledger row; a URL whose host the snapshot states no pub for is counted, never crawled under an invented host. That reordering is why `crawlHost` now drops the home page from the queue BY VALUE rather than by slicing index 0, which would have discarded the seed. (4) The file names the door it was read through (`readVia`), because a service-role read and a session read are two different claims about who took the answer. THE ALARM is `__tests__/overlayMenuUrlSupply.test.ts`, which fails the day the fold fills the table so the coverage claim is remeasured in the same commit.

<a id="a-url-we-decide-to-fetch-is-somebody-else-s-string-and-the-allow-list-is-asked-a"></a>

- **A URL WE DECIDE TO FETCH IS SOMEBODY ELSE'S STRING, AND THE ALLOW-LIST IS ASKED ABOUT WHERE WE LANDED.** `isHarvestableOperatorUrl` (`lib/harvest/sourcePolicy.ts`) is the predicate in front of every harvested URL, and nobody types those: a menu URL comes from `harvest_venue_overlays.menu_url`, a pub's OSM `website` tag or a link on a page a crawl already read, and the same predicate gates every URL-taking Context.dev call, where a passing URL also spends credit. FOUR CLASSES, and the last is the one a single-URL check cannot see. A REFUSAL IS ABOUT AN OPERATOR, so it matches on a LABEL BOUNDARY: a refused estate host was refused while its own menu SUBDOMAIN was not, which gave every refused estate a way back in that the table still claimed to hold shut; a look-alike domain that merely CONTAINS a refused name is a different operator and is judged on its own permission. A HOST THAT NAMES OUR OWN NETWORK is refused (localhost, loopback, the private ranges, CGNAT 100.64.0.0/10, the benchmarking range 198.18.0.0/15, the reserved range 240.0.0.0/4, the mDNS and internal suffixes and the cloud metadata address), because a harvested string reaching a server-side fetch is otherwise a question asked of our own infrastructure in a pub's name. A HOST IS READ IN ONE SPELLING: lowercase, with a single trailing DNS-root dot stripped, so a refused estate or a loopback written with that dot is the same name; a second trailing dot is refused. The Outer London price lane asks this predicate and a live robots answer before it fetches a page, and it only follows a link whose host is the pub's own. THE FAMILY IS DECIDED FIRST AND AN ADDRESS IS READ AS AN ADDRESS: the first cut tested the hostname as a string, so `[::ffff:169.254.169.254]` (which the WHATWG parser normalises to `[::ffff:a9fe:a9fe]`) was ADMITTED while its v4 spelling was refused, and every pub whose name began `fc` or `fd` was refused as though it were a unique-local address. An IPv6 literal is parsed into its eight hextets, judged by first-hextet RANGE (`fc00::/7`, `fe80::/10`, `fec0::/10`, `::1`, `::`), unwrapped where it EMBEDS a v4 address (mapped, compatible, NAT64 `64:ff9b::/96`, 6to4 `2002::/16`) and refused outright when it cannot be parsed. A DNS name that RESOLVES to a private address is not covered by a pre-resolution check, and `harvestRedirectLanding` re-asking the predicate about the landed page is the control that is. CREDENTIALS in a URL are refused, since they are sent to whatever the URL names. And A REDIRECT CHAIN IS RE-ASKED: both price lanes fetch with `redirect: "follow"`, so the HOST picks the last hop; both computed a `finalUrl` and handed it to NOTHING, so a permitted site that 30x-ed to a refused one was read in full and the row was then stamped with the asked-for URL, naming a page that never stated the price. `harvestRedirectLanding` is the ONE owner of that rule and both `scripts/harvest/uk-prices/run.mjs` and `scripts/harvest/uk-prices/ocr.mjs` read it. Pin: `__tests__/harvestUrlAllowList.test.ts`.

<a id="a-price-source-is-fenced-like-every-other-source-and-the-narrower-table-binds"></a>

- **A PRICE source is fenced like every other source, and the NARROWER table binds.** Two governance tables answer whether a price page may be read: `data/price_sources.json` (the refresh allowlist) and `lib/harvest/sourcePolicy.ts` (permission). They disagreed in production, the allowlist marking Nicholson's permissible while sourcePolicy refused the Mitchells & Butlers estate on `robots-unreadable`, and 1,914 Nicholson's rows shipped on the refused side. Price sources now live in sourcePolicy under a `chain-menu-prices` kind, a source is usable only when it is permissible in the allowlist AND not refused on permission, and `__tests__/priceSourceGovernance.test.ts` fails the build if they drift apart again. PERMISSION AND SUPPLY ARE TWO QUESTIONS: `publishes-no-web-price` is its own skip reason, because a chain that admits us and keeps its prices in an app said YES, and `REFUSED_HOSTS` is therefore derived from `isRefusedOnPermission` rather than from every refusal, or recording a permitted chain as empty would bar its own pub pages from every other lane. Live re-read 2026-09-03: Greene King and Wetherspoon both PERMIT and publish no price in the document, Nicholson's still answers robots with a Cloudflare 403 and stays refused, so the one chain publishing web prices is the one we may not read. `npm run harvest:chain-prices` takes its pages from the table alone (no URL flag), re-asks robots live every run, honours each source's crawl delay under a page budget, keeps a figure only when the shared reader (`lib/harvest/ukPriceCrawl.ts`, mapped through `lib/harvest/chainMenuPrices.ts`) finds it verbatim on the page with a drink word beside it, and writes NOTHING through to the price store. The Tavily enrichment path (`scripts/lib/tavilyPubEnrichment.mjs`) uses the same reader. Both call the judged batch path when `TYPESAFE_API_KEY` is set; the model call stays in `scripts/harvest/uk-prices/readPrices.mjs`. Pins: `__tests__/priceSourceGovernance.test.ts`, `__tests__/chainMenuPrices.test.ts`; findings in `docs/plans/CHAIN_PRICE_HARVEST.md`.

<a id="the-london-harvest-reads-first-party-pages-and-a-skip-is-a-finding"></a>

- **The London harvest reads first-party pages, and a skip is a finding.** `docs/LONDON_HARVEST.md` is the map. `lib/harvest/sourcePolicy.ts` is the fence: nothing takes a URL from a caller, so a source absent from that table is not harvested at all. PERMISSION, not reachability, is the bar: an unreadable `robots.txt` is a REFUSAL, and a site may admit ordinary crawlers while naming `CloudflareBrowserRenderingCrawler`, the class this harvest belongs to, in a Disallow; the venue lanes follow the curated dataset's own `website`, so `lib/harvest/robots.ts` asks each host live, once per run. THREE FINDINGS hide under that one word and only two are about permission: a body that PARSES as a rules file publishes no restriction however few rules it holds (`looksLikeRulesFile`, so an empty file, a Sitemap-only file and a comments-only file are permission, the same permission a 404 gives), an ORDINARY HTML PAGE served on a 200 where a rules file should be is an ABSENT rules file (captain 2026-09-05, "Crawl them": 254 UK pub hosts route `/robots.txt` to their own site, and RFC 9309 section 2.3.1.3 reads no rules as no restriction), recorded on the host row as `robots: "html-page"` so each admission is auditable, while a CHALLENGE page stays refused at every status, a 200 included, through the closed `CHALLENGE_PAGE_SIGNATURES` table, and a 401, 403, 429 or 5xx is refused whatever its body says; and a host nobody was home at is `robots-unreachable`, asked once more first, because reporting it as a refusal says a pub turned us away when it has no site left. `--recheck <outcome>` re-asks one finding without discarding the ledger. A page that does not STATE a thing yields no row, and the drop is counted; `empty`, `skipped` and `failed` are three outcomes with three names in `lib/harvest/runReport.ts`. `lib/harvest/firecrawl.ts` fails closed without `FIRECRAWL_API_KEY` and caps a run at its own request budget counting RETRIES. `npm run harvest:run` owns the durable output because a Vercel function's file system is read-only; `/api/cron/harvest-refresh` runs the same fetchers weekly. Pub facts ACCUMULATE (merge on `venueId`, freshest wins); the deal and event files are re-derived whole. The events refresh may also read REGISTERED venue-events pages through Context.dev when `CONTEXT_DEV_API_KEY` is set server-side only: ONE wrapper `lib/contextDev.ts`, lane `lib/events/contextDevProvider.ts` gated on FIRST PARTY rather than a URL suffix, spending ONE `createContextDevBudget()` per run. BOTH are imported by a plain-`node` CLI, so the wrapper carries NO `server-only` marker, nothing in `app/` imports it, and every specifier inside the lane is RELATIVE with its extension. Pins: `__tests__/harvest*.test.ts`, `__tests__/contextDev*.test.ts`, `__tests__/cronHarvestRefreshRoute.test.ts`.

<a id="the-wetherspoon-directory-is-the-pubs-the-chain-runs-today-and-it-is-never-edite"></a>

- **THE WETHERSPOON DIRECTORY IS THE PUBS THE CHAIN RUNS TODAY, AND IT IS NEVER EDITED BY HAND.** `npm run fetch:wetherspoons-pubs` (`scripts/fetch_wetherspoons_pubs.mjs`) is keyless: it takes its endpoint and its 10 s delay from the `wetherspoon-pub-directory` row (`pub-directory` kind) in `lib/harvest/sourcePolicy.ts`, asks robots live, and refuses a read that disagrees with the endpoint's `x-wp-total` or holds under 90 per cent of the committed file. A pub the chain SELLS leaves the directory while its `pub-histories` page stays, so a pub reported "missing" is checked against that sitemap before anything else: The Millers Well (E6 2JX) and The Coronet (N7 6PA) were sold in 2023, and a price the index still holds for either is a price question, not a directory one. The script also owns the entity decode (WP renders titles as HTML) and the William Chambers coordinate correction. Pins: `__tests__/wetherspoonsDirectory.test.ts`, `__tests__/wetherspoonsDirectoryLondonJoin.test.ts`, `__tests__/harvestSourcePolicy.test.ts`.

<a id="the-uk-venue-extraction-is-osm-stated-or-it-does-not-exist-save-one-london-resta"></a>

- **The UK venue extraction is OSM-stated or it does not exist, save one London restaurant lane.** `scripts/lib/ukOsmVenueSeed.mjs` is the taxonomy and the only place it is written down; `data/osm/uk/VENUES.md` is the map. THE RULE: a restaurant is not a drinking venue and a fast-food counter is not a night venue, so both are taken only where a tag says otherwise, and nothing is inferred from a name, a chain or a postcode. ONE EXCEPTION, London only: a restaurant OSM names (`amenity=restaurant`, alcohol not stated either way) may join `public/data/london_venues/` as a `restaurant` row when its OWN website states alcohol. The evidence lives in `data/london_restaurant_drinks/evidence.json` (`npm run harvest:london-restaurant-drinks`): a verbatim own-site quote, the URL that stated it, the read time and the robots answer that permitted the read. `npm run build:london-venues` checks every row again with `validateRestaurantDrinksPack` (`scripts/lib/londonRestaurantDrinks.mjs`) and fails rather than ship one that lost any of them. The identity stays OSM's, the row carries no price, band or opening claim, and the exception reaches no other kind and no other place. `amenity=nightclub` and `amenity=music_venue` are a `club`. A restaurant, a `club=*` and a casino are taken when OSM states a bar, a microbrewery, real ale, `alcohol=yes|served`, or an alcoholic `drink:*` key from the OSM wiki list, including when `yes`, `served`, `draught` or `bottled` is one token in a semicolon-separated value. An element the table does not claim is DROPPED AND COUNTED, because a silent drop is how a selector change stops covering a lane with nothing saying so. `npm run fetch:uk-venues` keeps the pub fetcher's contract and asks for the WHOLE taxonomy in ONE request per chunk, because three lanes tripled the requests against public mirrors already answering 504. The shared client is `scripts/lib/overpassClient.mjs`, and its endpoint order is MEASURED, not preferred: primaries take the first four attempts and the degraded pair only sees the tail. The normalized per-group packs are what a reader consumes. `public/data/london_venues/` is the kind-tagged London publish and is deliberately NOT `uk_base`, because that layer's every reader draws a pub, so ids are salted apart (`venue-osm-…`) and the decoder is its own module (`lib/londonVenueShards.ts`). Nothing here is a price source.

<a id="the-nightly-tavily-pass-spends-the-plan-and-writes-listed-evidence-only"></a>

- **The nightly Tavily pass spends the plan and writes Listed evidence only.** `npm run tavily:nightly` (`scripts/tavily-nightly-pass.mjs`, `lib/harvest/tavilyNightlyPass.ts`) reads the account usage and spends tonight's allowance. The figure is stated in `docs/TAVILY_NIGHTLY_PASS.md`. Pay as you go headroom is ignored. `--max-credits` can only lower that allowance. The cursor and the curation queue stay in the gitignored nightly directory beside the other Tavily checkpoints. Every drink line is standing listed. The queue refuses a confirmed standing and refuses `cheapestPrice`. The pass does not write community prices, `public/data/drink_price_updates`, or `public/data/uk_prices`. The shared reader in `lib/harvest/ukPriceCrawl.ts` is asked first. A half or a bottle it refuses as not a pint stays eligible, and so does a stated serving it drops for want of a category word. A pint, a keg and a bottle stay different sizes, a 125ml, 175ml or 250ml glass stays unstated, and a vague line is not a price. A drink line is kept only when the same line states a pound price and a serving size, and only on a drinks menu page, a drinks title, a drinks heading, or the page that bound the site. A food menu page or section, a served flag, a closure, hours, an amenity, a phone number and a dish are the source URL and a short verbatim excerpt, and a later read keeps an earlier excerpt it does not restate. The page that bound the site is read with the menu pages. A site is bound only when a result states this venue's postcode or its exact street address; otherwise the venue stays unbound, the candidate URLs are kept for a curator, and no extract credit is spent. Two pubs with one name stay apart by postcode. An extract URL still has to pass `isHarvestableOperatorUrl`. The run command and both schedule options are in `docs/TAVILY_NIGHTLY_PASS.md`. This tree does not add the workflow. Pin: `__tests__/tavilyNightlyPass.test.ts`.

<a id="the-london-tavily-pass-and-the-london-promotion-are-capped-in-code"></a>

- **The London Tavily pass and the London promotion are capped in code, and every row keeps its evidence.** `npm run enrich:city -- --city=london` (`.github/workflows/tavily-london-nightly.yml`) refuses more than 200 searches and 400 credits per run in `scripts/lib/tavilyPubEnrichment.mjs`, and no flag raises either figure. A full night is $3.20, stated in `docs/TAVILY_LONDON_NIGHTLY.md`. The workflow opens a review PR and never pushes to the default branch. The committed prices are the source of truth: a night never overwrites a committed row with an older checkpoint row, never re-adds a row a reviewer removed from a merged nightly PR (a committed run report marks its night merged), never writes a page listed in `data/enrichment/tavily/london/rejected.json` (`npm run tavily:reject`), and never overwrites a price listed in `data/enrichment/tavily/london/corrected.json` (`npm run tavily:correct`). `npm run promote:london-osm` (`scripts/promote_london_osm_pubs.mjs`) promotes at most `PROMOTION_BATCH_CAP` (300) OSM pubs into the London dataset as UNPRICED rows. A pub is eligible only when it states its own website, no curated venue owns it and no chain harvester owns it. Each promotion is written to `data/london_osm_promotion/ledger.json` with its OSM id, website and read time, and `scripts/build_uk_base_shards.mjs` owns it by that OSM id so the base layer stops drawing it twice. The wine and cocktail estimate basis in `public/data/price_estimates/baselines.json` (`drinks`) is London borough medians over pubs, each with its pages, sample, operator count and serving band, and never a chain or postcode basis. A borough row needs at least three distinct operators (`MIN_ESTIMATE_OPERATORS`), so one chain's menus never make a row however many of its pubs they cover. A cocktail estimate goes only to a pub that itself states it serves cocktails. Pins: `__tests__/tavilyLondonNightly.test.ts`, `__tests__/londonOsmPromotion.test.ts`, `__tests__/priceEstimateDrinks.test.ts`.
