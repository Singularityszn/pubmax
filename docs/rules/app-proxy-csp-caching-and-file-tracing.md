<a id="a-file-a-route-opens-at-runtime-is-not-in-the-deployed-function-unless-you-say-s"></a>

- **A file a route opens at runtime is not in the deployed function unless you say so.** Next traces only paths it can see statically, so any route that builds a path at request time ships without its data. Declare such files in `next.config.mjs` `outputFileTracingIncludes`, derived from their registry rather than hand-copied. WHICH freshness artifacts ship is one predicate, `datasetOpensArtifact` (`lib/freshness.ts`), mirrored by `lib/freshnessTracing.mjs` and `scripts/check_freshness.mjs`; an untraced pack is the dangerous case, because the file is simply absent and the reader falls back to the registry's literal stamp and reports the feed fresh for ever. A STATICALLY PRERENDERED route needs no key at all, so `/sitemap.xml` reads its packs at build and a bad pack fails `next build` rather than serving a 500. The ROUTE list is derived as well: `RUNTIME_DATA_PACKS` in `lib/venueIndexTracing.mjs` names each module that assembles a data path at request time with the files it can open, the reader routes come from the source import graph, and a hand-written key for such a route merges with the derived one instead of replacing it. Then mark the declared dynamic path operation with Next's `turbopackIgnore` comment so automatic tracing does not widen the route to the whole repository; the comment never replaces the explicit include. `__tests__/venueIndexTracing.test.ts` fails when a reader is undeclared, and also when ANY route-reachable module hands `fs` a path it assembled unless that module is a declared pack, is named in `RUNTIME_PATH_MODULES_TRACED_ELSEWHERE`, or is carried in `RUNTIME_PATH_MODULES_PENDING_DECLARATION`, a documented exception whose list may only shrink. That is why the pack table lives in `lib/cityVenuePacks.mjs`: the config cannot import TypeScript, so a city added to `lib/cities.ts` alone would browse in the app and be missing from the deployed function. Venue-detail lookup must preserve `unavailable` through `/api/venue/[id]` as a 503, never collapsing missing runtime data into an unknown pub. `/bar-tab/[id]` and `/ledger/[id]` call `lookupVenueDetail`, which asks the alias file first and does not cache a failed read, so an unreadable alias file is the read-unavailable surface and never an unknown pub (`__tests__/venuePageReadUnavailable.test.tsx`). The Ledger is a prerendered document, so it may not render that surface INTO itself: it throws, ISR keeps the last good copy or holds nothing, and `app/ledger/[id]/error.tsx` draws the card. To check a real build rather than guess, read `.next-prod/server/<route>/route.js.nft.json`, the exact file set that function ships with. Pins: `__tests__/freshnessTracing.test.ts`, `__tests__/feedTracing.test.ts`, `__tests__/venueRoute.test.ts`, `e2e/map-unknown-selection.spec.ts`.

<a id="a-tab-you-have-already-opened-is-not-a-page-you-have-to-fetch-again"></a>

- **A tab you have already opened is not a page you have to fetch again.** Routes that use the per-request CSP nonce are dynamic; CDN document exceptions are defined below. `experimental.staleTimes` in `next.config.mjs` owns the client Router Cache window. Its safety depends on keeping per-account content and mutable data out of reusable server payloads. `/admin` requires a fresh document credential check: token entry reloads the document, the refused document carries no account content, and every `/api/admin` read re-gates on the same credential. Keep `/admin` outside client-side navigation so a held payload cannot bypass the document guard. A new credential-dependent server page or a mutation that needs `router.refresh()` requires re-evaluating the cache window. `npm run lint` holds both safety conditions over the tree: `lib/routerCacheFence.mjs` refuses a server page that imports `cookies` or `draftMode` (statically, dynamically or through a re-export of `next/headers`), reads or tests for the `Authorization` or `Cookie` header, or imports any repository module that reaches such a read through its imports (reported as the concrete door that module reaches), and any `refresh()` on the App Router's `useRouter()` router however the router is named or destructured, plus any `.refresh()` call on an identifier or property whose name contains `router`, so a router passed as a parameter, prop or object property is still caught. It names each argued exception (`/admin` the `Cookie` header that `lib/adminAuth.ts` reads, `/login` `cookies()`, `/p/[id]` the `Authorization` header that `lib/pintDropViewer.ts` reaches) with the doors it may read, directly or through an import, and its reason, still refuses every other door in that file, reports an exception whose page no longer reads one of its doors as stale, and refuses to load while an exception names a page that is gone, so the list can only shrink. `__tests__/clientRouterCache.test.ts` pins both windows to the derived values under their ceiling and proves every lint rule fires on fixtures. `e2e/admin-document-guard.spec.ts` covers the anonymous refusal, session access, and token-entry reload. The data behind a tab uses `lib/surfaceDataCache.ts`, a browser-only store backed by sessionStorage. It refuses auth, identity and admin keys, holds nothing on the server, and clears on `DEVICE_IDENTITY_CHANGED_EVENT`. Each caller limits snapshot age and validates held and network answers. A valid answer within `freshForMs` can skip the network. Older valid snapshots seed a paint while the caller revalidates. Callers that opt out of this store retain their own data policy. This browser reuse does not change HTTP cache headers. `loadWhatsOnTonight` reuses public answers for 60 seconds and location answers for five seconds, with separate public and pub-only keys. Successful answers require a valid `servedAt` in the current London service night, including at publication after a delayed response. After the 04:00 rollover, the loader cannot join a request started before that boundary. Explicit retry bypasses both held answers and pending reads. Active callers may finish a displaced pending read, but that read cannot overwrite the newer request's snapshot. Source-observation dates remain separate from `servedAt`. Regression coverage is `__tests__/whatsOnTonightPublicReuse.test.ts`, `__tests__/whatsOnTonightRolloverRace.test.ts`, and `__tests__/whatsOnTonightBodyCancellation.test.ts`. Third half: a link to a DYNAMIC route is warmed on INTENT, never prefetched on sight (`components/nav/IntentLink.tsx`), because a Tonight arrival otherwise fired about twenty server renders in front of the listings the reader was waiting for. Pins: `__tests__/clientRouterCache.test.ts`, `__tests__/surfaceDataCache.test.ts`; method and figures in `docs/PERFORMANCE_BUDGETS.md`.

All of them take `script-src 'unsafe-inline'` in exchange for being prerendered and held by the CDN; the inline slot is the ONLY thing that differs, and every other route keeps a fresh nonce. A route that resolves a session or reads an `Authorization` header in its document (`/u/you`, `/messages`, `/admin`, `/p/[id]`) may never join either list. THREE rules ride with it. (1) A prerendered document may read NOTHING per request (`force-static` makes that a build error, and it is also what stops the root layout's `headers()` nonce read pulling the route back to dynamic), and it may carry NOTHING personal, because one copy is handed to every stranger. (2) THE LIST AND THE PAGE FILES ARE ONE LIST READ TWO WAYS: a listed path whose page is not `force-static` renders per request under 'unsafe-inline' and buys nothing, and a `force-static` page outside the list is prerendered with no nonce in its scripts and then answered with a policy that demands one, so `__tests__/cdnCachedDocuments.test.ts` holds both directions. Next sends `s-maxage=<revalidate>, stale-while-revalidate=<expire - revalidate>`, so `/today` and `/tonight` are fresh for 5 minutes and then may be served stale for up to 60 more (65 in all), and the hourly routes get a 5-minute stale window. It is global because a per-route expire needs cacheComponents, and it stays above every route's revalidate, because at equal values Next sends no stale window at all. These are the windows the header asks for, not a promise about age: a regeneration that fails can leave older content in place for longer. Pin: `__tests__/isrExpireTime.test.ts`. So a `/map` request whose document really differs is rewritten by the proxy to `app/map/arrival` and rendered per request with the nonce intact; `lib/mapDocumentTwin.ts` owns that key list, and adding a key takes those requests off the CDN while dropping one silently serves a share link the wrong card. <a id="the-five-cdn-documents-run-no-function-and-their-policy-is-one-policy"></a>

- **THE FIVE CDN DOCUMENTS RUN NO FUNCTION, AND THEIR POLICY IS ONE POLICY.** Task vercel-f1-cdn-documents, item 3 of the Vercel insights read (15 Oct 2026). `/`, `/map`, `/tonight`, `/today` and `/near` answered `x-vercel-cache: HIT` with no nonce, yet Vercel ran `proxy.ts` and `clerkMiddleware` IN FRONT OF the cache on every request, so a CDN hit still paid a Node invocation and a cold start for a policy that changes only with a deploy. On the canonical host the general matcher now leaves the five paths out (and `/plan` and `/pal` since they joined the list on 17 Oct 2026, the proxy acting on no query of theirs), and `next.config.mjs` ships their Content-Security-Policy from `headers()`. FOUR rules. (1) ONE BUILDER: `lib/contentSecurityPolicy.mjs` builds the policy for both the proxy and the config, and `lib/clerkIdentity.ts` and `lib/supabaseCsp.ts` re-export its parsers, so the static header cannot drift from what `securityProxy` would have sent; the fence evaluates `next.config.mjs` in a clean Node under the same env and compares the two byte for byte, with and without Clerk and Supabase configured. (2) THE PROXY KEEPS ITS QUERIES: `/?src=` (the printed-poster 307) and a `/map` key in `MAP_DOCUMENT_QUERY_KEYS` (the per-request document twin) still run the proxy through their own matcher entries, and each header rule carries the same keys as `missing` conditions, so a request takes its policy from exactly one place. A key added to `MAP_DOCUMENT_QUERY_KEYS` must join `CDN_EDGE_PROXY_QUERY_KEYS` in `lib/cdnDocumentEdge.mjs`, and the fence fails until it does. (3) CLERK HAS NO CONSUMER THERE: nothing outside `proxy.ts` imports `@clerk/nextjs/server`, these documents render at build or ISR time when no middleware runs, and Clerk mounts client-side after first paint, so skipping `clerkMiddleware` drops only its handshake redirect, never a session. (4) THE ENV IS THE BUILD'S: the static policy reads the env `next build` sees, which on Vercel is the runtime env, because an env change there takes a redeploy. Generated and preview `*.vercel.app` hosts still run the proxy on every path. Pin: `__tests__/cdnDocumentEdge.test.ts`.

<a id="a-static-asset-never-runs-the-proxy-and-a-failing-pack-is-not-a-failing-basemap"></a>

- **A STATIC ASSET NEVER RUNS THE PROXY, AND A FAILING PACK IS NOT A FAILING BASEMAP.** Two halves of one finding (#1425 under the Wayfinder map #1423). (1) `proxy.ts` is a Node function that Vercel runs IN FRONT OF the CDN for every path its matcher claims, and the matcher claimed `/data`: two consecutive `x-vercel-cache: HIT` responses for one static file carried DIFFERENT nonces, and a cached copy cannot mint a nonce, so the 500 seen on an 82 KB uk_base pack was that function failing in front of a healthy file. `lib/staticAssetPrefixes.mjs` is the ONE list of public directories the matcher now excludes, and its rule is that a prefix must name a directory under `public/` NO app route shares. `/pal` is the standing counter-example, being both `public/pal/` and `app/pal/`, and excluding it would strip the per-request nonce off a rendered document. A PREFIX PROVES ITSELF BY BYTES OR BY A GENERATOR, and the witness is the COMMIT rather than the working tree: the `vendor` prefix names gitignored output that `prepare:maplibre-worker` writes, so a fence asking `existsSync` passed on every machine that had ever run the app and turned main red in the CI unit job, which checks out clean and runs `npx vitest run` with no build in front of it. Such a prefix is declared in `BUILD_WRITTEN_STATIC_ASSET_PREFIXES` and is held to a generator that writes the directory it names and is wired into `npm run build` ahead of `next build`; every other prefix is held to files present at HEAD, so a directory living only on one developer's machine can never join the list unannounced. THE ROOT FILES GO BY EXTENSION: the files at the root of `public/` (`public/theme-init.js` and `public/map-first-paint-init.js`, which load in `<head>`, plus `public/sw.js`, the manifest and every icon) and the `/pal` art still ran the proxy, and live headers on 15 Oct 2026 showed a fresh nonce on `/theme-init.js?v=splash-1`. `STATIC_ASSET_EXTENSIONS` names the byte extensions the matcher excludes at the END of a path, and ONLY for one segment at the root or under `public/pal` (`/u/foo.png` normalises to a real handle and keeps its nonce), so `/pal` keeps its nonce while `/pal/*.webp` skips the function; the html extension is never listed (`public/offline.html` is a document), and the fence holds every committed root file to the list and every app page path to falling outside it. The PostHog relay is a caller too: `/ingest` never enters `clerkMiddleware`, and the trailing-slash rule leaves out the relay's slashed paths, so a PostHog event (posted to a trailing-slash path under the relay) pays the relay route's invocation and not a second one in front of it. Next only reads a matcher it can analyse STATICALLY, so `proxy.ts` writes the alternation out as a literal and the fence derives it. Anything the proxy used to do on those paths moved to a routing rule that costs no function: the legacy uk_base generation rewrite is `rewrites()` and the non-production `X-Robots-Tag` is `headers()`, both in `next.config.mjs`. (2) `map.on("error")` hears two things through one channel. `tube-lines` is the ONE scene source MapLibre fetches for itself, and its bytes are our own `/data` file, so a failure there says nothing about the tile source while the remedy it used to buy - the mount's ONE shared style reload - rebuilds every source and re-asks for the same file. `lib/mapDataPackFailure.ts` gives a pack its own bounded lane, asked BEFORE any tile stamp is taken: one retry of that pack, then empty it and carry on, never a style reload and never a stamp in the burst window, which stays exactly as it was for genuine tile failures. Pins: `__tests__/staticAssetPrefixes.test.ts`, `__tests__/ukBaseLegacyPath.test.ts`, `__tests__/mapDataPackFailure.test.ts`.

<a id="the-host-canonicalisation-is-for-readers-and-api-is-a-caller"></a>

- **The host canonicalisation is for READERS, and `/api` is a caller.** `proxy.ts` 308s a `*.vercel.app` host to `pubmaxxing.com` so a generated alias never serves an indexable copy of the site (`shouldRedirectVercelHost`). Vercel's cron dispatcher issues its scheduled GET against the deployment's OWN generated host and does not follow that redirect, so every job in `vercel.json` once answered 308 and no handler ran, including the watchdog that would have said so. The whole `/api` tree is therefore exempt from the host redirect (`servesApiCaller`, the one predicate the CSP skip also reads), because the split-brain being prevented is a crawlable DOCUMENT mirror and a JSON answer is not one. What protects those routes is the CALLER'S CREDENTIAL, never the hostname: `assertCronRequest` (`lib/cronAuth.ts`) requires the bearer secret and denies in production when it is unset. The trailing-slash 308 is deliberately NOT exempt, because `skipTrailingSlashRedirect` means `/api/thing/` matches no route. Pin: `__tests__/vercelProductionHostRedirect.test.ts`, which reads the scheduled paths out of `vercel.json` so a new cron cannot fall outside the fence.

<a id="a-route-that-ships-a-document-nobody-keeps-and-the-header-that-says-so"></a>

- **A ROUTE THAT SHIPS A DOCUMENT NOBODY KEEPS, AND THE HEADER THAT SAYS SO.** `/onboarding` is the native shell's first-run surface, and the web reaches it only from the first-run chip `/near` offers a first-time visitor, which carries `?start=web` (`webOnboardingStartRequested`, `lib/firstRunRoute.ts`): `FirstRunOnboardingGate` consumes a native-only, session-scoped handoff, so a web visit without that mark has always failed closed to "/". It did that in the BROWSER, after rendering and discarding a whole document, and on Slow 4G that was the worst LCP on the site at 4676 ms, the paint being the homepage hero arriving after the bounce (Astra's live walk, 7 Sep 2026, finding B6). `proxy.ts` turns away, with a 307 and no document, a document request that no page on this origin started. FOUR rules. (1) THE SIGNAL IS `Accept`, NOT NEXT'S OWN: this version of Next STRIPS both the `RSC` header and the `_rsc` query before middleware, measured on a production build, so neither can be read there. A browser document navigation sends `text/html,...` and every RSC navigation and prefetch sends `*/*`, which is why the shell's `router.replace` arrival from "/" (`components/native/AppEntryRoute.tsx`) is untouched. Accept also FAILS SAFE: an RSC fetch cannot start claiming to want HTML, so a future Next release cannot turn this rule on the shell's own arrival, where a header-name change could. (2) THE SHELL'S OWN DOCUMENT NAVIGATION PASSES: a fresh install leaves "/" with a location replace in `public/theme-init.js`, which is a document request. Turning it away sent every fresh install to the landing page with the first-run mark stamped, so onboarding never ran (7 to 14 Sep 2026). `Sec-Fetch-Site: same-origin` passes, and when that header is ABSENT (WKWebView before iOS 16.4, and the app targets 15.0) a Referer on the same host and scheme passes. When `Sec-Fetch-Site` is sent it decides alone, so a typed visit (`none`), a `same-site` and a `cross-site` navigation keep the 307 whatever Referer says. (3) 307 AND NEVER 308: a browser caches a permanent redirect, the shell is a remote-URL wrap of this same origin, and one cached 308 would take the first run away from every later install on that device. (4) THE PATH IS A LEAF: `ONBOARDING_PATH` lives in `lib/firstRunRoute.ts`, which imports nothing, because a middleware bundle may not drag the city tables, the Capacitor probe and the storage seams in behind one string; `lib/entryDecision.ts` re-exports it. Pins: `__tests__/onboardingWebDocument.test.ts`, `e2e/mobile-first-run-onboarding.spec.ts` (a fresh install boots "/" and lands on the route), and `__tests__/clerkProxyCsp.test.ts`, whose nonced-family list keeps the route, because the document it answers to a same-origin navigation still needs its nonce.

- **A CRAWL STOP STILL READS WITH NO SIGNAL, AND THE SAVED PAGE IS THE ONE A STRANGER GETS.** The crawl offline pack (30 Oct 2026). When `components/plan/NightCrawlMode.tsx` knows its stops, `lib/crawlOfflinePack.ts` posts their venue ids, and nothing else, to the controlling service worker. `public/sw.js` then saves each stop's `/pubs/<id>` page and that page's hashed stylesheets, and a navigation that fails offline is answered from the pack after the plan preview and before the shell ladder. FIVE rules. (1) NO COOKIES: the worker fetches every pack page with `credentials: "omit"`, so the saved HTML is the anonymous page and no session or account can reach Cache Storage. (2) THE WORKER CLEANS THE MESSAGE: only the message type `pubmax:crawl-offline-pack`, only ids shaped `[a-z0-9][a-z0-9-]{0,119}`, at most 12 a message, so a page cannot steer the worker at another path. (3) ONLY A PLAIN 200 OF HTML IS SAVED: a redirect, an error status or another content type is dropped. (4) BOUNDED AND CHEAP: the `crawl-pubs-v1` family keeps at most 24 pages, oldest out first, and a stop saved less than six hours ago is not fetched again, so reopening the crawl screen all night costs one fetch per stop. (5) DATA SAVER IS RESPECTED: with the browser data saver on, or with no worker in control yet, nothing is sent. (6) A FIRST VISIT STILL GETS ITS PACK: the worker registers after load, so `components/plan/useCrawlOfflinePack.ts` asks again on every `controllerchange` (the first claim or a worker update) and drops that listener when the crawl screen closes (`__tests__/useCrawlOfflinePack.test.tsx`). Map tiles are NOT in the pack: their URLs come from a versioned TileJSON, and the tile cache already keeps what the reader has looked at. Pins: `__tests__/crawlOfflinePack.test.ts` (the real worker over a Map-backed Cache Storage), `__tests__/useCrawlOfflinePack.test.tsx`, `__tests__/serviceWorkerCache.test.ts`.
