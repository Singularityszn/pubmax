# Proxy, CSP, caching and file tracing

Moved from [`app/AGENTS.md`](../../app/AGENTS.md). Authoritative policy detail lives here; the area index stays short.

<a id="a-file-a-route-opens-at-runtime-is-not-in-the-deployed-function-unless-you-say-s"></a>

- **A file a route opens at runtime is not in the deployed function unless you say so.** Next traces only paths it can see statically, so any route that builds a path at request time ships without its data. Declare such files in `next.config.mjs` `outputFileTracingIncludes`, derived from their registry rather than hand-copied. WHICH freshness artifacts ship is one predicate, `datasetOpensArtifact` (`lib/freshness.ts`), mirrored by `lib/freshnessTracing.mjs` and `scripts/check_freshness.mjs`; an untraced pack is the dangerous case, because the file is simply absent and the reader falls back to the registry's literal stamp and reports the feed fresh for ever. A STATICALLY PRERENDERED route needs no key at all, so `/sitemap.xml` reads its packs at build and a bad pack fails `next build` rather than serving a 500. The ROUTE list is derived as well: `RUNTIME_DATA_PACKS` in `lib/venueIndexTracing.mjs` names each module that assembles a data path at request time with the files it can open, the reader routes come from the source import graph, and a hand-written key for such a route merges with the derived one instead of replacing it. Then mark the declared dynamic path operation with Next's `turbopackIgnore` comment so automatic tracing does not widen the route to the whole repository; the comment never replaces the explicit include. `__tests__/venueIndexTracing.test.ts` fails when a reader is undeclared, and also when ANY route-reachable module hands `fs` a path it assembled unless that module is a declared pack, is named in `RUNTIME_PATH_MODULES_TRACED_ELSEWHERE`, or is carried in `RUNTIME_PATH_MODULES_PENDING_DECLARATION`, a documented exception whose list may only shrink. That is why the pack table lives in `lib/cityVenuePacks.mjs`: the config cannot import TypeScript, so a city added to `lib/cities.ts` alone would browse in the app and be missing from the deployed function. Venue-detail lookup must preserve `unavailable` through `/api/venue/[id]` as a 503, never collapsing missing runtime data into an unknown pub. `/bar-tab/[id]` and `/ledger/[id]` call `lookupVenueDetail`, which asks the alias file first and does not cache a failed read, so an unreadable alias file is the read-unavailable surface and never an unknown pub (`__tests__/venuePageReadUnavailable.test.tsx`). To check a real build rather than guess, read `.next-prod/server/<route>/route.js.nft.json`, the exact file set that function ships with. Pins: `__tests__/freshnessTracing.test.ts`, `__tests__/feedTracing.test.ts`, `__tests__/venueRoute.test.ts`, `e2e/map-unknown-selection.spec.ts`.

<a id="the-answer-is-a-pub-people-are-talking-about-then-our-own-listings-then-an-hones"></a>

- **THE ANSWER IS A PUB PEOPLE ARE TALKING ABOUT, THEN OUR OWN LISTINGS, THEN AN HONEST QUIET NIGHT.** Captain 7 September 2026, over a hydrated `/tonight` that led with "Deals tonight, Small Plates Club, J D Wetherspoon" while `/api/whats-on` served 96 Wetherspoon deal rows and 24 Ticketmaster events. THE LEDE REGION is a DOM region (`data-testid="tonight-lede"`) and only three things may fill it, in this order: the hyped pubs from `lib/hypedPubs.ts`, the independent listings, and the quiet-night sentence. FIVE rules. (1) NO CHAIN AND NO TICKET PLATFORM MAY LEAD. `lib/tonightPrimary.ts` already refused Wetherspoon and Ticketmaster; `withoutTonightChainRows` (`lib/tonightChainLanes.ts`) now takes Greene King too, whose 259 bundled sport fixtures each say in their own detail line that the pub has not confirmed the screening. The lane is read off the PUBLISHER, never the title. (2) THE CHAIN KEEPS ITS SUPPLY AND LOSES THE FRONT ROW: one labelled block per chain under the lede ("Wetherspoon deals tonight", "Greene King tonight"), carrying the chain's own source label and the day that page was read, folded after three, and grouped by OFFER through `groupTonightListings` so one promotion across 96 pubs is one row saying how many pubs run it. A chain row leaves the generic Deals lane in the same move, because one offer under two headings is the same offer counted twice. (3) A QUIET NIGHT WAS CHECKED, AND THE CHIP SAYS WHEN: with no What's-On row on screen, `tonightWhatsOnObservedAt` dates the quiet reading from the live read's own `kindObservedAt`, oldest kind first. The old answer was null, so a read that had just dated 120 rows printed "No date on this yet". A read that dated NOTHING still answers null. (4) A QUIET NIGHT ANSWERS WITH PUBS, NOT CHIPS: `lib/tonightCheapPints.ts` puts the cheapest listed pints above the soft plans and the vibe chips. It is NOT a "quieter pubs" list, and may never become one: the F02 ruling in `lib/AGENTS.md` settles that no per-venue quiet reading exists in this product. It holds ONE ROW PER CHAIN, the chain named on that row, and the chain is read off a source (the Wetherspoon membership in `tonightWetherspoonVenueIds`, which is the directory join in `lib/wetherspoonsMatch.ts` or the SpoonMe pack, the pub's own website host, or the price listing naming the operator), never off a name (site audit D17). The lede wrapper holds the lede and nothing else; the rail is ONE element after it in the DOM holding, in order, the rail summary, the cheapest listed pints, the chain blocks, the vibe chips, the phone Deals and Music lanes, the editorial rail, the soft plans and the area news, so a phone keeps its base order. From 1100px that element spans every desktop grid row down to a flexible last row, so the two columns share no row height and the rail has no gap (site audit D8; firstmate ruled on 13 Sep 2026 that the editorial rail lives in the desktop rail, because a rail split around the column left about 1,000px of it empty beside the lede). (5) THE PACK IS READ AT BUILD, in `app/tonight/page.tsx`, because the document is prerendered and a lane a reader may never see must cost no request. Pins: `__tests__/tonightHypedLede.test.ts` (a hydrated DOM, not static markup, which is how every earlier fence stayed green over this defect), `__tests__/tonightChainLanes.test.ts`, `__tests__/tonightQuietChipDate.test.ts`, `__tests__/hypedPubs.test.ts`, `__tests__/tonightCheapPints.test.ts`, and for the rail and the one row per chain on a real DOM, `e2e/tonight.spec.ts`.

<a id="a-tab-you-have-already-opened-is-not-a-page-you-have-to-fetch-again"></a>

- **A tab you have already opened is not a page you have to fetch again.** Routes that use the per-request CSP nonce are dynamic; CDN document exceptions are defined below. `experimental.staleTimes` in `next.config.mjs` owns the client Router Cache window. Its safety depends on keeping per-account content and mutable data out of reusable server payloads. `/admin` requires a fresh document credential check: token entry reloads the document, the refused document carries no account content, and every `/api/admin` read re-gates on the same credential. Keep `/admin` outside client-side navigation so a held payload cannot bypass the document guard. A new credential-dependent server page or a mutation that needs `router.refresh()` requires re-evaluating the cache window. `npm run lint` holds both safety conditions over the tree: `lib/routerCacheFence.mjs` refuses a server page that imports `cookies` or `draftMode` (statically, dynamically or through a re-export of `next/headers`), reads or tests for the `Authorization` or `Cookie` header, or imports any repository module that reaches such a read through its imports (reported as the concrete door that module reaches), and any `refresh()` on the App Router's `useRouter()` router however the router is named or destructured, plus any `.refresh()` call on an identifier or property whose name contains `router`, so a router passed as a parameter, prop or object property is still caught. It names each argued exception (`/admin` the `Cookie` header that `lib/adminAuth.ts` reads, `/login` `cookies()`, `/p/[id]` and `/ledger/[id]` the `Authorization` header that `lib/pintDropViewer.ts` reaches) with the doors it may read, directly or through an import, and its reason, still refuses every other door in that file, reports an exception whose page no longer reads one of its doors as stale, and refuses to load while an exception names a page that is gone, so the list can only shrink. `__tests__/clientRouterCache.test.ts` pins both windows to the derived values under their ceiling and proves every lint rule fires on fixtures. `e2e/admin-document-guard.spec.ts` covers the anonymous refusal, session access, and token-entry reload. The DATA behind a tab is the second half: `lib/surfaceDataCache.ts` is ONE in-memory stale-while-revalidate store. It REFUSES an auth, identity or admin key outright rather than declining quietly, holds nothing on the server (a `"use client"` module still executes there, and one module Map would be shared by every request), ages entries out so a snapshot may seed a paint but never stand in for an answer, and leaves with the account on `DEVICE_IDENTITY_CHANGED_EVENT`. A surface that declares `no-store` keeps its own lane and is never cached. Third half: a link to a DYNAMIC route is warmed on INTENT, never prefetched on sight (`components/nav/IntentLink.tsx`), because a Tonight arrival otherwise fired about twenty server renders in front of the listings the reader was waiting for. Pins: `__tests__/clientRouterCache.test.ts`, `__tests__/surfaceDataCache.test.ts`; method and figures in `docs/PERFORMANCE_BUDGETS.md`.

<a id="exactly-five-documents-are-exempt-from-the-nonce-and-the-list-is-the-fence"></a>

- **Exactly five documents are exempt from the nonce, and the list is the fence.** Captain decision 2026-08-09, widened 2026-09-05 ("Widen"): `CDN_CACHED_DOCUMENT_PATHS` in `proxy.ts` names `/`, `/map`, `/tonight`, `/today` and `/near`, which take `script-src 'unsafe-inline'` in exchange for being prerendered and held by the CDN; the inline slot is the ONLY thing that differs, and every other route keeps a fresh nonce. A route that resolves a session in its document (`/u/you`, `/messages`, `/admin`) may never join the list. THREE rules ride with it. (1) A prerendered document may read NOTHING per request (`force-static` makes that a build error, and it is also what stops the root layout's `headers()` nonce read pulling the route back to dynamic), and it may carry NOTHING personal, because one copy is handed to every stranger. (2) THE LIST AND THE PAGE FILES ARE ONE LIST READ TWO WAYS: a listed path whose page is not `force-static` renders per request under 'unsafe-inline' and buys nothing, and a `force-static` page outside the list is prerendered with no nonce in its scripts and then answered with a policy that demands one, so `__tests__/cdnCachedDocuments.test.ts` holds both directions. (3) THE ISR WINDOW IS SIZED TO THE CLOCK THE PAGE READS: `/tonight` and `/today` compose off the London hour (the greeting slot, the quiet-pint window) and revalidate every 300 s, while `/`, `/map` and `/near` read only bundled data and take 3600 s; do not lengthen the short ones, because a "Good morning" at ten past noon is the cost. So a `/map` request whose document really differs is rewritten by the proxy to `app/map/arrival` and rendered per request with the nonce intact; `lib/mapDocumentTwin.ts` owns that key list, and adding a key takes those requests off the CDN while dropping one silently serves a share link the wrong card. The homepage's poster arrival moved into the proxy for the same reason. Pins: `__tests__/clerkProxyCsp.test.ts`, `__tests__/cdnCachedDocuments.test.ts`, `__tests__/mapDocumentTwin.test.ts`, `e2e/borough-crawls-security.spec.ts`.

<a id="a-static-asset-never-runs-the-proxy-and-a-failing-pack-is-not-a-failing-basemap"></a>

- **A STATIC ASSET NEVER RUNS THE PROXY, AND A FAILING PACK IS NOT A FAILING BASEMAP.** Two halves of one finding (#1425 under the Wayfinder map #1423). (1) `proxy.ts` is a Node function that Vercel runs IN FRONT OF the CDN for every path its matcher claims, and the matcher claimed `/data`: two consecutive `x-vercel-cache: HIT` responses for one static file carried DIFFERENT nonces, and a cached copy cannot mint a nonce, so the 500 seen on an 82 KB uk_base pack was that function failing in front of a healthy file. `lib/staticAssetPrefixes.mjs` is the ONE list of public directories the matcher now excludes, and its rule is that a prefix must name a directory under `public/` NO app route shares. `/pal` is the standing counter-example, being both `public/pal/` and `app/pal/`, and excluding it would strip the per-request nonce off a rendered document. A PREFIX PROVES ITSELF BY BYTES OR BY A GENERATOR, and the witness is the COMMIT rather than the working tree: the `vendor` prefix names gitignored output that `prepare:maplibre-worker` writes, so a fence asking `existsSync` passed on every machine that had ever run the app and turned main red in the CI unit job, which checks out clean and runs `npx vitest run` with no build in front of it. Such a prefix is declared in `BUILD_WRITTEN_STATIC_ASSET_PREFIXES` and is held to a generator that writes the directory it names and is wired into `npm run build` ahead of `next build`; every other prefix is held to files present at HEAD, so a directory living only on one developer's machine can never join the list unannounced. Next only reads a matcher it can analyse STATICALLY, so `proxy.ts` writes the alternation out as a literal and the fence derives it. Anything the proxy used to do on those paths moved to a routing rule that costs no function: the legacy uk_base generation rewrite is `rewrites()` and the non-production `X-Robots-Tag` is `headers()`, both in `next.config.mjs`. (2) `map.on("error")` hears two things through one channel. `tube-lines` is the ONE scene source MapLibre fetches for itself, and its bytes are our own `/data` file, so a failure there says nothing about the tile source while the remedy it used to buy - the mount's ONE shared style reload - rebuilds every source and re-asks for the same file. `lib/mapDataPackFailure.ts` gives a pack its own bounded lane, asked BEFORE any tile stamp is taken: one retry of that pack, then empty it and carry on, never a style reload and never a stamp in the burst window, which stays exactly as it was for genuine tile failures. Pins: `__tests__/staticAssetPrefixes.test.ts`, `__tests__/ukBaseLegacyPath.test.ts`, `__tests__/mapDataPackFailure.test.ts`.

<a id="the-host-canonicalisation-is-for-readers-and-api-is-a-caller"></a>

- **The host canonicalisation is for READERS, and `/api` is a caller.** `proxy.ts` 308s a `*.vercel.app` host to `pubmaxxing.com` so a generated alias never serves an indexable copy of the site (`shouldRedirectVercelHost`). Vercel's cron dispatcher issues its scheduled GET against the deployment's OWN generated host and does not follow that redirect, so every job in `vercel.json` once answered 308 and no handler ran, including the watchdog that would have said so. The whole `/api` tree is therefore exempt from the host redirect (`servesApiCaller`, the one predicate the CSP skip also reads), because the split-brain being prevented is a crawlable DOCUMENT mirror and a JSON answer is not one. What protects those routes is the CALLER'S CREDENTIAL, never the hostname: `assertCronRequest` (`lib/cronAuth.ts`) requires the bearer secret and denies in production when it is unset. The trailing-slash 308 is deliberately NOT exempt, because `skipTrailingSlashRedirect` means `/api/thing/` matches no route. Pin: `__tests__/vercelProductionHostRedirect.test.ts`, which reads the scheduled paths out of `vercel.json` so a new cron cannot fall outside the fence.

<a id="a-route-that-ships-a-document-nobody-keeps-and-the-header-that-says-so"></a>

- **A ROUTE THAT SHIPS A DOCUMENT NOBODY KEEPS, AND THE HEADER THAT SAYS SO.** `/onboarding` is the native shell's one-time first-run surface, and the web reaches it only from a link inside the app that carries `?start=web` (`webOnboardingStartRequested`, `lib/firstRunRoute.ts`): `FirstRunOnboardingGate` consumes a native-only, session-scoped handoff, so a web visit without that mark has always failed closed to "/". It did that in the BROWSER, after rendering and discarding a whole document, and on Slow 4G that was the worst LCP on the site at 4676 ms, the paint being the homepage hero arriving after the bounce (Astra's live walk, 7 Sep 2026, finding B6). `proxy.ts` turns away, with a 307 and no document, a document request that no page on this origin started. FOUR rules. (1) THE SIGNAL IS `Accept`, NOT NEXT'S OWN: this version of Next STRIPS both the `RSC` header and the `_rsc` query before middleware, measured on a production build, so neither can be read there. A browser document navigation sends `text/html,...` and every RSC navigation and prefetch sends `*/*`, which is why the shell's `router.replace` arrival from "/" (`components/native/AppEntryRoute.tsx`) is untouched. Accept also FAILS SAFE: an RSC fetch cannot start claiming to want HTML, so a future Next release cannot turn this rule on the shell's own arrival, where a header-name change could. (2) THE SHELL'S OWN DOCUMENT NAVIGATION PASSES: a fresh install leaves "/" with a location replace in `public/theme-init.js`, which is a document request. Turning it away sent every fresh install to the landing page with the first-run mark stamped, so onboarding never ran (7 to 14 Sep 2026). `Sec-Fetch-Site: same-origin` passes, and when that header is ABSENT (WKWebView before iOS 16.4, and the app targets 15.0) a Referer on the same host and scheme passes. When `Sec-Fetch-Site` is sent it decides alone, so a typed visit (`none`), a `same-site` and a `cross-site` navigation keep the 307 whatever Referer says. (3) 307 AND NEVER 308: a browser caches a permanent redirect, the shell is a remote-URL wrap of this same origin, and one cached 308 would take the first run away from every later install on that device. (4) THE PATH IS A LEAF: `ONBOARDING_PATH` lives in `lib/firstRunRoute.ts`, which imports nothing, because a middleware bundle may not drag the city tables, the Capacitor probe and the storage seams in behind one string; `lib/entryDecision.ts` re-exports it. Pins: `__tests__/onboardingWebDocument.test.ts`, `e2e/mobile-first-run-onboarding.spec.ts` (a fresh install boots "/" and lands on the route), and `__tests__/clerkProxyCsp.test.ts`, whose nonced-family list keeps the route, because the document it answers to a same-origin navigation still needs its nonce.
