<a id="model-call-tracing-is-one-inert-server-leaf"></a>

- **Model-call tracing is one inert server leaf.** `lib/observability/arize.ts` is the only tracing module, registered once from the root `instrumentation.ts`, and it stays a no-op unless BOTH `ARIZE_API_KEY` and `ARIZE_SPACE_KEY` are set, so keyless dev, tests and CI send nothing. Every direct model HTTP call in `lib/` goes through `traceArizeModelCall` / `traceArizeModelLoop`, whose spans carry the model, tokens, latency and a static `metadata.route` tag chosen at the call site, and whose prompt and completion values are capped at 2048 characters. The AI SDK `generateText` gateway call is traced by the AI SDK telemetry bridge instead: its spans carry `functionId` (`gen_ai.agent.name`), not `metadata.route`, and no length cap. Prompts and completions are masked for emails and handles, at write time in the helpers and for every span in the `MaskingSpanExporter`, and the moderation adapters record NO input at all because their requests carry signed image URLs. The keyed path also registers an `OpenAIInstrumentation` (`@arizeai/openinference-instrumentation-openai`), which patches the `openai` npm SDK on require; NOTHING in this app imports that SDK yet, so it emits no span today and the `openai` dependency exists only so the patch target resolves. Tracing never enters a client bundle: the root `instrumentation-client.ts` is PostHog only. Fence: `__tests__/arizeTracing.test.ts`, `__tests__/arizeTracingRegistration.test.ts`. Operator setup: `docs/observability/arize.md`.
