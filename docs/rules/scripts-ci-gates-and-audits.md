<a id="every-job-runs-on-the-avrea-label-and-a-build-is-not-a-production-runtime"></a>

- **EVERY JOB RUNS ON THE AVREA LABEL, AND A BUILD IS NOT A PRODUCTION RUNTIME.** GitHub-hosted allocation stopped answering on an organisation billing fault and no job started between 5 September 2026 11:08Z and 6 September 16:37Z, so the captain installed Avrea runners: every `runs-on` in `.github/workflows/` is `avrea-ubuntu-latest-2-vcpu` (PR #1585 made the switch) EXCEPT the two measuring jobs in `.github/workflows/ci.yml`, `Performance budget` and `UX lane performance`, which take `avrea-ubuntu-latest-4-vcpu`. That pair is a MEASUREMENT decision and the workflow carries its own reason: on the 2 vCPU box the sweep could not measure itself, the 6 September run spreading LCP samples 37 to 51 per cent on four routes against the method's own 12 per cent width, so a route flipped between pass and fail on one commit. No ceiling moved for it, and the second job shares the size because two figures taken on two different boxes are not comparable. The image is Ubuntu and each job still installs its own toolchain, so `sudo apt-get`, `npx playwright install --with-deps` and the PostgreSQL 16 cluster all behave as before; the Blacksmith migration stays rejected (#747). `.github/workflows/ci.yml` triggers on pull_request and push to `main`, effective RLS stays in `.github/workflows/rls-session.yml`, and branch protection is captain-side. TWO rules the first green run cost. (1) A KEYLESS BUILD IS NOT A PRODUCTION DEPLOY: `next build` sets NODE_ENV=production, so a runner with no Supabase keys satisfied `isDeployedProduction()` and `selectStore` (`lib/storeBackend.ts`) threw while prerendering `/today`, which reads the weather snapshot store. `isProductionBuildPhase()` (`lib/deploymentEnv.ts`, the leaf both guards read) answers the one question `lib/serverEnv.ts` already asked, so `requiresSupabaseStore()` says no during the build and the runtime refusal is untouched: Next never sets that phase on a server answering requests. THE PRODUCTION CHECK COMES FIRST AND EVERY ESCAPE SITS BELOW IT, in `lib/supabase.ts` and in `lib/serverEnv.ts` alike: `NEXT_PHASE` is an ordinary environment variable and a Vercel dashboard variable applies to Build and Runtime alike, so an escape read ABOVE `VERCEL_ENV === "production"` hands a deployed production process the in-memory store and skips the startup secret assertions, which is every write answering 200 and evaporating on the next cold start. `lib/analyticsAttribution.mjs` follows the same ordering for the same reason: the inlined build answer first, then the platform's production word, and only then the browser-suite escape, because `currentAnalyticsAttribution()` reads the live process environment on the server and one project variable used to relabel every real drinker event `internal-test`. A keyless CI build sets no `VERCEL_ENV` at all, so it still falls through to the build-phase line. (2) A CHECKOUT WITH `persist-credentials: false` CANNOT FETCH: the budget ratchet's `git fetch origin main` died with "could not read Username for 'https://github.com'", so the step reads the base branch's own remote-tracking ref out of the `fetch-depth: 0` checkout and verifies the ref first, because `scripts/check-budget-ratchet.mjs` reports an unreadable base as "nothing was compared" and exits 0. Pins: `__tests__/storeBackend.test.ts`, `__tests__/serverEnv.test.ts`, `__tests__/analyticsAttribution.test.ts`, `__tests__/qualityGateWiring.test.ts`.

<a id="knip-is-the-dead-code-gate-and-every-ignore-names-the-caller-knip-cannot-see"></a>

- **KNIP IS THE DEAD-CODE GATE, AND EVERY IGNORE NAMES THE CALLER KNIP CANNOT SEE.** `npm run deadcode` runs `scripts/deadcode-gate.mjs`, which runs knip over the whole tree with every issue type at `"error"` bar `duplicates` (a judgement, so a warning) and `unresolved` (off) and then, on a branch, fails only the findings `origin/main` does not already have. `npm run deadcode:all` is the unfiltered run, for the merge train and for anyone cleaning inherited debt. `verify` runs `deadcode` after `typecheck` and `__tests__/qualityGateWiring.test.ts` holds both scripts. FIVE rules. (1) THE IGNORE LIST IS NOT KNIP'S OWN: `lib/agentToolingPaths.mjs` is the ONE list of the directories agent tooling writes into this checkout, read by `eslint.config.mjs` AND by knip, which is why the config is TypeScript rather than JSON. Two hand-written copies is how the GitNexus index fell between them: the `gitnexus` MCP server this repo is wired to writes a CommonJS entry file full of `require()` calls, neither list named its directory, and `npm run lint` - so `npm run verify` and the pre-push hook, the documented merge bar - exited 1 on a CLEAN tree on every machine that tool had run against. Being gitignored is not the test for joining that list; `.agents/` and `skills/` are vendored packs this tree commits and are still upstream sources rather than our code. (2) A FILE KNIP FINDS NO CALLER FOR IS NOT AUTOMATICALLY DEAD, so every other ignore entry carries the caller in a comment: a GitHub workflow, a Python subprocess call, a `command()` string in `scripts/local-refresh/scheduler.mjs`, a fence test reading the source as TEXT, or the refresh command a lane names in `data/freshness_registry.json`. Delete only what NOTHING names. (3) A PLAIN .mjs LEAF BESIDE ITS DECLARATION SIDECAR IS ONE MODULE IN TWO FILES: TypeScript resolution sends an import of the .mjs leaf to the .d.mts beside it, so the sidecar reads as a file nobody imports AND the implementation's exports read as exports nobody uses. Acting on either half deletes a LIVE export while `tsc` stays green off the stale sidecar, so the pair leaves the graph together: the sidecars are ignored and `declaredMjsPairs()` in `knip.config.ts` enters each implementation leaf as an entry. (4) A PLUGIN IS WHAT MAKES A DEPENDENCY READABLE: knip only analyses files reachable from an entry, and `convex/*.ts` are entries only because knip's convex plugin says so, so disabling that plugin reports the live `convex` dependency as unused. Never silence a finding by switching a plugin off; the dependency itself is what the finding is about. Dependency exceptions and their callers are recorded beside `ignoreDependencies` in `knip.config.ts`. A false-positive EXPORT uses a `@public` JSDoc tag naming its caller, never an ignore, and the tag needs the same evidence: `npx tsc --noEmit` goes red when the export keyword is removed. (5) VERIFY FAILS ONLY ON FINDINGS THE BRANCH INTRODUCED. A rebase that inherits an unused export from a PR that landed while this branch was open is not this branch's to delete, so the wrapper subtracts origin/main's knip JSON from HEAD's. On main (no commits ahead of origin/main), or when origin/main cannot be read, every finding fails, which is the same gate as `npx knip`. A committed baseline file is not this gate: an empty-on-main baseline is a no-op after rebase, and a non-empty one would let main carry unused exports. `npx knip` on main stays at zero. Pins: `__tests__/knipDeadcodeGate.test.ts`, `__tests__/qualityGateWiring.test.ts`, `__tests__/handWrittenSourceFence.test.ts`.

<a id="a-generated-lane-may-ride-the-review-that-produced-it-and-nothing-else-may"></a>

- **A GENERATED LANE MAY RIDE THE REVIEW THAT PRODUCED IT, AND NOTHING ELSE MAY.** Two gates forbade every generator change between them. `scripts/run-with-restored-next-env.mjs` refuses a build that rewrites a tracked file, so a generator change HAS to carry its regenerated output; `scripts/check_review_scope.mjs` forbade every path under a generated lane, so carrying that output failed review scope. PR #1461 regenerated 610 `public/data/uk_base` files and was merged red on 4 September 2026, because there was no third answer. The third answer is EVIDENCE rather than an exemption: `REGENERATED_LANES` declares each lane's output beside the generator that writes it and the input it is cut from (`uk_base` today: `scripts/build_uk_base_shards.mjs`, its two index builders, `scripts/lib/ukBaseGrid.mjs`, and `data/osm/uk/**`), and the output is permitted ONLY in a diff that also changes one of them, which is exactly the diff a reviewer can check it against. FOUR rules. (1) A lane's permission covers THAT lane: a diff carrying the uk_base builder still fails on a changed `venues_slim` pack. (2) Output nobody in the diff produced stays forbidden, so a hand-edited cell is refused as before. (3) A skill pack is never permitted, whatever else the diff carries. (4) Permitted output leaves the HUMAN-REVIEW count (`reviewFileCount`), because a reviewer reads the generator and never 600 machine-written cells; the file-count and runtime-domain lines stay warnings, since a wide review is a judgement rather than a defect. Adding a lane means naming its generator and its input in that table, never widening a pattern. Pin: `__tests__/reviewScopeGuard.test.ts`.

<a id="every-gate-is-run-by-something-and-a-report-gate-runs-where-the-report-is"></a>

- **EVERY GATE IS RUN BY SOMETHING, AND A REPORT-GATE RUNS WHERE THE REPORT IS.** `gate:e2e-skips`, `gate:playwright` and `check:freshness` were all defined, all unit-tested against fixtures, and all invoked by nothing. The [common command reference](../../README.md) describes `verify`, whose complete sequence lives in `package.json`; `gate:playwright` judges a RUN, so it takes a Playwright JSON report and runs beside the browser suite in `.github/workflows/e2e.yml` rather than printing its usage line on every push. `__tests__/qualityGateWiring.test.ts` holds both halves. THREE rules ride with them. (1) A SKIPPED BROWSER TEST IS ARGUED OR IT IS REFUSED: `e2e/conditional-skips.allowlist.json` names the spec, the exact condition, the reason and what ENDS it, and a row matching no live skip fails the gate, so the list can only shrink; the two rows today are the CWV sweep and the plan capability-recovery lane. BOTH GATES READ THAT ONE LIST: the run gate takes it as `--skips-argued`, because it refuses every skip otherwise and the law-pin job would have gone red over a lane the source gate had already accepted, taking that spec's other proof down with it. An unargued skip still fails, and an allowlist the gate cannot read fails rather than passing quietly. (2) A FEED IS MEASURED WHERE ITS WRITER WRITES: the `weather` row dated itself by `public/data/weather/latest.json` while the 6-hourly cron writes `weather_snapshots`, and a Vercel filesystem is read-only, so that copy could only age and the check went red however healthy the cron was. The row is store-stamped now, the committed file stays as a `degraded-fallback` `artifactRole` that dates nothing, and `scripts/check_freshness.mjs` carries `DURABLE_FEED_SOURCES`, the table each durable feed really stamps. A store this runtime has no credentials for is UNMEASURABLE, never fresh and never stale: the plain run passes and says so, and `--require-store` makes it fatal where credentials exist. (3) A BUDGET IS A PROMISE SOMEBODY CAN KEEP: `food_price_updates` carried a 1440h budget while no script in the tree writes its artifact, so it went stale for ageing exactly as designed and the whole bar went red with it. A lane nothing can advance carries `stalenessBudgetHours: null` with the reason in its `gate`, the `night_signals` shape; it is never reported fresh, and adding a generator is a captain decision rather than a budget change. A NULL BUDGET WAS ONLY HALF THE ANSWER, AND A LANE WITH NO WRITER NOW SAYS SO IN ONE WORD: `untracked` reads as "not budgeted", which is a sentence about a lane somebody might still refresh, so `price_updates` and `food_price_updates` sat in the audit for weeks looking like work in hand. A row declaring `retired: true` reports `retired` in both readers, a FOURTH finding beside stale, unresolved and unmeasured, and it means exactly one thing: no producer for this lane exists in this tree, so no run is owed and none can be made. It is deliberately NOT what a closed `snapshot` lane says: `drink_price_updates` HAS a producer that runs weekly and comes back empty, and "a writer that finds nothing" and "no writer" are two different facts with two different fixes. Retiring a lane retires its REFRESH and never its artifact's integrity, so the retired check sits BELOW the unresolved-stamp branch and a served pack that goes missing is still a breach. The weather fence asserts the UNRESOLVED weather lines, which print on both branches, and proves never-fresh through `evaluateFreshness` on the weather row alone; it never asserts the exit code or the summary sentence of the whole spine, so one stale row cannot take an unrelated proof red again. Pins: `__tests__/postgresSuiteInventory.test.ts`, `__tests__/rlsSessionRunner.test.ts`, `__tests__/qualityGateScripts.test.ts`, `__tests__/qualityGateWiring.test.ts`, `__tests__/freshnessWeatherStore.test.ts`.

<a id="an-audit-waiver-is-a-documented-exception-not-a-mute-button"></a>

- **An audit waiver is a documented exception, not a mute button.** `npm run verify` ends in `scripts/resilient-audit.mjs`, which fails on high and critical findings, tolerates primary registry outages, and waives only advisories named in its `WAIVED_ADVISORIES` set, each with an inline rationale and a removal condition, and only while a second production-only audit proves the chain is dev-only. Add an entry there only after upgrades and `overrides` are exhausted; never hide an advisory by raising `--audit-level`, omitting dev dependencies, or skipping the step. Pin: `__tests__/resilientAuditWaivers.test.ts`.

<a id="the-no-mistakes-test-step-runs-npm-run-verify-as-its-own-command"></a>

- **The no-mistakes Test step runs `npm run verify:no-mistakes` as its own command.** The `commands` block in `.no-mistakes.yaml` sets `prepare` to `npm ci --prefer-offline` and `test` to `npm run verify:no-mistakes`, so the suite runs outside the evidence agent's 30 minute `test_agent_timeout`. The evidence agent still runs after it. The Push step commits what a step leaves in the worktree; `PUBMAX_VERIFY_COMMITTED_DATA=1` makes `scripts/prevalidate-data.mjs` skip the slim and UK builders so validation reads the committed shards instead of rewriting them, and `DEPLOYMENT_VERSION=local` keeps the committed `local` revision marker. `scripts/run-with-restored-bundled-data.mjs` restores committed bundled-data trees from HEAD after verify, and browser builds that set `PUBMAX_TRACKED_OUTPUTS=public/data` restore through `scripts/run-with-restored-next-env.mjs`. no-mistakes reads the `commands` block only from the copy on the remote main branch, so a change to it takes effect after merge. Never add the Playwright suite there. Pin: `__tests__/noMistakesTestCommand.test.ts`.
