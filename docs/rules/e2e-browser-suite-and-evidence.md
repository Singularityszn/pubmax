# The browser suite and browser evidence

Detail for [e2e/AGENTS.md](../../e2e/AGENTS.md). The area file keeps the short traps; this file keeps the full rules, their pins and their history.

## Driving the browser suite

- **Wait for the event.** Fixed sleeps and test-runner retries are forbidden. Web-first auto-retrying assertions (`expect(...).toPass()`) and auto-waiting locators are allowed.

- **Clock and theme setup follows the [browser-test traps](../../e2e/AGENTS.md#traps).** To test the default daytime appearance, use `holdLondonAfternoon` from `e2e/helpers/themeClock.ts` before the first navigation. Do not store a theme choice for that case, because a stored choice overrides the default under test.

- **`PUBMAX_TRACKED_OUTPUTS=public/data` allows a build's revision-stamp churn; it never keeps a pack change.** `scripts/run-with-restored-next-env.mjs` fails a wrapped command that changes a tracked file outside that comma-separated allowlist. When the allowlist names `public/data`, the wrapper also git-restores `public/data` from HEAD on exit, so commit a real pack change before a wrapped build or e2e run or it is discarded. Other allowlisted paths are only excluded from the dirty-tree check, never restored. Playwright's `webServer.env` sets it in CI (`playwright.config.ts`); a hand-started e2e server or local production build that rewrites `public/data` must export the same value or the wrapper fails on the stamped packs.

- **`npm run test:e2e`** (Playwright) needs the suite's Chromium in the shared browser cache. A lane never installs one (see "ONE BROWSER CACHE, ONE PLAYWRIGHT VERSION" below). On a fresh machine, the captain runs `npx playwright install --with-deps chromium` once. The e2e config builds and starts the app itself.

- **A hand-started server on the e2e port makes Playwright lie.** `playwright.config.ts` owns the env that lets keyless API routes run (`webServer.env`); without it a production build refuses the routes that write. Playwright reuses an existing listener on its port rather than starting its own, so a stray `npm run start` silently becomes the server under test and every later run inherits that gap. Free the port before a real run; to reuse a build deliberately, start it with the config's env and pass `PW_SKIP_WEBSERVER=1`. `PW_NEXT_DIST_DIR` moves the build directory, and the screenshot commands inherit the isolated wrapper's `NEXT_DIST_DIR` unless an explicit `PW_NEXT_DIST_DIR` wins. `webServer.env` pins `NEXT_PUBLIC_SW_VERSION=local` on purpose, so the pack build stamps every `public/data` venue pack `"revision":"local"`, the same stamp the committed packs carry.

- **Two workers share one hashed loopback IP, so the e2e server carries a test-only limiter allowance.** Production stays at 8 POSTs / 60s for `/api/plans/generate` and 60 / 60s across `/api/citymcp/*`. Under two Playwright workers those ceilings answer `429` and `expect(browserErrors).toEqual([])` fails even though the product is right. `webServer.env` sets `PUBMAX_E2E_RATE_LIMIT_MAX`; `lib/e2eRateLimitAllowance.ts` raises the in-process budget only when that env is a positive integer. Never change the production numbers. A hand-started server must carry the same env or the suite will 429 itself. Pin: `__tests__/e2eRateLimitAllowance.test.ts`.

- **A hand-started production server must mint Plan claims.** `PLAN_IDEMPOTENCY_SECRET` (or `RATE_LIMIT_SALT`) needs at least 32 bytes or `/api/plans/generate` answers `PLAN_SIGNING_UNAVAILABLE` 503. Playwright's `webServer.env` already generates a fresh 32-byte secret per run.

- **Bill fixtures must decode, and one helper attaches them.** The [bill attachment rule](lib-images-uploads-and-photo-walls.md#a-new-price-comes-with-the-bill-and-the-pint-photo-is-the-fun-one) owns which price doors require a bill. Specs that submit a bill use `e2e/helpers/priceBill.ts`. `attachBill` serves the one-tap door, and `attachSpillBill` serves the Spill composer. A picker change belongs in this helper, so every bill submission uses the same controls. `e2e/fixtures/bill.jpg` is a baseline JPEG that DECODES as well as validates: the old 131-byte file passed the server's byte sniffing but Chromium refused to paint it, so every shot of an attached bill was a broken-image box.

- **Manual planner testing is stateful and constraint-sensitive.** `/api/plans/generate` returns `422` when the intake carries must-have needs the area's data cannot satisfy: honest scarcity, not a broken environment. The intake and a route draft also persist across sessions in `localStorage`, so a prior run's constraints silently leak into the next. Run manual UI planner tests in a fresh or incognito profile; a low-constraint free-text request through "Describe instead" reliably yields a priced three-stop plan keyless. The e2e specs clear this state with `addInitScript`.

- **A browser test never guesses where a pin is.** The pins paint through the MapLibre canvas, so a spec cannot find one in the DOM, and a grid of taps hunting for one is a race the test loses under parallel workers. `components/map/canvas/paintedPinProbe.ts` publishes `paintedMapTapPoints` on `window`: the viewport point of every pin and cluster the map is drawing right now, each checked to have survived symbol collision, to re-query to the same mark, and to carry no app chrome on top of it. It is unconditional, like the `pubmax:pin-reveal` event beside it, because the browser suite runs a production build. The map opens with the pubs gathered, so a spec that wants a pin opens a cluster first. Pins: `__tests__/paintedPinProbe.test.ts`, `e2e/mobile-map-chrome-fit.spec.ts`.

- **COMMUNITY SHEET FIXTURE VENUE.** Specs that mock Pint Drops and assert community-only sheet state (price doors, trust chips, estimate pills) must use `COMMUNITY_SHEET_FIXTURE_VENUE_ID` from `e2e/helpers/communitySheetFixture.ts`, not `venue-1vle947` (The Sir Christopher Hatton gained harvested drink rows). `__tests__/e2eCommunitySheetFixtureVenue.test.ts` fails if that pub gains `uk_prices` or `drink_price_updates` rows.

- **A LONE CLICK IS NOT A WAIT FOR HYDRATION, and the dropped tap looks exactly like missing markup.** A control painted on the SERVER is tappable in the document before React attaches, so Playwright's own actionability check passes and the tap is dropped with nothing on screen saying so; the spec then waits out its whole budget and reports the surface the tap would have opened as ABSENT. That is how `/pal`'s `Meet your Pub Pal` was read as a heading main had deleted when the heading was there all along (#1464), and how `/plan`'s stop-count answered `aria-pressed=false` for a full assertion budget before. The idiom is to retry the TAP rather than assert harder on what follows it: `await expect(async () => { await control.click(); await expect(result).toBeVisible({ timeout: 1_000 }); }).toPass({ timeout: 20_000 })`, as in `e2e/plan-invite.spec.ts` and `e2e/mobile-button-system.spec.ts`. Before changing an assertion that a server-painted surface never appeared, open the page in a browser and click it: a page that answers there is right, and the spec's tap is the defect.

- **MAP TOOLBAR PICKS AND DESKTOP DRAWER WAITS HAVE ONE HOME EACH.** Venue suggestions live under the `Search suggestions` listbox, not bare `role=option` nodes elsewhere on the page; a slow runner also needs the slim index ready and may need to dismiss a pub-list Retry before the combobox fills. `e2e/helpers/mapToolbar.ts` owns `expectMapToolbarReady` and `selectFirstToolbarVenue`; `e2e/helpers/mapSurfaceDrawers.ts` owns the sole open desktop drawer poll (`expectSoleDesktopDrawer`). Pin: `e2e/map-surface-history.spec.ts`.

- **THE PHONE MAP SHELL HAS ONE READINESS WAIT, AND IT IS NEVER SHORTER THAN THE SHELL'S OWN CEILING.** Every control on the phone map (More map controls, Filters, the TfL chip, the map-edge column) mounts with the shell, and the shell is held until the map's loading frame lets go (`mobileShellReady` in `components/PubMap.tsx`). A pending basemap style can hold that frame through the style-load timeout and the fallback's answer, so the default 10s expect timeout raced it and flaked twice on CI (#2104). `e2e/helpers/mobileMapShell.ts` owns `expectMobileMapShellReady`, floored at `MAP_CANVAS_READINESS_CEILING_MS` and read from the product; a longer budget may be passed, a shorter one is raised. Call it after `goto` and before touching shell chrome. The canvas wrapper class is no readiness signal, because the loading skeleton carries it too. Reach a shell control (Search, Filters, More map controls, TfL, Near me) through `mobileMapShellControl`, which waits the same way and scopes the control to the shell, never by its class, by the More map controls name, off a top-bar locator, or (in a phone-only map spec) by a name the desktop shares. Pin: `__tests__/e2eMobileMapShellReady.test.ts`.

- **A SPEC THAT READS THE MAP'S OWN CREDIT ROUTES THE BASEMAP.** MapLibre's own credit control prints whatever the loaded style credits. When the live OpenFreeMap style fails or misses the 8s style-load timeout, the map takes CARTO and the credit changes. A layout pin then failed on a third-party server (layout shard 3, PR #2473). Install `installDeterministicMapBasemap` (`e2e/helpers/mapNetworkFixtures.ts`) and block the service worker, which otherwise fetches the OpenFreeMap host past `page.route()`. Its styles carry each provider's live credit (`LIVE_BASEMAP_CREDITS`), so the measured line is the one a reader sees. Fence: `__tests__/e2eBasemapFixtureCredits.test.ts`.

## Browser evidence for agents

- **Take shots, snapshots and page checks with the Playwright CLI.** `npm run e2e:cli -- <command>` runs `playwright cli` from the repo's own `@playwright/test`, so it uses the same Playwright and the same Chromium as the suite. It writes snapshots and console logs to disk and prints a link, so an agent reads only what it needs. Three evidence tasks cost 2,546 tokens on it and 24,003 on the DevTools route.
- **Command shape:** `PLAYWRIGHT_MCP_OUTPUT_DIR=artifacts/playwright-cli npm run e2e:cli -- -s=<lane> open --browser=chromium`, then `goto`, `route`, `screenshot --filename=artifacts/playwright-cli/<name>.png`, `snapshot --filename=artifacts/playwright-cli/<name>.yml` and `close`. Drive a private-port production build, as the rules above say. The artifacts folder is gitignored.
- **Pass `--browser=chromium` and the full folder in `--filename`.** The default channel is Chrome stable, which is absent here. The CLI resolves `--filename` against the working directory, not the output directory.
- **ONE BROWSER CACHE, ONE PLAYWRIGHT VERSION.** Never run a browser install or download from a lane, and never add the separate `@playwright/cli` package: its newer Chromium pruned the suite's revision from the shared cache and broke a running merge gate. A tool that needs another browser gets its own `PLAYWRIGHT_BROWSERS_PATH` under the artifacts folder.
- **A DESIGN CHANGE CARRIES A PROOF SHEET, AND ONE COMMAND TAKES IT.** `npm run proof:design -- --base-url http://127.0.0.1:<port> --page home=/ --page pub=/pubs/<venue-id> --out artifacts/design-proof/after --before artifacts/design-proof/before` shoots each named page at 390x844 (two pixels per point) and 1440x900, light and dark, chosen by the stored `pubmax-theme` preference rather than the clock, and writes one PNG per shot, named page, width and theme, plus one contact sheet in the same folder. `--before` lays an earlier run of the same pages above this one; `--full-page` shoots whole pages, cut at 1800 sheet pixels on the sheet. It refuses a `next dev` server: build and serve a private-port production build as the rules above say, or pass `--start` (and `--port`) to serve the build already on disk and stop it afterwards. It uses the repo's own Playwright and the shared browser cache; on a host whose cache holds another Chromium revision, point `PUBMAX_PROOF_PLAYWRIGHT` at an installed Playwright package that matches it. Design plan step 0.4 (`docs/plans/DESIGN_UX_PLAN.md`): every design pull request attaches the sheet. Code: `scripts/design-proof.mjs`, plan and layout in `scripts/lib/designProof.mjs`; pins: `__tests__/designProof.test.ts`.
- **Fallback: `chrome-devtools-axi`,** for Lighthouse, performance traces and heap snapshots, which the CLI does not have. With no Chrome, point `CHROME_DEVTOOLS_AXI_BROWSER_URL` at a Chromium started with `--remote-debugging-port`. In 0.1.34 its `wait` and `run` fail with `fn is not a function`; wait with an `eval` of a Promise.
