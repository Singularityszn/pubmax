# Tile CDN decision: measured and dropped (3 October 2026)

The September performance review recorded the first basemap tile at 8,568 ms
on a cold `/map` under its phone rig (390x844, 4x CPU throttle, Chrome Slow
4G) and listed a tile CDN as a paid option: put our own edge in front of
`tiles.openfreemap.org`, described there as "a third party with nothing of
ours in front of it" serving `public, max-age=86400`. The proposal was a
Google Cloud external load balancer with Cloud CDN and an internet NEG at
`tiles.openfreemap.org`, behind `tiles.pubmaxxing.com`.

It was measured before anything was built, and it was dropped. No Google
Cloud resource was created.

## What was measured

OpenFreeMap already sits behind Cloudflare. Every response carries
`server: cloudflare` and a `cf-ray` ending in `-LHR`, so it is served from
London.

| response | `cache-control` | edge |
| --- | --- | --- |
| tile `/planet/<version>/{z}/{x}/{y}.pbf` | `public, max-age=315360000` (10 years) | `cf-cache-status: HIT` |
| style `/styles/dark` | `public, max-age=86400` | `HIT` |
| TileJSON `/planet` | `public, max-age=86400` | `HIT` |

The `max-age=86400` the review saw belongs to the style and TileJSON, not
the tiles.
Tile URLs carry a dated build path, so they are immutable and cached for ten
years at Cloudflare and in the browser.

Timings from a London Mac with curl, a fresh connection per request (DNS,
TCP and TLS included):

| request | time |
| --- | ---: |
| style `/styles/dark` | 53-137 ms |
| TileJSON `/planet` | 55-139 ms |
| London tile at z11, Cloudflare HIT | 80-299 ms |
| never-viewed tiles at z13 and z14, Cloudflare MISS | 84-187 ms |

The whole network chain from style to first tile is about 200-350 ms cold,
before the phone throttle. A second CDN in front of Cloudflare cannot win
back more than a few tens of milliseconds of it, and on its own cache miss
it adds a hop (Google edge, then Cloudflare, then origin).

## Why it was dropped

1. **The tile is not the slow part.** The review's own timeline, cold, on
   the throttled rig: the MapLibre chunk lands at 4,939 ms, the map object
   exists at 6,562 ms, the style is parsed at 7,304 ms, the scene is built
   at 7,915 ms and the first tile paints at 8,568 ms. The last 650 ms is
   mostly vector-tile decode on a 4x-throttled CPU, which a CDN does not
   touch.
2. **A new host costs a handshake.** `app/layout.tsx` already preconnects to
   `tiles.openfreemap.org` during HTML parse. A `tiles.pubmaxxing.com` host
   would need its own preconnect, CSP entries in `proxy.ts`, the
   service-worker tile host in `public/sw.js`, and a GoDaddy DNS record.
3. **It costs money and expires.** A global external load balancer
   forwarding rule is about USD 0.025 an hour, about USD 18 a month before
   egress. It was to run on the Google Cloud free trial, which is not to be
   upgraded. When the trial lapses, the load balancer stops serving, and a
   map pointed at it waits out `STYLE_LOAD_TIMEOUT_MS` (8 s,
   `components/map/canvas/tokens.ts`) before falling back to CARTO. That is
   slower than today.

Warm visits already skip the wire: `public/sw.js` keeps OpenFreeMap tiles in
a bounded stale-while-revalidate cache.

## Where the first-paint time actually is

These are the changes that move the cold `/map` timeline. File references
are as of this date. Re-measure on the CWV rig (`docs/perf/baseline-2026-09-05.md`)
before and after each one.

1. **Take the MapLibre chunk off the critical path.** It is the largest
   single cost, landing at 4,939 ms. `components/PubMap.tsx` loads
   `components/PubMapCanvas.tsx` through `next/dynamic`, and
   `PubMapCanvas.tsx`, `components/map/canvas/donutClusters.ts` and
   `components/map/canvas/useMapCamera.ts` all import the full
   `maplibre-gl` namespace. Start that download from the prerendered `/map`
   document `<head>` with a `modulepreload` for the canvas chunk, so it runs
   in parallel with the shell instead of after hydration. Read
   `__tests__/mapEarlyWarm.test.ts` first: the earlier eager warm that was
   reverted fetched data early, not the engine. Review estimate:
   1,500-3,000 ms.
2. **Warm the chunk from the landing on intent.** `components/nav/IntentLink.tsx`
   already warms routes on hover and touch. Extend the same intent to the
   map canvas chunk from the landing's map entry, so a reader arriving from
   `/` finds MapLibre already parsed. Measure the landing's own LCP beside
   it, because these are bytes in front of the landing's answer. Review
   estimate: up to 4,900 ms on that path.
3. **Ship the style JSON with the app.** `MAP_STYLES` in
   `components/map/canvas/tokens.ts` is a URL, so `new maplibregl.Map` in
   `components/PubMapCanvas.tsx` waits on one more cross-origin request
   before it can ask for TileJSON, sprite and glyphs. A committed copy of
   the dark and positron styles, served from our origin or inlined as an
   object, removes that round trip. Style updates then need a deploy.
   Review estimate: 150-400 ms.
4. **Shorten construction to first frame.** 6,562 ms (map constructed) to
   7,915 ms (scene built) is style parse, sprite decode and layer setup in
   `components/PubMapCanvas.tsx` (marks `pubmax:map-constructed`,
   `pubmax:map-style-load`, `pubmax:map-icons-ready`). Profile that
   window under the 4x throttle; rasterising pin icons in
   `lib/mapIcons.ts` before the style resolves, rather than after, is the
   first candidate.
5. **Keep the pin entrance off the critical path.** Phones already skip the
   ramp (`phoneFirstImpression` in `components/PubMapCanvas.tsx`) and the
   ramp has a ceiling (`PIN_ENTRANCE_SETTLE_CEILING_MS` in
   `components/map/canvas/tokens.ts`). Any new entrance animation must keep
   that shape: the review measured the old ramp at 1,948 ms cold on the rig
   against a 400 ms specification.

## Revisit when

A tile CDN is worth re-measuring only when the first tile is the last thing
the reader waits for and the network chain is a measurable share of it, or
if OpenFreeMap's availability becomes a problem. Re-measure the `cf-cache-status`
and `cache-control` headers first; if they still read HIT and ten years, the
answer is unchanged.
