# The native shell (iOS, and the seams both platforms share)

The Capacitor wrap: the seams gated on `isNativeApp()`, the iOS capabilities and the store review. The Android half is [android/AGENTS.md](../android/AGENTS.md), and every capability is stated in both.

Repo-wide laws and the index of every other area file are in the root [AGENTS.md](../AGENTS.md).

## Shell seams and iOS capabilities

- **The native shell is the site plus a few seams, and every one is gated on `isNativeApp()`.** `lib/nativePlatform.ts` is the only Capacitor probe. `nativeBackGesture` (Back is a panel, then `history.back()` into the surface trail, then exit), `nativeHaptics` (a closed occasion table, never a raw intensity, silent under reduced motion), `components/native/NativeShellChrome.tsx` + `components/native/nativeShell.css` (`[data-native-shell]` on `<html>`, adding the long-press callout and overscroll rules and deliberately NO selection rule and NO safe-area inset, both of which are owned elsewhere), `nativeDeepLinks` (which EXPORTS the route families that `public/.well-known/apple-app-site-association` and the Android manifest are then held to) and `nativePush`. `lib/nativeCamera.ts` is the ONE photo seam, taking its SURFACE by name (`moment` | `pint` | `venue`), because the file name it builds is what a person's phone hands over; its sheet stays the plugin's Prompt source, offering Camera and Photo Library together, which is the native reading of the picker law in `__tests__/profilePhotoPicker.test.ts` rather than an exception to it, and every surface keeps its web file input for off the shell. THE iOS CAPABILITIES ARE FILES: `ios/App/App/App.entitlements` carries `aps-environment` and `applinks:pubmaxxing.com` and both build configurations set `CODE_SIGN_ENTITLEMENTS`, so adding one by hand in Xcode writes a SECOND entitlements file and the two then disagree; `ios/App/App/PrivacyInfo.xcprivacy` is the machine-readable half of STORE_READINESS section 5 and must move with it. Neither a missing entitlement nor a bare WKWebView chooser is reproducible in a browser, so both are held by source fences. Store copy is `lib/storeListing.ts` with each field's limit beside it; screenshots are `npm run gen:store-screenshots`, which refuses a dev server and is shot at `BASE=https://pubmaxxing.com`, because the shell is a remote-URL wrap of that site and a keyless local server puts a listings error in the Tonight shot. THE iOS BUILD IS `npm run ios:build` AND `npm run ios:run` (`scripts/ios-simulator.mjs`), and it is a script rather than one command because the obvious command is wrong here: Capacitor 8 generated a Swift Package Manager project, so there is NO Podfile and NO Xcode workspace file, `xcodebuild` takes `-project ios/App/App.xcodeproj`, and `ios/App/CapApp-SPM/Package.swift` names each plugin by a relative path into `node_modules`, so `npx cap sync ios` has to run first or the previous plugin list compiles. A green simulator build proves the code and the remote-URL wrap, never the entitlements, because a team-less build writes an EMPTY entitlements file. Pins: `__tests__/native*.test.ts`, `__tests__/iosCapabilities.test.ts`, `__tests__/storeAssets.test.ts`; runbooks `docs/STORE_READINESS.md` (section 8 is the ordered Saturday checklist) and `docs/CAPACITOR_WRAP.md`.

- **A CAPACITOR PLUGIN IS A PROXY, AND THREE SEAMS HANDED IT TO AN `await`.** Mobile design review 7 Sep 2026, measured through the Android WebView's own DevTools: `registerPlugin()` returns a Proxy whose EVERY property is a native method, `then` included, so `return Share` from an `async` loader made the await look for a thenable, call `Share.then()` on the native side and reject with `"Share.then()" is not implemented on android`. `lib/nativeShare.ts` (the OS share sheet, which therefore never opened on either platform and every share fell to its web fallback), `lib/nativeReviewPrompt.ts` (the store review, which was never requested and, because the loader failed BEFORE the marker, never spent) and `lib/nativeOAuth.ts` all did it, and their unit tests injected plain fakes, which is why nothing caught it. A loader hands back a plain object that closes over the plugin, and `__tests__/capacitorPluginProxy.test.ts` drives every DEFAULT loader against a proxy shaped like the real one and sweeps `lib/native*.ts` for a `return <Plugin>;`. TWO seams ride on the same review. (1) THE ANDROID WEBVIEW HAS NO `navigator.share`, and nine surfaces call it directly rather than through `lib/shareSheet.ts`, so inside the shell each took its own fallback (the Tonight button copied a link in silence, or said "Could not share tonight" on a cleartext origin); `lib/nativeWebShareBridge.ts` fills the API over the plugin from `components/native/NativeShellChrome.tsx`, a fill and never an override (WKWebView ships the API and keeps it), rejecting a dismissed sheet with the same `AbortError` the web throws. (2) THIRD-PARTY SIGN-IN OPENS THE SYSTEM BROWSER INSIDE THE SHELL: Google refuses OAuth in an embedded web view (403 `disallowed_useragent`), so `lib/nativeOAuth.ts` asks supabase-js for the provider URL (`skipBrowserRedirect`) and hands it to `@capacitor/browser`; the provider returns to `/auth/callback`, already a universal link and an App Link, which lands in the shell's own WebView holding the PKCE verifier, and `lib/nativeDeepLinks.ts` closes the system browser when that link arrives. Off the shell the web call is byte for byte what it was. (3) THE SHELL FOLLOWS THE OS TEXT SIZE: iOS's Larger Text reaches only `-apple-system-body` text and this app's type is CSS px, so the setting did nothing, while the Android WebView zooms every node and the six-tab bar's labels ran into each other at 2.0x. `lib/nativeTextScale.ts` asks WebKit for the preferred size through `@capacitor/text-zoom` (clamped to 2.0, Android's own ceiling), reads the zoom Android already applied, and publishes the bucket as `data-text-scale` on `<html>`, which is what the tab bar (icons alone, the accessible name staying on the link) and the consent card (no ceiling) change shape on. Pins: `__tests__/capacitorPluginProxy.test.ts`, `__tests__/nativeWebShareBridge.test.ts`, `__tests__/nativeOAuth.test.ts`, `__tests__/nativeTextScale.test.ts`; proof `docs/proof/mobile-app-design/`.

- **A STORE REVIEW IS ASKED ONCE EVER, AND THE PLATFORM'S OWN DIALOG IS THE WHOLE UI.** A rating ask is the only prompt the app does not ration: iOS allows `SKStoreReviewController` about three times a year per device and SILENTLY IGNORES every request past that, resolving exactly as a shown dialog does, and Play In-App Review holds its own hidden quota the same way. So no runtime signal can tell a wasted ask from a spent one, and a request at the wrong moment burns the one chance a good moment had. `lib/nativeReviewPrompt.ts` is the ONE place that timing rule lives, in the `lib/nativePushPrompt.ts` idiom: a pure `shouldRequestStoreReview` gate over a plain state record, localStorage around it, and `@capacitor-community/in-app-review` behind a dynamic import gated on `isNativeApp()`. FOUR rules. (1) ONCE EVER, with no re-ask and no snooze, so `hasAskedForStoreReview()` is permanent and the marker is written BEFORE the plugin call, because a rejected promise says nothing about whether the OS drew anything and reading it as unspent is what turns one ask into many. (2) ONLY AFTER A KEPT ACTION AND NEVER THE FIRST: `KEPT_ACTION_KINDS` is the closed table (`price-logged`, `plan-kept`), a kind outside it counts as nothing, and `REVIEW_PROMPT_KEPT_ACTION_FLOOR` is 2 because the first kept action is a coin flip the quota cannot afford. (3) THE OS DIALOG IS THE WHOLE UI: no stars, no pre-prompt and no words asking for a GOOD rating, which App Store Review Guideline 1.1.7 and Play policy both forbid, and the fence sweeps the tree for that copy rather than listing files, while leaving the DRINK star rating in `components/ratings` alone. (4) TWO in-memory latches, because the plugin load is AWAITED and two kept actions in one tick would otherwise both reach the OS: `askInFlight` is claimed before the await and released only when the plugin could not be loaded, the one outcome that spends nothing. A community plugin is wired by the same `npx cap sync` and fails in the same silence as an official one, so `__tests__/nativeShare.test.ts` now holds BOTH scopes to the two generated native manifests. Pins: `__tests__/nativeReviewPrompt.test.ts`, `__tests__/nativeShare.test.ts`.

- **A PHONE THAT LOSES SIGNAL, A PHONE THAT SHARES, AND A PHONE THAT THROWS.** Three seams the WebView shell owes every route rather than one. (1) OFFLINE IS OWED TO EVERY ROUTE: `components/OfflineReady.tsx` registers the worker where its API is available, on TWO triggers and the earlier one wins, `pubmax:first-pins` where the map fires it and a deferred idle pass anywhere else, because the shell cold-starts on /tonight (`lib/entryDecision.ts`) and a reader who never opened /map used to register nothing at all. The fallback is held back by `OFFLINE_REGISTER_FALLBACK_DELAY_MS` rather than armed at the first idle moment, because on /map the first idle moment IS the cold path the first-pins gate protects. (2) THE OS PICKER IS ASKED FIRST INSIDE THE SHELL: the Web Share API is absent from the Android System WebView, so `navigator.share` answered nothing there and every share became a wa.me link. `lib/nativeShare.ts` is the seam and it NEVER gates the share, answering `unavailable` off the shell and on every failure so the web path is untouched; a dismissed sheet is `cancelled`, never a WhatsApp tab forced open behind it, and iOS says so with its own message `Share canceled` rather than an AbortError. `__tests__/nativeShare.test.ts` also holds both generated native manifests to package.json's plugin list, because `npx cap sync` is not optional and skipping it fails in silence. (3) A CLIENT ERROR IS REPORTED REDACTED AND STORED NOWHERE: `lib/clientErrorReport.ts` is the ONE definition of redacted, the route name is the closed pageview vocabulary rather than a URL so a handle or a plan id is templated out by construction, and REDACTION HAPPENS TWICE because a direct POST is not the reporter. `POST /api/client-error` spends a per-IP `isLimited` budget, bounds the body, answers 204 to everything including its refusals, and writes ONE `[pubmax-client-error]` log line: no table, no SDK, no consent identity, and therefore no privacy-form change. It is not analytics and may never grow a field that would make it one. Doc `docs/analytics/CLIENT_ERROR_REPORTING.md`; pins `__tests__/offlineReadyRegistration.test.tsx`, `__tests__/nativeShare.test.ts`, `__tests__/clientError*.test.ts*`.
