# Policy modules, stores and shared leaves

Rules whose subject is a module under `lib/`: the closed vocabularies, the policy leaves and the stores. `lib/harvest/*` is governed by [scripts/AGENTS.md](../scripts/AGENTS.md), because the harvest CLIs and the source policy are one rule.

Repo-wide laws and the index of every other area file are in the root [AGENTS.md](../AGENTS.md).

## Identity, accounts and sessions

- **The password ask is separate from password creation.** `CreatePasswordPrompt` runs in the deferred shell under the shared prompt budget. `lib/passwordPrompt.ts` owns its once-per-account marker and offers it only after a claimed handle and `hasPassword: false` answer. `SetAccountPassword` remains the only password setter. Pins: `__tests__/passwordPrompt.test.ts`, `__tests__/createPasswordPromptRender.test.ts`.

- **The signed-in account is the only identity authority on a device.** `lib/deviceAccountIdentity.ts` owns the artifact set and the owner stamp; `AuthProvider.updateSession` rebinds it on every auth event before children re-render, and a different or unstamped account loses the whole set atomically. Sign-out drops set and stamp together, in that order. Identity is TRI-STATE: a surface that NAMES or ROUTES the viewer stays neutral until the live session answers, never a cache, never a confident "nobody" from a failed read (`components/auth/useViewerHandle.ts`, `components/auth/useViewerSession.ts`, and the shared `providerHasAnswered` in `lib/authProviderRevision.ts`, which only `authenticated` or `signed-out` pass). `ensureSupabaseBrowser()` can REJECT, so `lib/authClientLoad.ts` retries it and answers `unavailable`, and `bootstrapAuthSession` preserves failed reads the same way, publishing nothing and asking for `requestDeploymentSkewCheck`. A Night Profile MIRRORED off an account leaves with it; one typed here stays. Writes announce themselves, because a same-tab `localStorage` write raises no `storage` event. Every browser write to an actor-gated route sends its bearer token so the SERVER derives the actor (`resolveMessageHandle` + `gateHandleAction`). - **A device may hold several accounts, and exactly one of them owns it.** `lib/deviceAccountSessions.ts` is the lane: one key, one REFRESH token per account id, capped at `MAX_DEVICE_ACCOUNTS`. An outcome is THREE-WAY: a token GoTrue REFUSED is deleted and its row reads "Signed out"; a read we could not run keeps the token. Sign-out is SCOPED (`SignOutScope`), offered only above one account, and awaits `clearPersistedSession`. `components/auth/AccountDeviceControls.tsx` is the ONE control, shared by the nav card and /login's signed-in card, because `.siteNavBar .authUser` is hidden at 640px; `/login?add=1` is the only thing that makes a live session see the form; a held profile card carries the HANDLE it is about.
