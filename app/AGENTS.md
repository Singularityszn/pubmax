## API contract and rate limits

- **The daily price cap has TWO enforcers, and it is a ROUTE's rule rather than the table's.** Pentest finding F-1: `hasPricedDropToday` followed by `create` is a check-then-insert with nothing underneath it, so a concurrent burst walked straight through the stated "one price per pub each day" rule (eight simultaneous priced POSTs, six rows, one authority key, so nothing corroborated and nothing moved). The pre-check STAYS and stays deliberately fail-open, because it gives the ordinary refusal without spending a failed insert; the hard guard behind it is `pint_drops_priced_day_unique_idx` (migration `0141` + rollback). THREE rules. (1) THE BUCKET IS A COLUMN, never an expression: `timezone(text, timestamptz)` is only STABLE so a London day cannot anchor an index, and a UTC day is the WRONG day in both directions under BST, so the writer stamps `price_day` with the same `londonDayKey()` the pre-check compares against and the two enforcers cannot read one day differently. The migration's backfill claims the EARLIEST row of each existing bucket, because the rows the finding is about are already in the table and a naive backfill would fail the index build. (2) THE CAP GOVERNS THE LANE THAT STATES IT: `create` takes `underDailyPriceCap` (`PintDropCreateOptions`) and only `POST /api/pint-drops` opts in, because `POST /api/price-submit` pairs a Pint Drop with every community price a drinker sends and takes several from one account at one pub in one day on purpose, with its own rate limiter as the brake. A guard over every row would refuse the second of those. Whether the pairing lane should share the cap is an open product question, not a bug. (3) ONE SENTENCE: `DAILY_PRICE_CAP_REFUSAL` is spent by the pre-check and by the `PintDropDailyCapError` the store throws, so a drinker cannot tell which enforcer turned them away, and that refusal logs as `pint_drops.daily_cap_conflict` rather than as an outage. Pins: `__tests__/pintDropDailyCapAtomicEffective.test.ts` (real PostgreSQL 16, eight writers released at one instant, before and after the migration), `__tests__/pintDropDailyDedupe.test.ts`, `__tests__/pintDrops.test.ts`.

- **An API error is one envelope, and every mutating route is rate limited.** Every 4xx and 5xx JSON body from `app/api` goes through `publicApiError` (`lib/apiError.ts`; `publicApiErrorFromStatus` when a shared gate decided the status), and extra reader-visible fields ride `compatibilityFields`, never a bespoke shape. A 2xx fail-soft payload may carry an `error` field beside real data; that is not an error response. Cron routes authenticate with `assertCronRequest` (`lib/cronAuth.ts`) instead of a limiter; every other mutating route consults `isLimited` (`lib/pintDrops.ts`, per-IP keys, neighbours' budgets) or a named delegation such as `socialCrewActor`. `__tests__/theLocalErrorContract.test.ts` sweeps every route plus one level of local helper imports and fails on a rogue emitter or an unlimited mutating route. A MUTATING ROUTE OUTSIDE `app/api` IS STILL A MUTATING ROUTE: `/ingest` (`app/ingest/[...path]/route.ts`, the owned PostHog proxy) lets any caller POST up to 1 MB into the billed EU project, so it spends a per-instance in-memory `ingestRateLimited` budget keyed on the hashed address (240 a minute, named in `__tests__/posthogProxyRoute.test.ts`) before it reads a body - not the durable `isLimited`, because the proxy must make no Supabase call at request time and the durable limiter's degraded mode tightens to 3 a minute during the very outage the telemetry reports. That budget lives in the leaf `lib/ingestRateLimit.ts`, and the route reaches its caller's address through the pure leaves `lib/clientIpTrust.ts` and `lib/rateLimitHash.ts` rather than `lib/supabase.ts`, so the Supabase client is not traced into the bundle of the route every browser event and asset fetch hits. The limiter imports nothing, compares before it records so a refused address cannot grow its own window, and drops a key once every hit in it has expired so a flood of distinct addresses leaves no permanent entry behind (`__tests__/ingestRateLimit.test.ts`) - and the same sweep reads it because it now walks the whole `app` tree rather than `app/api` alone, which is how the proxy shipped unauthenticated and unlimited in the first place. It is not an envelope route, because a browser SDK reads its status and never a JSON body, and it keeps its origin pin, its content-type allow-list and its 1 MB cap.

- **AN UNKNOWN ADDRESS ANSWERS THE ENVELOPE, AND A DELETE STILL ANSWERS AFTER THE ACCOUNT HAS GONE.** Two API contract slips verification scout verify-preview-4 measured on a production build (section 7.3 and observation 9), and each is a rule rather than a patch. (1) NEXT TREATS A FORM-ENCODED OR MULTIPART POST TO A PATH NO ROUTE HANDLER CLAIMS AS A SERVER ACTION INVOCATION: it looks the action id up in the body, finds none and throws, so a mistyped multipart `POST /api/avatar` answered a 500 HTML page (`Failed to find Server Action`) while the same address answered 404 to a GET. THE CONTENT TYPE DECIDED THE ANSWER, which is a promise no caller can read. `app/api/[[...unmatched]]/route.ts` is the API tree's own 404: an OPTIONAL catch-all, so bare `/api` is claimed too, sitting below every real route and answering one `publicApiError(..., 404)` for every method. Because a handler MATCHES, the Server Action lookup never runs. It is a REFUSAL and not a write surface, so it takes no authority boundary and spends no rate-limit budget (one on an unknown address would make a typo cost more than a real request), and both tree-wide fences record that as a PROOF rather than a listing: the route may import nothing but `@/lib/apiError` and each handler's whole reachable source must be the single refusal call. Scope is `/api` alone, because the flat envelope is a contract with a CALLER and a browser is owed `app/not-found.tsx`. (2) A DELETE IS IDEMPOTENT, SO ITS DOOR MUST ANSWER AFTER THE AUTH ROW IT NAMES HAS GONE: `DELETE /api/account` resolved its caller with `callerUserId`, which asks GoTrue for the ACCOUNT, so the first delete removed the row and every repeat with the same unexpired bearer read as `user_not_found` and answered 401, leaving the documented 410 `already-gone` unreachable for the life of the door. It asks `verifyCallerAuth(request, { localOnly: true })`, the local JWKS lane, so a deleted account is still NAMED by its own token; the seam in `__tests__/accountDeletionRoute.test.ts` records the options it was asked with, so a return to the account lane fails there. THAT OPTION IS THIS DOOR'S ALONE, AND THE DEFAULT IS REVOCATION (review finding F-3): #1501 made the local lane the DEFAULT to spare a messaging poll a round trip, and `getClaims` checks a signature and an `exp` and nothing else, so a token whose account had just deleted itself still passed the contribution gate on every price write, the Social 18+ gate, both plan-seat claims and the session refresh for the rest of its hour - while the messaging routes it was written for never took the saving, `callerUserId` needing account metadata and always having asked GoTrue. `verifyCallerAuth` asks GoTrue unless a caller passes `{ localOnly: true }`, and `__tests__/authServerVerification.test.ts` sweeps `app`, `lib` and `components` so exactly one file may. A verification we could not RUN is its own answer, a retryable 503 `AUTH_UNAVAILABLE`, because `callerUserId` collapsed absent, invalid and unavailable into one null and telling somebody who is signed in that they are not is the one thing this door may not say. Pins: `__tests__/apiUnmatchedRoute.test.ts`, `__tests__/accountDeletionRoute.test.ts`, `__tests__/writeSurfaceCertification.test.ts`, `__tests__/theLocalErrorContract.test.ts`; proof `docs/proof/api-envelope-contracts/`.

## Proxy, CSP, caching and file tracing

- **A file a route opens at runtime is not in the deployed function unless you say so.** Next traces only paths it can see statically, so any route that builds a path at request time ships without its data. Declare such files in `next.config.mjs` `outputFileTracingIncludes`, derived from their registry rather than hand-copied. WHICH freshness artifacts ship is one predicate, `datasetOpensArtifact` (`lib/freshness.ts`), mirrored by `lib/freshnessTracing.mjs` and `scripts/check_freshness.mjs`; an untraced pack is the dangerous case, because the file is simply absent and the reader falls back to the registry's literal stamp and reports the feed fresh for ever. A STATICALLY PRERENDERED route needs no key at all, so `/sitemap.xml` reads its packs at build and a bad pack fails `next build` rather than serving a 500. The ROUTE list is derived as well: `RUNTIME_DATA_PACKS` in `lib/venueIndexTracing.mjs` names each module that assembles a data path at request time with the files it can open, the reader routes come from the source import graph, and a hand-written key for such a route merges with the derived one instead of replacing it. Then mark the declared dynamic path operation with Next's `turbopackIgnore` comment so automatic tracing does not widen the route to the whole repository; the comment never replaces the explicit include. `__tests__/venueIndexTracing.test.ts` fails when a reader is undeclared, and also when ANY route-reachable module hands `fs` a path it assembled unless that module is a declared pack, is named in `RUNTIME_PATH_MODULES_TRACED_ELSEWHERE`, or is carried in `RUNTIME_PATH_MODULES_PENDING_DECLARATION`, a documented exception whose list may only shrink. That is why the pack table lives in `lib/cityVenuePacks.mjs`: the config cannot import TypeScript, so a city added to `lib/cities.ts` alone would browse in the app and be missing from the deployed function. Venue-detail lookup must preserve `unavailable` through `/api/venue/[id]` as a 503, never collapsing missing runtime data into an unknown pub. `/bar-tab/[id]` and `/ledger/[id]` read the venue three ways for the same reason, so a dataset or alias read that FAILED is never cached and never worded as an unknown pub (`__tests__/venuePageReadUnavailable.test.tsx`). To check a real build rather than guess, read `.next-prod/server/<route>/route.js.nft.json`, the exact file set that function ships with. Pins: `__tests__/freshnessTracing.test.ts`, `__tests__/feedTracing.test.ts`, `__tests__/venueRoute.test.ts`, `e2e/map-unknown-selection.spec.ts`.

- **THE ANSWER IS A PUB PEOPLE ARE TALKING ABOUT, THEN OUR OWN LISTINGS, THEN AN HONEST QUIET NIGHT.** Captain 7 September 2026, over a hydrated `/tonight` that led with "Deals tonight, Small Plates Club, J D Wetherspoon" while `/api/whats-on` served 96 Wetherspoon deal rows and 24 Ticketmaster events. THE LEDE REGION is a DOM region (`data-testid="tonight-lede"`) and only three things may fill it, in this order: the hyped pubs from `lib/hypedPubs.ts`, the independent listings, and the quiet-night sentence. FIVE rules. (1) NO CHAIN AND NO TICKET PLATFORM MAY LEAD. `lib/tonightPrimary.ts` already refused Wetherspoon and Ticketmaster; `withoutTonightChainRows` (`lib/tonightChainLanes.ts`) now takes Greene King too, whose 259 bundled sport fixtures each say in their own detail line that the pub has not confirmed the screening. The lane is read off the PUBLISHER, never the title. (2) THE CHAIN KEEPS ITS SUPPLY AND LOSES THE FRONT ROW: one labelled block per chain under the lede ("Wetherspoon deals tonight", "Greene King tonight"), carrying the chain's own source label and the day that page was read, folded after three, and grouped by OFFER through `groupTonightListings` so one promotion across 96 pubs is one row saying how many pubs run it. A chain row leaves the generic Deals lane in the same move, because one offer under two headings is the same offer counted twice. (3) A QUIET NIGHT WAS CHECKED, AND THE CHIP SAYS WHEN: with no What's-On row on screen, `tonightWhatsOnObservedAt` dates the quiet reading from the live read's own `kindObservedAt`, oldest kind first. The old answer was null, so a read that had just dated 120 rows printed "No date on this yet". A read that dated NOTHING still answers null. (4) A QUIET NIGHT ANSWERS WITH PUBS, NOT CHIPS: `lib/tonightCheapPints.ts` puts the cheapest listed pints above the soft plans and the vibe chips. It is NOT a "quieter pubs" list, and may never become one: the F02 ruling in `lib/AGENTS.md` settles that no per-venue quiet reading exists in this product. It holds ONE ROW PER CHAIN, the chain named on that row, and the chain is read off a source (the Wetherspoon membership in `tonightWetherspoonVenueIds`, which is the directory join in `lib/wetherspoonsMatch.ts` or the SpoonMe pack, the pub's own website host, or the price listing naming the operator), never off a name (site audit D17). The lede wrapper holds the lede and nothing else; the rail is ONE element after it in the DOM holding, in order, the rail summary, the cheapest listed pints, the chain blocks, the vibe chips, the phone Deals and Music lanes, the editorial rail, the soft plans and the area news, so a phone keeps its base order. From 1100px that element spans every desktop grid row down to a flexible last row, so the two columns share no row height and the rail has no gap (site audit D8; firstmate ruled on 13 Sep 2026 that the editorial rail lives in the desktop rail, because a rail split around the column left about 1,000px of it empty beside the lede). (5) THE PACK IS READ AT BUILD, in `app/tonight/page.tsx`, because the document is prerendered and a lane a reader may never see must cost no request. Pins: `__tests__/tonightHypedLede.test.ts` (a hydrated DOM, not static markup, which is how every earlier fence stayed green over this defect), `__tests__/tonightChainLanes.test.ts`, `__tests__/tonightQuietChipDate.test.ts`, `__tests__/hypedPubs.test.ts`, `__tests__/tonightCheapPints.test.ts`, and for the rail and the one row per chain on a real DOM, `e2e/tonight.spec.ts`.

- **A tab you have already opened is not a page you have to fetch again.** Every route here is dynamic because of that nonce, and Next's default client Router Cache window for a dynamic route is ZERO. `experimental.staleTimes` in `next.config.mjs` owns that window, and `__tests__/clientRouterCache.test.ts` owns the two invariants that make it safe: NO page server-renders per-account content, and NOTHING calls `router.refresh()`, so a held payload can neither name the previous account nor hide a write. `/admin` is the ONE argued exception to the first invariant and is named in the fence itself (`PER_SESSION_SERVER_PAGES`), never granted quietly: its refused document carries NO account content, nothing in the tree links to it so no soft navigation can serve a held payload around the guard, and every `/api/admin` read re-gates on the same credential. A second such exception is a re-derivation of the whole window. `router.refresh()` is not forbidden, but reaching for it means a server surface has started carrying mutable state, and then the window is re-derived in the same commit. The DATA behind a tab is the second half: `lib/surfaceDataCache.ts` is ONE in-memory stale-while-revalidate store. It REFUSES an auth, identity or admin key outright rather than declining quietly, holds nothing on the server (a `"use client"` module still executes there, and one module Map would be shared by every request), ages entries out so a snapshot may seed a paint but never stand in for an answer, and leaves with the account on `DEVICE_IDENTITY_CHANGED_EVENT`. A surface that declares `no-store` keeps its own lane and is never cached. Third half: a link to a DYNAMIC route is warmed on INTENT, never prefetched on sight (`components/nav/IntentLink.tsx`), because a Tonight arrival otherwise fired about twenty server renders in front of the listings the reader was waiting for. Pins: `__tests__/clientRouterCache.test.ts`, `__tests__/surfaceDataCache.test.ts`; method and figures in `docs/PERFORMANCE_BUDGETS.md`.

- **Exactly five documents are exempt from the nonce, and the list is the fence.** Captain decision 2026-08-09, widened 2026-09-05 ("Widen"): `CDN_CACHED_DOCUMENT_PATHS` in `proxy.ts` names `/`, `/map`, `/tonight`, `/today` and `/near`, which take `script-src 'unsafe-inline'` in exchange for being prerendered and held by the CDN; the inline slot is the ONLY thing that differs, and every other route keeps a fresh nonce. A route that resolves a session in its document (`/u/you`, `/messages`, `/admin`) may never join the list. THREE rules ride with it. (1) A prerendered document may read NOTHING per request (`force-static` makes that a build error, and it is also what stops the root layout's `headers()` nonce read pulling the route back to dynamic), and it may carry NOTHING personal, because one copy is handed to every stranger. (2) THE LIST AND THE PAGE FILES ARE ONE LIST READ TWO WAYS: a listed path whose page is not `force-static` renders per request under 'unsafe-inline' and buys nothing, and a `force-static` page outside the list is prerendered with no nonce in its scripts and then answered with a policy that demands one, so `__tests__/cdnCachedDocuments.test.ts` holds both directions. (3) THE ISR WINDOW IS SIZED TO THE CLOCK THE PAGE READS: `/tonight` and `/today` compose off the London hour (the greeting slot, the quiet-pint window) and revalidate every 300 s, while `/`, `/map` and `/near` read only bundled data and take 3600 s; do not lengthen the short ones, because a "Good morning" at ten past noon is the cost. So a `/map` request whose document really differs is rewritten by the proxy to `app/map/arrival` and rendered per request with the nonce intact; `lib/mapDocumentTwin.ts` owns that key list, and adding a key takes those requests off the CDN while dropping one silently serves a share link the wrong card. The homepage's poster arrival moved into the proxy for the same reason. Pins: `__tests__/clerkProxyCsp.test.ts`, `__tests__/cdnCachedDocuments.test.ts`, `__tests__/mapDocumentTwin.test.ts`, `e2e/borough-crawls-security.spec.ts`.

- **A STATIC ASSET NEVER RUNS THE PROXY, AND A FAILING PACK IS NOT A FAILING BASEMAP.** Two halves of one finding (#1425 under the Wayfinder map #1423). (1) `proxy.ts` is a Node function that Vercel runs IN FRONT OF the CDN for every path its matcher claims, and the matcher claimed `/data`: two consecutive `x-vercel-cache: HIT` responses for one static file carried DIFFERENT nonces, and a cached copy cannot mint a nonce, so the 500 seen on an 82 KB uk_base pack was that function failing in front of a healthy file. `lib/staticAssetPrefixes.mjs` is the ONE list of public directories the matcher now excludes, and its rule is that a prefix must name a directory under `public/` NO app route shares. `/pal` is the standing counter-example, being both `public/pal/` and `app/pal/`, and excluding it would strip the per-request nonce off a rendered document. A PREFIX PROVES ITSELF BY BYTES OR BY A GENERATOR, and the witness is the COMMIT rather than the working tree: the `vendor` prefix names gitignored output that `prepare:maplibre-worker` writes, so a fence asking `existsSync` passed on every machine that had ever run the app and turned main red in the CI unit job, which checks out clean and runs `npx vitest run` with no build in front of it. Such a prefix is declared in `BUILD_WRITTEN_STATIC_ASSET_PREFIXES` and is held to a generator that writes the directory it names and is wired into `prebuild`; every other prefix is held to files present at HEAD, so a directory living only on one developer's machine can never join the list unannounced. Next only reads a matcher it can analyse STATICALLY, so `proxy.ts` writes the alternation out as a literal and the fence derives it. Anything the proxy used to do on those paths moved to a routing rule that costs no function: the legacy uk_base generation rewrite is `rewrites()` and the non-production `X-Robots-Tag` is `headers()`, both in `next.config.mjs`. (2) `map.on("error")` hears two things through one channel. `tube-lines` is the ONE scene source MapLibre fetches for itself, and its bytes are our own `/data` file, so a failure there says nothing about the tile source while the remedy it used to buy - the mount's ONE shared style reload - rebuilds every source and re-asks for the same file. `lib/mapDataPackFailure.ts` gives a pack its own bounded lane, asked BEFORE any tile stamp is taken: one retry of that pack, then empty it and carry on, never a style reload and never a stamp in the burst window, which stays exactly as it was for genuine tile failures. Pins: `__tests__/staticAssetPrefixes.test.ts`, `__tests__/ukBaseLegacyPath.test.ts`, `__tests__/mapDataPackFailure.test.ts`.

- **The host canonicalisation is for READERS, and `/api` is a caller.** `proxy.ts` 308s a `*.vercel.app` host to `pubmaxxing.com` so a generated alias never serves an indexable copy of the site (`shouldRedirectVercelHost`). Vercel's cron dispatcher issues its scheduled GET against the deployment's OWN generated host and does not follow that redirect, so every job in `vercel.json` once answered 308 and no handler ran, including the watchdog that would have said so. The whole `/api` tree is therefore exempt from the host redirect (`servesApiCaller`, the one predicate the CSP skip also reads), because the split-brain being prevented is a crawlable DOCUMENT mirror and a JSON answer is not one. What protects those routes is the CALLER'S CREDENTIAL, never the hostname: `assertCronRequest` (`lib/cronAuth.ts`) requires the bearer secret and denies in production when it is unset. The trailing-slash 308 is deliberately NOT exempt, because `skipTrailingSlashRedirect` means `/api/thing/` matches no route. Pin: `__tests__/vercelProductionHostRedirect.test.ts`, which reads the scheduled paths out of `vercel.json` so a new cron cannot fall outside the fence.

- **A ROUTE THAT SHIPS A DOCUMENT NOBODY KEEPS, AND THE HEADER THAT SAYS SO.** `/onboarding` is the native shell's one-time first-run surface and the web has no first-run surface at all: `FirstRunOnboardingGate` consumes a native-only, session-scoped handoff, so a web visit has always failed closed to "/". It did that in the BROWSER, after rendering and discarding a whole document, and on Slow 4G that was the worst LCP on the site at 4676 ms, the paint being the homepage hero arriving after the bounce (Astra's live walk, 7 Sep 2026, finding B6). `proxy.ts` turns a document request away with a 307 and ships none. THREE rules. (1) THE SIGNAL IS `Accept`, NOT NEXT'S OWN: this version of Next STRIPS both the `RSC` header and the `_rsc` query before middleware, measured on a production build, so neither can be read there. A browser document navigation sends `text/html,...` and every RSC navigation and prefetch sends `*/*`, which is why the shell's `router.replace` arrival from "/" (`components/native/AppEntryRoute.tsx`) is untouched. Accept also FAILS SAFE: an RSC fetch cannot start claiming to want HTML, so a future Next release cannot turn this rule on the shell's own arrival, where a header-name change could. (2) 307 AND NEVER 308: a browser caches a permanent redirect, the shell is a remote-URL wrap of this same origin, and one cached 308 would take the first run away from every later install on that device. (3) THE PATH IS A LEAF: `ONBOARDING_PATH` lives in `lib/firstRunRoute.ts`, which imports nothing, because a middleware bundle may not drag the city tables, the Capacitor probe and the storage seams in behind one string; `lib/entryDecision.ts` re-exports it. Pins: `__tests__/onboardingWebDocument.test.ts`, and `__tests__/clerkProxyCsp.test.ts`, whose nonced-family list names the route's absence rather than dropping it quietly.
